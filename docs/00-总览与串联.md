# good-life 总览与串联

## 一、项目一句话

一个由个人档案驱动的健康生活智能体。它把经期、医嘱、饮食、健身四类数据沉淀为可复用的数据工具层（SDK 加 MCP），再由智能体在聊天中调用，给出符合个人约束的饮食与生活建议。

定位声明：只提供生活方式建议，不做医疗诊断，不替代医生。

## 二、已确认的关键决策

| 项 | 决策 |
|---|---|
| 目的 | 求职作品集，重点是架构清晰、取舍可讲 |
| 形态与技术栈 | 手机浏览器 H5，React 前端，Python 后端 |
| 数据库 | 注册登录加 PostgreSQL，多用户隔离 |
| 用户定位 | 通用底座，由个人档案驱动，不分角色入口 |
| 经期预测 | 规则加个人统计，给出置信区间，不用机器学习 |
| 医嘱失效 | 带有效期和复查日，也从对话推断，必须用户确认后才解除 |
| 工具层形态 | Python SDK 为核心，再包一层 MCP |
| 拍照识别 | 大模型识别菜名，再查营养库计算热量，结果可由用户修正 |
| 外卖 | 不对接外卖平台，用高德地图兴趣点推荐附近健康餐厅 |
| 主动提醒 | 用户打开应用时，智能体主动开场提问 |
| 多模型 | 用户填地址和密钥后点击获取模型列表，后端统一适配 |
| 合规 | 免责声明，高风险内容引导就医，敏感数据加密 |

## 三、创新点（作品集主线）

1. 个人档案驱动的动态智能体：按档案动态注入上下文和工具。
2. 带时效的医嘱记忆：结构化存储，提议后由用户确认解除。
3. 经期数据服务化：入库后封装成 SDK 和 MCP，任何支持 MCP 的智能体都能调用。
4. 多约束融合的饮食建议：医嘱禁忌为硬约束，经期阶段、健身目标、当日摄入为软约束，大模型只负责表达。
5. 确定性触发加模型措辞：何时提问由规则决定，模型只负责说得自然。

## 四、推进方式：先验收，再往下

每一步都是独立文档，每份文档都有明确的验收标准。规则如下：

1. 严格按下表顺序推进，一次只做一步。
2. 一步完成后，由你按该文档的验收清单逐项检查。
3. 你明确说"通过"，该步骤才算完成，才能开始下一步。
4. 验收不通过，只修改当前步骤，不提前做后面的内容。
5. 每一步的范围之外的需求，一律记入该文档的"后续再议"，不在当步扩展。
6. 本文档的状态列由验收结果更新。

- 文档中不出现代码，只用自然语言描述行为、字段含义和规则。

## 八、开源调研结论摘要

没有找到成熟的一体化开源项目，做法是拼装成熟组件，自己写业务层。

| 环节 | 选用或参考 | 许可证注意 |
|---|---|---|
| 多模型统一接入 | LiteLLM 的 Python 库 | MIT，可嵌入 |
| 设置页交互参考 | LobeHub、Cherry Studio | 有限制或强传染，只借鉴思路，不拷代码 |
| 智能体编排 | LangGraph | MIT |
| 偏好类记忆 | mem0 | Apache-2.0，只存口味习惯等软信息 |
| 医嘱存储 | 自建结构化表 | 无 |
| 中文营养库 | 中国食物成分表整理数据 | 声明为仅供个人学习，商用前必须核实授权 |
| 包装食品营养库 | Open Food Facts | 需核实数据库许可 |
| 附近餐厅 | 高德地图接口，可参考高德 MCP | 需申请密钥 |
| 经期算法与模型参考 | Drip、ovumcy-web | 强传染许可，只参考思路，自己实现 |
| 健身表结构参考 | wger | 强传染许可，只参考表结构 |

调研中未能核实的事项，在对应步骤文档的风险一节中逐条列出，落地时逐一验证。
