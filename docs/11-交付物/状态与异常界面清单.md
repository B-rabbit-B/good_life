# 步骤 11 状态与异常界面清单

对应步骤文档：docs/11-前端H5.md 的“状态展示”与验收标准第 7、8 条。本文列出加载中、失败可重试、无数据、数据不足、需要授权五类状态各出现在哪些页面、标题是什么、正文来自哪里、下一步动作是什么；再列出界面处理的全部错误码与各自的表现；最后是“仅供参考”、就医提示与遮盖。

总的规则：每种状态都写清发生了什么、下一步做什么；标题是界面写死的固定标题（宋体），正文与错误码原样来自后端；界面不判断对错，只决定显示在哪里、给什么出路。

## 1. 五类状态总表

| 类别 | 出现在哪些页面 | 标题 | 正文来自哪里 | 下一步动作 |
|---|---|---|---|---|
| 加载中 | 启动画面、对话、拍照识别结果、饮食记录、训练、经期、医嘱三个标签、附近吃什么、我的、修改档案、建档、免责、模型服务、隐私与数据各块 | 没有标题：骨架块（浅青圆角条，带扫光，减弱动效时不扫光）加一行读屏会播报的文字 | 界面写死的进行中文字，例如“正在读取这天的记录”“正在读取对话”“正在读取经期记录”“正在取得定位”“正在查找附近的店” | 无，等待；数据到达后原地换成内容 |
| 失败可重试 | 上面每一处读取失败时；守卫检查失败时整页；页面分包没能加载时整页 | 默认“没能读取”；页面分包没能加载时同样是“没能读取”，正文是“页面没能加载，请检查网络后重试” | 后端统一错误体里的说明原文，下一行“错误码 某某”；后端没有给错误体时是界面的通用说明（见第 2 节 http_error、network_error） | 主按钮“重试”（只重新请求失败的那些）；分包加载失败时“重试”会重新载入页面；手上已有数据时后台刷新失败不打断页面 |
| 无数据 | 饮食记录的一天；医嘱的待核对、生效中、历史与审计；训练列表；模型服务；外部授权；调用记录；已保存的大致区域；附近的店为 0 家 | 饮食记录是“这天没有饮食记录”；其余是列表里的一句说明（例如“没有待核对的条目。录入医嘱后，提取出的条目会出现在这里。”“没有生效中的医嘱。”“近 30 天还没有训练记录。”“还没有模型服务。添加一个，填地址与密钥即可。”“还没有外部授权。”“还没有调用记录。”“没有保存大致区域。”） | 界面写死的流程文案；饮食记录写“某月某日 还没有记录。拍一张饭菜，或者手动记一餐。补记的记录会算进那一天。” | 饮食记录给“拍照记录”与“手动记一餐”；待核对给“录入医嘱”；模型服务给“添加模型服务”；附近的店写“2 公里内 0 家”，可换地点或需求再查 |
| 数据不足 | 经期的预测；饮食记录的能量账本（档案不全无法估算每日需要） | 经期是“还不能预测下次经期”；饮食是“还不能估算每日需要” | 后端返回的说明原文，逐条显示；经期另写“已记录 N 个完整周期” | 经期给“记录经期开始”（或“记录经期结束”）；饮食给“去补充档案” |
| 需要授权（定位） | 附近吃什么，只在后端说“应询问定位”时出现一次 | “用一次你的位置？” | 界面写死的说明：只用来查找附近的餐厅，精确位置不会保存；不允许也没关系，可以输入地名或地标，以后不再询问 | “允许定位”（记下授权、取定位、检索）或“输入地点”（记下拒绝，以后不再询问）；浏览器拒绝或 10 秒没取到定位时改为地点输入，并写“没能取得定位，输入地名或地标即可。” |
| 需要授权（没有模型） | 对话页消息流末尾；发消息时后端答没有配置对话模型 | “还没有可用的对话模型” | 界面写死的说明：对话和拍照识别都需要先添加一个模型服务，填地址与密钥，大约两分钟 | “去添加模型服务”，进入添加模型服务的四步 |
| 需要授权（登录过期） | 登录页，任何接口答登录失效之后，或另一个标签页退出登录之后 | “登录已过期” | 界面写死的说明：请重新登录，记录不会丢失 | 动作就在同一页：重新登录后回到原来的页面；令牌与缓存已经清掉 |

另有两种整页状态：

- 启动画面：守卫还在读取免责状态、档案与能力清单时显示，写“正在加载”。
- 守卫失败：读取这三项失败且手上没有数据时，整页显示“没能读取”、后端说明、错误码与“重试”。

## 2. 界面处理的错误码与表现

下表的“表现”都包含原样显示后端说明；“错误码 某某”的写法见第 1 节。只列界面按错误码做了特别处理的，以及验收需要说明的；没有列出的错误码一律按“失败可重试”或“写在表单上”显示。

### 2.1 登录、免责与通用

| 错误码 | 什么时候出现 | 界面表现 |
|---|---|---|
| username_taken | 注册时用户名已被占用 | 写在用户名输入框下面 |
| invalid_credentials | 登录时用户名或密码错误 | 写在表单上，令牌保持为空；不会被当成登录过期 |
| invalid_token | 令牌已失效或被吊销 | 清令牌与缓存，取消进行中的请求，回登录页并显示“登录已过期” |
| not_authenticated | 没有带令牌或会话已退出 | 同上；主动“退出登录”时即使令牌早已失效也不显示“登录已过期” |
| disclaimer_outdated | 确认免责时，页面上的版本已不是最新 | 免责页显示后端说明，重新读取正文，要求重新勾选 |
| disclaimer_not_accepted | 使用中免责声明换了版本（任何接口答 403） | 去免责页，确认后回到原来的页面 |
| validation_error | 后端的字段校验没通过 | 按后端给出的字段逐个写在对应输入框下面并把焦点移过去；字段不在这一页的写在表单上，前面加上字段的中文名 |
| network_error | 连不上服务、上传超时、流式回答中途断开 | 写“网络连接失败，请检查网络后重试”；读取类请求自动再试一次；已填的内容与对话里刚发的话都保留，可以直接重试 |
| http_error | 服务答了错误状态却没有统一错误体（例如网关返回的网页） | 写“服务暂时不可用，请稍后再试（HTTP 状态码）”，给“重试”；5xx 的读取请求自动再试一次 |

### 2.2 对话与模型

| 错误码 | 什么时候出现 | 界面表现 |
|---|---|---|
| agent_model_not_configured | 发消息时还没有为日常对话选模型 | 不当作错误行：消息流末尾换成“还没有可用的对话模型”与“去添加模型服务” |
| agent_model_error | 模型调用失败（后端已转成统一说明） | 在这一轮的位置显示一行警示：说明原文、错误码与“重试”；输入的文字保留，重试不用重新输入 |
| llm_invalid_key | 模型服务的密钥无效 | 添加模型服务第 1 步：密钥框朱色内描边，说明与错误码紧贴其下，按钮变为“重新保存并获取模型”；拍照识别：标题“这次没有识别完成”，给“重试识别”与“去设置” |
| llm_key_required_for_new_url | 改了服务地址却没有重填密钥 | 第 1 步密钥框下 |
| llm_invalid_url | 服务地址不合格 | 第 1 步地址框下 |
| llm_provider_exists | 已有同名的模型服务 | 第 1 步名称框下 |
| llm_bad_url | 地址连不上 | 第 2 步失败，给“修改地址”（回第 1 步地址框并把焦点放进去） |
| llm_listing_unsupported_or_bad_url | 服务不提供模型列表，或地址写错 | 第 2 步失败，给“修改地址”，并可手动添加模型编号 |
| llm_model_unavailable | 选的模型不存在或不可用 | 获取模型时写在第 2 步并给“重试”；测试时写在第 3 步并给“重新测试”；对话与识别中按所在页面的失败行显示 |
| llm_quota_exceeded | 服务额度用完 | 同上 |
| llm_rate_limited | 请求太频繁 | 同上 |
| llm_timeout | 服务在限定时间内没有回应 | 同上 |
| llm_bad_request | 服务拒绝了这次请求 | 同上 |
| llm_provider_error | 服务端出错 | 同上 |

模型服务页的“测试连通”失败时写“未连通”、说明原文与错误码。

| 错误码 | 什么时候出现 | 界面表现 |
|---|---|---|
| photo_not_food | 照片里没有识别到食物 | 识别失败页，标题“没有认出食物”；重拍、从相册换一张、手动记一餐 |
| photo_unclear | 照片太模糊或太暗 | 识别失败页，标题“照片看不清”；出路同上 |
| photo_recognition_failed | 看图模型出错或没按要求回答 | 识别失败页，标题“这次没有识别完成”；重试识别、去设置、重拍、从相册换一张、手动记一餐 |
| photo_empty | 没有收到图片内容 | 识别失败页，标题“这次没有识别完成”；重拍、从相册换一张、手动记一餐 |
| photo_too_large | 图片超过 8 MB | 同上（浏览器已先压缩，一般不会出现） |
| photo_type_not_allowed | HEIC、GIF 等不支持的格式 | 同上，说明原文写明怎么改成 JPEG |
| photo_too_many_pixels | 像素太多 | 同上 |
| photo_unreadable | 图片打不开 | 同上 |
| photo_items_need_confirmation | 确认入库时还有待确认的项 | 轻提示后端说明，重新读取结果，焦点移到第一个需要处理的项（按钮本来在有待确认项时就不可用） |
| photo_grams_out_of_range | 确认入库时有克数不在常见范围 | 同上，焦点移到克数需要核对的项 |
| photo_unknown_food | 选的候选在营养库里不存在 | 轻提示后端说明，候选单选恢复为未选 |
| photo_unknown_item | 修正里有不存在或重复的菜品编号 | 轻提示后端说明；修改面板里写在表单上 |
| photo_too_many_items | 一餐菜品超过上限 | 同上 |
| photo_empty_meal | 一餐已经没有菜品 | 确认入库时轻提示后端说明 |
| photo_not_editable | 记录已确认或已放弃，不能再改 | 轻提示后端说明；确认入库时另重新读取结果，页面按新状态只读显示 |
| photo_image_not_kept | 这次识别没有保留图片 | 缩略图位置写“图片 未保留”；保留了却取不到时写“读取失败” |

### 2.4 医嘱

| 错误码 | 什么时候出现 | 界面表现 |
|---|---|---|
| still_due | 继续遵守时新的日期仍然立即到期 | 写在继续遵守面板里触发复核的那一项日期下面，日期框描红并获得焦点；面板保持打开 |
| subjects_required | 确认生效或修改时没有涉及的食物或行为 | 确认生效面板里写在按钮上方，可以“返回修改”；修改面板里写在“涉及”下面 |
| invalid_item_dates | 日期前后不对（例如复查日期早于生效日期） | 写在对应的日期字段下面 |

### 2.5 附近餐厅（restaurant_ 全部错误码）

| 错误码 | 什么时候出现 | 界面表现 |
|---|---|---|
| restaurant_location_not_granted | 没有定位授权却按坐标检索 | 不当作错误：改为地点输入，并把后端说明写在地点表单下面，同时刷新授权状态 |
| restaurant_place_not_found | 地点找不到 | “没能读取”、说明原文（建议换个说法或加上城市）、错误码与“重试” |
| restaurant_no_location | 没有给地点，或已保存的区域已被清除 | 同上 |
| restaurant_unknown_need | 需求不在词表里 | 同上（界面只提供词表里的需求，一般不会出现） |
| restaurant_rate_limited | 检索太频繁 | 同上 |
| restaurant_not_configured | 服务端没有配置高德密钥 | 同上 |
| restaurant_service_busy | 高德额度用完或太频繁 | 同上 |
| restaurant_service_failed | 高德出错 | 同上 |

“重试”按上一次的方式重来：定位检索重新取定位，地点检索用表单里的地点，已保存区域检索用已保存的区域。

## 3. 拍照识别失败的画面

识别失败时照片占位写“你选的照片（已丢弃）”，看图模型失败与断网时写“你选的照片（还在本页，可以直接重试）”；下面是失败标题（按错误码：没有认出食物、照片看不清，其余“这次没有识别完成”）、后端说明原文、“错误码 某某。这次没有产生识别记录。”、出路按钮（见第 2.3 节），最后是“拍照小提示”（光线充足从斜上方拍、一张照片一餐、只支持 JPEG、PNG、WebP 且不超过 8 MB）。

## 4. 表单与面板里的错误

- 表单字段的错误写在字段下面，输入框带错误状态，提交失败后焦点移到第一个出错的字段。
- 面板（继续遵守、确认生效、确认解除、作废、修改、经期记录、放弃与删除识别、清除区域、吊销授权）里的错误写在按钮上方，带错误码；面板保持打开，按钮恢复可用，可以再试。保存期间面板不能关闭。
- 成功只用轻提示（“已记下”“已保存”“已继续遵守”“已撤销解除建议”“已确认生效”“已作废”“已清除”“已吊销”等），这些固定的说法不带医嘱、地点、授权名称等内容。轻提示本身不在遮盖范围内：拍照修正失败时轻提示里的后端说明可能带菜名；记训练的冲突说明在遮盖时改为不带内容的一句（见第 6.2 节）。

## 5. “仅供参考”

所有预测、建议与评价旁都有一枚灰色细边的“仅供参考”胶囊，出现在：

| 页面 | 位置 |
|---|---|
| 对话 | 每一条助手回答的气泡下，与免责句一起 |
| 识别结果 | 整餐评价的标题旁 |
| 饮食记录 | 能量账本的需求说明旁 |
| 训练 | 本周估算消耗旁 |
| 经期 | 当前阶段标题旁；预测区间旁 |
| 医嘱 | 解除建议区（医嘱页与对话页的待处理条） |
| 附近吃什么 | 结果顶部的提示旁；已避开类型的说明随结果一起显示 |

经期预测、整餐评价、营养汇总、餐厅推荐另有后端的免责原文，界面原样显示。

## 6. 就医提示与遮盖

### 6.1 就医提示

- 后端把一轮回答标为用药、孕期异常、严重症状、极端节食或自伤话题时，界面只画就医提示，不再接回答气泡、依据或别的内容。
- 就医提示是全站唯一不圆角、不透明、整块朱色的东西：在回答最上方，左右出血到屏幕边，不可折叠、不可关闭；标题按话题是“请尽快就医”“请联系专业帮助”“请咨询医生或药师”“请咨询医生或营养师”；正文是后端的固定回复原文；每个号码一个拨号按钮（都有 120，自伤与极端节食另有 12356）；底部注明“这是一条固定的安全提示，不是模型生成的。”
- 本次刚出现的就医提示会立即播报；历史里的旧提示不在每次打开页面时重复播报。
- 最后一条回答是就医提示时，对话底座的快捷操作整行隐藏。
- 输出检查附加的医嘱提醒是另一种东西：画成气泡外的“系统附注”便笺，朱色标题“医嘱提醒”，标明不是模型写的。

### 6.2 遮盖

- 入口：有底部导航的页面在导航最右一格；没有导航的敏感二级页在页头右上。
- 打开后，所有登记过的敏感区盖上不透明的斜纹（浅灰蓝底加细斜纹），同时对读屏隐藏、键盘无法进入，并播报“已遮盖”；导航那一格写“已遮盖”。不用模糊：模糊只是把字形抹软，大号数字和短词仍能从轮廓猜出来。
- 应用切到后台再回来时默认遮盖。
- 遮盖时的说法也不泄露内容：经期页的记录按钮统一写“记录经期”；解除医嘱的结果只读“已解除这条医嘱。审计已记录。”；记训练成功的冲突提示改为“已记下。有一条提示，取消遮盖后可在训练记录里查看。”
- 各页的敏感区见《页面清单与信息结构说明》的路由总表；密钥从不出现在页面上，只显示后端给的掩码。
