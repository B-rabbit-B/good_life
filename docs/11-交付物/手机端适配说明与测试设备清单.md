# 步骤 11 手机端适配说明与测试设备清单

对应步骤文档：docs/11-前端H5.md 的“手机适配”、风险“手机浏览器对拍照、定位的支持差异”与验收标准第 6 条。本文写前端在手机上的适配做法、浏览器的最低要求、首屏预算、自动化测试用的模拟设备，以及需要你在真机上逐条核对的清单。设计依据见 docs/superpowers/design/step11/DESIGN.md 第二、八、十、十一、十二节。

## 1. 适配说明

### 1.1 竖屏为主

- 页面按竖屏手机设计，在 360 与 390 两种宽度下逐页检查过版式（没有横向滚动、文字不溢出、触控目标与字号合格）。
- 页面宽度跟随设备，允许双指缩放；视口声明覆盖到刘海与圆角区域（由安全区留白兜住，见下一条）。
- 横屏只做到“尽力可用”：布局不会坏，但没有专门设计与测试，列入真机核对清单。

### 1.2 安全区

- 页头上沿加系统给的顶部安全区高度，内容不会被刘海与状态栏挡住。
- 浮起的底部导航、对话底座、操作坞的下边距取“底部安全区减 16 像素”与 18 像素中的较大者；底部面板下沿至少留出底部安全区（不小于 8 像素）。
- 安全区在模拟设备里量不出真实的刘海与圆角，需要真机确认。

### 1.3 软键盘

- 安卓：视口声明让键盘弹起时页面跟着缩小（键盘区域不覆盖内容），对话底座自然落在键盘上沿。
- iOS：键盘弹起时布局视口不变、可见视口变小。对话页监听可见视口，算出键盘高度后把对话底座贴到键盘上沿，导航那一行暂时隐藏；地址栏伸缩（小于 80 像素的变化）与双指放大不当作键盘。
- 底部面板里的输入框（继续遵守的日期、作废原因、经期备注等）在 iOS 上被键盘遮挡的情况没有自动化手段核对，列入真机核对清单。

### 1.4 触控目标与字号

- 所有触控目标宽高不小于 44 像素；36 像素高的小按钮、快捷操作胶囊、需求胶囊用透明的伪元素把点按区补到 44；返回键是 44 点按区里一颗 36 的瓷扣；月历在 360 宽时每格约 44.6 像素。
- 全站最小字号 12 像素，用相对单位，跟随浏览器的字号设置。
- 两种宽度下的主要页面由端到端测试逐个元素检查触控目标与字号（含模拟 iPhone 的 3 倍屏）。

### 1.5 玻璃预算与四种降级

磨砂玻璃只用于不随内容滚动的外壳（底部导航与对话底座、操作坞、吸顶后的页头、底部面板）；滚动内容里从不使用模糊。预算：

| 项目 | 上限 |
|---|---|
| 同屏同时模糊的层数 | 平时 2 层，硬上限 3 层；轻提示与面板互斥 |
| 模糊半径 | 外壳 16、面板 24，饱和度不超过 1.4 |
| 模糊总面积 | 不超过视口的 40%；面板高于视口 40% 时一律用实色 |
| 动画 | 模糊半径从不做动画；面板滑入时是实色，停稳后才打开模糊 |
| 嵌套 | 玻璃里不再放玻璃 |

样式默认写实色，只有浏览器支持模糊（同时写带前缀与不带前缀的两种写法）且根节点标为“玻璃开”时才升级为玻璃。下面四种情况任一成立就降级为实色：

1. 系统偏好“降低透明度”（浏览器能读到这项设置时；iOS Safari 目前不把系统的“降低透明度”交给网页，所以另有第 2 条）。
2. 应用内“隐私与数据”里的“减少透明”选了“开”（跟随系统、开、关三档，存在本机，永远优先于系统偏好与自动判定）。
3. 低端机判定：不在启动时测，等页面加载完再空闲 1.5 秒，只在用户第一次真实滚动时记录至少 60 帧的帧间隔，中位数达到 24 毫秒判为低端并记在本机；应用版本、浏览器主版本或判定规则变了就重测，判为低端的过 30 天也重测；设备内存不大于 2 GB 时先从实色起步，但仍按滚动结果复测。
4. 底部面板打开时，遮罩下面的外壳临时关掉模糊（遮罩已经把它们压暗，模糊没有意义，还占名额）。

不支持模糊的浏览器（部分国内浏览器与旧版内核）自然落到实色，外观完整。

### 1.6 强制颜色

系统开启高对比（强制颜色）时：所有材质退成系统底色加 1 像素系统文字色的真边框，去掉阴影与模糊；按钮、输入框、胶囊、导航键都有真边框；导航当前项用描边而不是填底；就医提示加 3 像素边框；结论形状、把握格、刻度、月历格、训练柱、开关、勾选框、遮盖斜纹等图形用系统色重画，形状不丢。

### 1.7 减弱动效

系统开启“减弱动效”时，界面的动画与过渡时长压到 1 毫秒：回答整段到达后一次显示、光标不闪；数字直接显示终值；骨架不扫光；识别进度圈静止，只靠文字。脚本驱动的计数与流式在开始前读取这项偏好并跟随变化。

### 1.8 最低引擎

| 内核 | 最低版本 | 说明 |
|---|---|---|
| iOS Safari | iOS Safari 16 | iOS 16 到 17 只认带前缀的模糊写法，所以两种写法同时写；焦点描边在 16.4 以前画成直角框，可以接受 |
| Chromium 内核 | Chromium 107 | 含安卓 Chrome 与系统 WebView；构建目标按这两个最低版本编译 |
| 微信内置浏览器与国内浏览器 | 内核版本各异 | 不支持模糊的会落到实色材质；只要求显示与相册正常，列为可选核对 |

用到但最低引擎可能缺少的特性都有回退：不支持“禁止键盘进入子树”时，遮盖改为把子树里的可聚焦元素临时移出键盘顺序；读不到“降低透明度”时按未开启处理。

### 1.9 首屏预算

对话页是首屏，预算按压缩后的大小计，由构建后的检查脚本逐项核对（数字为本次实测）：

| 项目 | 上限 | 实测 |
|---|---|---|
| 对话路由首屏脚本（gzip） | 150 KB | 145.1 KB |
| 样式（gzip） | 22 KB | 8.0 KB |
| 预加载字体（两个自托管子集） | 45 KiB（46,080 字节） | 42.2 KB（宋体子集 40,864 字节，数字子集 2,304 字节） |
| 首屏脚本块数 | 8 个 | 6 个 |
| 累计布局偏移 | 0.05 | 由端到端页面检查断言不超过 0.05 |

字体只用两个自托管子集，同源提供、预加载、先用系统字体再替换，运行时不访问任何外部字体服务。日历等较重的组件按路由拆包，不进对话页首屏。脚本余量约 5 KB，对话首屏以后新增的功能必须按需加载。

## 2. 测试设备清单

| 类别 | 设备与浏览器 | 方式 | 覆盖内容 |
|---|---|---|---|
| 自动化 | iPhone 13 模拟（WebKit），视口 390 × 664，3 倍屏 | Playwright 端到端验收流程 | 9 条验收标准的关键流程、状态、“仅供参考”、掩码、玻璃降级、遮盖、减弱动效、触控目标与字号；外网请求一律失败并被记录 |
| 自动化 | Pixel 7 模拟（Chromium），视口 412 × 839 | 同上 | 同上，另跑强制颜色 |
| 自动化 | 视口 390 与 360（Chromium，模拟触屏手机） | Playwright 页面级检查 | 逐页版式、触控目标、字号、敏感区登记、模糊预算、首屏布局稳定 |
| 自动化 | 视口 390（Chromium） | Playwright 视觉帧 | 关键画面截图（不进仓库） |
| 真机一 | 任一 iPhone，iOS 16 以上，Safari | 用户按下面的真机核对清单补测 | 拍照、相册、定位、软键盘、安全区、带前缀的模糊、系统“降低透明度”与应用内开关的说明 |
| 真机二 | 一台中端安卓机（例如骁龙 6 系列），Chrome 或系统浏览器 | 同上 | 拍照、相册、定位、低亮度下的细线与骨架、对话页滚动帧时间 |
| 可选 | 微信内置浏览器 | 同上 | 只看显示、相册，以及是否正确落到实色材质 |

模拟设备的局限：Windows 版 WebKit 计算了模糊却不画出来（只画半透明底），所以自动化截图里玻璃下的字比真机上清楚；相机、相册、定位权限弹窗、iOS 软键盘与安全区都模拟不出真实效果。以上都要靠真机确认。

## 3. 真机核对清单

准备：按仓库根目录 README 的“局域网 HTTPS 真机测试”一节在电脑上启动后端与前端，手机与电脑连同一个局域网，用手机浏览器打开电脑的局域网地址（首次打开要信任自签证书）。需要一个已建档、已配好对话与看图模型的账号；核对附近餐厅需要后端配置了高德密钥。

| 序号 | 核对项 | 怎么做 | 应看到什么 | iPhone 结果 | 安卓结果 |
|---|---|---|---|---|---|
| 1 | 拍照入口调起相机 | 在对话页点底座的“拍照”；再在拍照识别页点“拍照” | 直接打开后置相机（不是相册） |  |  |
| 2 | 相册入口调起相册 | 点“从相册选图”或“从相册选” | 打开相册或文件选择，能选一张饭菜照片 |  |  |
| 3 | 拍照后识别成功 | 拍一张真实的饭菜照片 | 依次看到压缩、上传百分比、认菜三步进度，随后进入识别结果页，菜品与热量合理；确认入库后跳到当天饮食记录 |  |  |
| 4 | 定位授权与拒绝后的地点输入 | 用一个新账号打开“附近吃什么”，先点“输入地点”；再用另一个新账号点“允许定位”，在系统弹窗里分别试“允许”与“不允许” | 选“输入地点”后出现地点表单，刷新后不再询问；允许后按当前位置列出附近的店；系统弹窗选“不允许”时改为地点输入并写“没能取得定位，输入地名或地标即可。” |  |  |
| 5 | 局域网 HTTPS 下定位可用 | 用局域网 HTTPS 地址打开附近吃什么并允许定位 | 浏览器弹出定位授权并能取到位置（用普通的 http 局域网地址时浏览器会直接拒绝定位） |  |  |
| 6 | 软键盘弹起时对话底座贴住键盘 | 在对话页点输入框 | 键盘弹起后对话底座紧贴键盘上沿，导航那一行隐藏；收起键盘后恢复 |  |  |
| 7 | 面板里的输入框与键盘 | 打开继续遵守、作废（填原因）、记录今天（填备注）面板，点里面的输入框 | 输入框不被键盘挡住，页面不被放大 |  |  |
| 8 | 遮盖与切后台自动遮盖 | 在经期、医嘱、我的页点“遮盖”；再取消遮盖、切到别的应用后回来 | 敏感区盖上不透明斜纹，导航那格写“已遮盖”；切回来时已经自动遮盖 |  |  |
| 9 | 系统“降低透明度”与应用内“减少透明”的说明 | iPhone：打开系统设置里的“降低透明度”，回到应用看说明；再在“隐私与数据”里把“减少透明”切到“开” | 系统设置不会自动关掉应用里的玻璃（iOS 网页读不到这项设置）；判断“减少透明”一行的说明（会关掉磨砂玻璃，界面改用实色，更省电）是否足以让人知道要在应用里手动打开；切到“开”后导航、底座、页头变成实色 |  |  |
| 10 | 带前缀的模糊与安全区 | 在 iOS 16 或 17 的 Safari 里滚动对话页与饮食记录 | 导航、底座与吸顶页头下的内容被柔化（不是只有半透明底）；页头不被刘海挡住，底部导航不压住手势条 |  |  |
| 11 | 低亮度下细线与骨架可见 | 把屏幕亮度调到最低，看饮食记录的细分隔线、营养进度条，以及读取中的骨架块 | 细线与骨架仍能看出来 |  |  |
| 12 | 对话页快速滚动的帧时间 | 安卓机连上电脑，用 Chrome 的远程调试打开性能面板，在对话页流式回答进行中快速上下滚动 5 秒 | 对话页快速滚动 5 秒时 90% 的帧不超过 16.7 毫秒；超出时记录机型，考虑加入降级名单 |  |  |
| 13 | 导航跳转唤起高德 | 在附近吃什么的结果里点某家店右侧的导航 | 装了高德地图的手机唤起高德并以这家店为终点；没装的打开高德网页版导航 |  |  |
| 14 | 横屏 | 把手机转成横屏，翻看对话、饮食记录与一个底部面板 | 布局不坏、能操作（横屏只做到尽力可用） |  |  |
| 15 | 微信内置浏览器（可选） | 在微信里打开局域网地址 | 显示正常、相册可用，不支持模糊时外壳是实色 |  |  |
