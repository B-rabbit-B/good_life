# 步骤 11 页面清单与信息结构说明

对应步骤文档：docs/11-前端H5.md 的“页面清单”。页面路径以前端代码的路径表（frontend/src/app/paths.ts）为准；本文逐个路由写明页面名称、从哪里进入、从上到下的信息结构、读写的接口、是否有敏感区、能力清单条件。视觉、令牌与组件以 docs/superpowers/design/step11/DESIGN.md 与同目录的可视稿为准，本文只写结构。

阅读约定：

- “接口”列写这一页直接读写的后端接口（方法加路径，路径里的花括号是编号）；守卫与外壳另外读取的免责状态、档案与能力清单不在每页重复。
- “敏感区”指打开一键遮盖后会盖上斜纹的区域，名称与前端的“本页有敏感区”登记表一致；“无”表示这一页不在遮盖范围内。
- “能力清单”指后端 GET /api/me/capabilities 返回的四个模块开关：经期 cycle、医嘱 medical、饮食 nutrition、健身 fitness。页面与入口是否开放只看它，前端不自己判断性别或其他条件。
- 界面不做业务规则判断：结论、依据、提示、说明与错误码一律原样显示后端返回的内容；前端只写死枚举到中文的标签、流程文案与少量后端固定文案的副本（副本由后端测试逐字核对）。

## 1. 导航与守卫

### 1.1 底部导航

底部导航是一块浮在内容上方的磨砂玻璃，最多四项文字加最右一格“遮盖”：

| 项 | 去往 | 什么时候出现 |
|---|---|---|
| 对话 | /chat | 总是出现 |
| 记录 | /records | 饮食或健身至少一个开放时 |
| 健康 | /health（再转到第一个开放的分段） | 经期或医嘱至少一个开放时 |
| 我的 | /me | 总是出现 |
| 遮盖（最右一格） | 不跳转，切换一键遮盖 | 有底部导航的页面总是出现；打开后文字改为“已遮盖”，读屏名称改为“已遮盖，点按恢复显示” |

- 四项变体：女性用户（经期与医嘱都开放）以及男性用户（只开放医嘱）都看到“对话、记录、健康、我的”四项；男性用户的健康页只有医嘱，不显示“经期 / 医嘱”分段。
- 三项变体：经期与医嘱都不开放时“健康”隐藏，导航变为“对话、记录、我的”三项；饮食与健身都不开放时“记录”同理隐藏。
- 对话页没有单独的导航条：导航嵌在对话底座这块玻璃的下沿，和快捷操作、输入框共用一块。
- 记录、健康（经期、医嘱）、我的这几页显示底部导航；其余二级页没有导航，页头左上是返回键，属于敏感页面的二级页在页头右上放遮盖按钮。

### 1.2 守卫顺序

打开任何一页时按下面的顺序检查，前一项不满足就去对应的页面，判断全部来自后端：

1. 没有登录令牌：去登录页 /login（登录成功后回到原来要去的页面）。已登录的人打开登录页会被送回首页。
2. 没有确认当前版本的免责声明：去免责页 /disclaimer（确认后回到原来的页面）。使用中免责声明换了版本（任何接口返回 403 disclaimer_not_accepted）时同样去免责页。
3. 档案六项（出生年份、性别、身高、体重、活动水平、目标）没有填完：去第一个没填完的建档步骤 /onboarding/1 或 /onboarding/2；第 3 步可以跳过，不算未填完。
4. 页面需要的模块全都没有开放：回对话页 /chat。

守卫还在请求中时显示启动画面；请求失败且手上没有数据时，整页显示后端的说明、错误码与“重试”；收到 401 且错误码为 not_authenticated 或 invalid_token 时清掉令牌与缓存，回登录页并显示“登录已过期”。手上已有数据时，后台刷新失败不打断页面。

未知路径一律回到 /，/ 再转到 /chat。

## 3. 各页的信息结构

### 3.1 登录与注册（/login）

从上到下：产品名与一句定位；大标题“登录”或“注册”；一句说明（记录只保存在你的账号下）；登录过期时多一块“登录已过期”的说明（请重新登录，记录不会丢失）；表单面板：登录与注册的分段切换、用户名（注册时提示 3 到 32 位，字母、数字或下划线）、密码（可显示或隐藏）、提交按钮。

- 接口：POST /api/auth/register、POST /api/auth/login。
- 注册成功立即登录并去免责页；登录成功回到原来要去的页面。
- 用户名已被占用写在用户名下面；用户名或密码错误写在表单上；字段格式问题按后端给出的字段逐个写在对应的输入框下面。

### 3.2 免责声明确认（/disclaimer）

页头写“免责声明”与版本号，没有返回键；正文按后端返回的原文逐条显示；勾选“我已阅读并理解以上内容”后“确认并继续”才可用；底部写明之后可以在“我的”里随时查看。

- 接口：GET /api/disclaimer、POST /api/disclaimer/accept（提交的是页面上显示的版本号）。
- 后端说版本已更新时，显示后端的说明、重新读取正文并要求重新勾选。

### 3.3 建档（/onboarding/:step，三步）

页头写当前一步的标题与“建档进度，第几步，共 3 步”；每一步的表单写在一块白瓷面板里，主按钮在底部浮起的操作坞里。

1. 第 1 步“基本信息”（/onboarding/1）：一句用途说明；出生年份（下拉）；性别（女、男、其他三段，说明它也决定是否显示经期记录）；身高与体重两把刻度尺（可左右拖动，也可点数字直接输入）；“下一步”。
2. 第 2 步“活动与目标”（/onboarding/2）：活动水平五档单选，每档一行写名称与一句说明；目标四选一（减脂、增肌、维持、不设）；“下一步”。
3. 第 3 步“饮食偏好与忌口”（/onboarding/3，可跳过）：饮食偏好与忌口两组可移除的标签；健康状况多行输入，下方注明医生的要求请到医嘱页录入；“完成”与文字按钮“跳过这一步”。

- 接口：GET /api/profile、PATCH /api/profile（每一步只提交本步的字段）。
- 打开的那一步前面还有没填完的，回到第一个没填完的一步；完成或跳过第 3 步后进入对话页。

### 3.4 对话（/chat）

从上到下：

1. 吸顶页头：“对话”、今天的日期与星期；有需要本人处理的医嘱时，页头玻璃里嵌一条白瓷的“待处理条”（收起时只写类别与状态，或“医嘱待处理 N 条”，不写医嘱原文；展开后逐条给动作）。
2. 消息流（整段是一个直角的敏感区）：历史消息，日期变了插一条日期分隔；打开应用时的开场卡片接在已有消息之后；本次发出的消息与正在流入的回答；还没有对话模型时，末尾是“还没有可用的对话模型”的说明与“去添加模型服务”。
3. 每条助手回答：白瓷气泡里的回答原文、依据折叠（默认收起，标题旁写条数）、“仅供参考”与免责句；输出检查附加的医嘱提醒画成气泡外的“系统附注”便笺；固定的安全回答注明不是模型生成的；有医嘱解除线索时只给一个“去医嘱页处理”的跳转；本轮调用了记录类工具时给“去看看”跳转卡片。
4. 风险话题的回答只画就医提示：整块朱色、不圆角、左右出血到屏幕边、带拨打 120（自伤与极端节食另有 12356），并注明这是固定的安全提示。
5. 对话底座（浮起的玻璃，渲染在页面之外的外壳层）：快捷操作胶囊（附近吃什么、记一餐只在饮食开放时出现，看医嘱只在医嘱开放时出现；最后一条回答是就医提示时整行隐藏）；拍照、从相册选图、多行输入框（回车发送、上档加回车换行、输入法组字时不发送）与发送键；下沿嵌着底部导航。

- 接口：GET /api/agent/conversations、GET /api/agent/conversations/{id}、POST /api/agent/conversations、POST /api/agent/conversations/{id}/messages（流式读取）、GET /api/agent/opening、POST /api/agent/opening/{id}/answer、POST /api/agent/opening/{id}/decline、GET /api/medical/reviews（医嘱开放时）、GET /api/llm/assignments；开场卡片与待处理条里的“继续遵守”调用 POST /api/medical/items/{id}/continue，“不解除”调用 POST /api/medical/items/{id}/cancel-proposal。
- 选了照片就交给拍照识别页，在那里直接开始识别。
- 对话里没有任何“确认生效”或“确认解除”的按钮或链接；医嘱的确认与解除只能在医嘱页的底部面板里完成。

### 3.5 拍照识别（/photos/new）

页头“拍照识别”带返回。

- 选图状态：“拍照”（调起后置相机）、“从相册选”、勾选“保留照片（加密保存，可随时删除）”；“未处理的草稿”（每条写识别时间、菜品数与待确认数）；“最近的识别”（已确认入库或已放弃，注明是否保留了照片）；“拍照小提示”。这一页只写时间与数量，不写菜名，所以不在遮盖范围内。
- 识别中：照片占位（写明是否保留）、三步进度（上传并显示百分比、认菜和份量、按营养库计算）、“可以离开这一页”的说明、操作坞里的“取消识别”。
- 识别失败：见《状态与异常界面清单》第 3 节。

接口：GET /api/photos/recognitions、POST /api/photos/recognitions（上传照片与是否保留，带上传进度）。

### 3.6 识别结果（/photos/:recId）

页头“识别结果”带返回。从上到下：缩略图（保留了照片才去取，否则写“图片 未保留”）与状态、识别时间、看图模型；有建议核对的项时一条赭色提示“有 N 项建议核对”；识别项面板（敏感区）：每项写菜名与这一项的评价结论形状、热量（待确认的写“待确认”）、份量说法与克数（估算的写“（估算）”）、把握程度五格加高中低、营养库里对应的食物，需要核对的项左侧赭色竖线并逐条写原因；待确认的项内嵌候选单选、“改个名字”、“删除这一项”；面板底部合计四格（千卡、蛋白质、脂肪、钠）与免责句；整餐评价面板（敏感区，只有草稿有）：结论大字、每道菜的每条依据、取舍说明、未核对提示、“仅供参考”与免责句；“吃的时间”（日期与餐次）；“放弃这次识别”；“删除这条识别”；操作坞里“确认入库”（还有待确认项时不可用，并写“还有 N 项待确认”）。

- 已确认入库或已放弃的记录只读显示状态；已确认的给“查看这天的饮食记录”。
- 接口：GET /api/photos/recognitions/{id}、GET /api/photos/recognitions/{id}/image、PUT /api/photos/recognitions/{id}/items、POST /api/photos/recognitions/{id}/confirm、POST /api/photos/recognitions/{id}/discard、DELETE /api/photos/recognitions/{id}。

### 3.7 记录（/records）

大标题页头“记录”，右上是刷新；饮食与健身都开放时页头里有“饮食 / 训练”分段，只有一个时不显示分段。地址里的 tab 决定分段，date 决定饮食的哪一天（默认今天）。

饮食（默认分段）从上到下：日期条（前一天、日期、后一天，今天之后不可选）；能量账本（敏感区：大数是当天摄入与需要，右边还可摄入，每格 25 千卡的刻度按餐次着色，图例四格，“仅供参考”与需求说明原文；档案不全无法估算时换成“还不能估算每日需要”）；营养表（敏感区：五种营养素的已摄入、需要、还差与进度条，钠写上限，有食物缺数据时写明哪几项可能偏低，最后是汇总的免责句）；三餐（敏感区：按餐次分组，每项食物名、克数与千卡，来自拍照识别的一餐带胶囊；没记的餐每餐一行，给拍照与“手动记一餐”）；最后是背景场上的“附近吃什么”。当天完全没有记录时整块换成“这天没有饮食记录”。

训练分段从上到下：运动限制条（敏感区：今天生效的“运动限制”类医嘱，医嘱不开放时不请求）；本周训练（次数、总时长、估算消耗与“仅供参考”，缺体重时写后端说明原文，七根柱）；“搜索动作”胶囊；动作趋势（最近一个力量动作的最大重量阶梯线）；近 30 天的训练列表（与运动限制冲突的说明原文写在行内）。页头右上多一个“记一次训练”。

- 接口：GET /api/nutrition/summary、GET /api/nutrition/meals；GET /api/fitness/summary/week、GET /api/fitness/workouts、GET /api/fitness/exercises/{id}/trend、GET /api/medical/constraints（医嘱开放时）。

### 3.8 手动记一餐（/records/meals/new）

页头带返回。食物搜索框（输入停下后再搜，后端的提示原文照写，例如名称相近的说明）；结果是账目行；选中一项后按克数，或按这种食物的常用份量（单位加份数）填写；日期（默认地址里的日期或今天）与餐次（默认地址里的餐次或按时间推断）；操作坞“保存”。保存成功回到那一天的饮食记录并轻提示“已记下”。

- 接口：GET /api/nutrition/foods/search、GET /api/nutrition/foods/{id}、POST /api/nutrition/meals。

### 3.9 记一次训练（/records/workouts/new）

页头带返回。顶部运动限制（敏感区）；胶囊搜索框（后端提示原文照写），结果是账目行（动作名、部位、器械）；点一个结果加一个动作：力量动作逐组填重量与次数（可加组、删组），有氧填时长与距离；训练日期（默认今天，不晚于今天）与整次时长；操作坞“保存”。成功后回训练分段并轻提示“已记下”，后端返回的冲突说明原文写在轻提示里（遮盖时不写内容）。

- 接口：GET /api/fitness/exercises/search、POST /api/fitness/workouts、GET /api/medical/constraints（医嘱开放时）。

### 3.10 健康（/health、/health/cycle、/health/medical）

/health 本身不显示内容：经期开放时转到 /health/cycle，否则医嘱开放时转到 /health/medical，都不开放时回对话页。刚关掉“经期记录”或档案正在保存时先等能力清单刷新完再转。

健康页是大标题页头（右上刷新经期与医嘱的全部数据）。经期与医嘱都开放时页头里是“经期 / 医嘱”分段，医嘱段带待处理条数的徽标；只开放医嘱时不显示分段，页头里直接是医嘱的三个子标签；只开放经期时直接是经期内容。

经期（/health/cycle，除两个记录按钮外全部在敏感区里）从上到下：

1. 当前阶段大标题（经期、卵泡期、排卵期、黄体期，或“暂时无法判断阶段”）加“仅供参考”，写本周期第几天与后端的第一条提示。
2. 周期刻度与预测面板：一行压缩整个周期，预测区间与置信范围、免责原文；数据不足或已暂停预测时换成“还不能预测下次经期”，正文逐条是后端的说明，并写已记录几个完整周期。
3. 月历：周一开头；已记录的日子是海军蓝实块，预计的日子是虚线框，预计开始范围在格子下方画虚线，有当天记录的右上一个小点，今天钴蓝内描边；点今天或更早的一天打开那一天的记录面板，今天以后的日子不可选。
4. 两个记录按钮（在敏感区外）：“记录经期开始”（最近一次经期还没结束时是“记录经期结束”；遮盖时一律写中性的“记录经期”）与“记录今天”。

全页只用海军蓝、灰与钴蓝，不用粉色，文案中性。

- 接口：GET /api/cycle/periods、GET /api/cycle/day-logs、GET /api/cycle/prediction、GET /api/cycle/phase、GET /api/cycle/tips、GET /api/cycle/stats、POST /api/cycle/periods、PATCH /api/cycle/periods/{id}、PUT /api/cycle/day-logs/{date}。

医嘱（/health/medical，全部内容在敏感区里）有三个文字子标签，与地址里的 tab 同步，默认“生效中”：

1. 待核对（tab=pending，标签写条数，有待核对时赭色）：说明“提取出来的条目要逐条核对，确认前不参与任何建议”；按医嘱分组，每组先写来源（证据缩略或“原文”、录入日期、提取出几条、“查看”打开原文与证据、“未提取的句子”折叠），再逐条写类别与“待核对”、有预计结束日期时赭色写“某日之后仍未确认，会自动作废”、原文、字段表（提取内容、涉及、生效日期、预计结束、复查日期、提取把握，缺的字段写清确认后的后果）、提取说明，以及“作废”“修改”“确认生效”；每组末尾“手动补充一条”。
2. 生效中（tab=active）：生效中与待复核的条目写在一块面板里，待复核的排在最前，其次带解除建议的；每条写类别、状态（待复核写赭色“待复核”与到期原因，否则“生效中”）、内容、日期行；待复核的写“这条医嘱正在待复核，确认解除之前仍按原要求执行。”；带解除建议的有一块解除建议区（谁提出、理由原文、“仅供参考”）。
3. 历史与审计（tab=history）：已解除与已作废的条目（颜色退一级，写“已解除 某日”或“已作废 某日”与最后一个关闭事件的来源与原因），以及跨条目的审计记录（时间、动作、条目、状态变化、来源）。

医嘱页下方背景场上有“录入医嘱”。各状态的动作见《关键流程交互说明》第 3 节。

- 接口：GET /api/medical/orders、GET /api/medical/items、GET /api/medical/reviews、GET /api/medical/events、GET /api/medical/items/{id}/events、GET /api/medical/evidence/{id}、POST /api/medical/orders/{id}/items、PATCH /api/medical/items/{id}、POST /api/medical/items/{id}/confirm、POST /api/medical/items/{id}/void、POST /api/medical/items/{id}/continue、POST /api/medical/items/{id}/cancel-proposal、POST /api/medical/items/{id}/resolve。

### 3.11 录入医嘱（/health/medical/new）

页头“录入医嘱”带返回（回医嘱页），全部内容在敏感区里。一句说明（照原文粘贴或拍照，不用改写，提取出的条目需要逐条核对后才生效）；医嘱原文（1 至 5000 字，带字数）；开具日期（默认今天，不晚于今天）；证据（可选，拍照或从相册选，每个文件显示大小与“加密保存”，可移除；超过 10 MB 或类型不支持时先提示）；操作坞“提取条目”。先建医嘱，再逐个上传证据，全部完成后去待核对标签。

- 接口：POST /api/medical/orders、POST /api/medical/orders/{id}/evidence。
- 任何一步失败都原样显示后端的说明与错误码；医嘱已经建好时不会重复提交，重试只上传还没传完的证据，也可以“先去核对，不传剩下的证据”。

### 3.12 附近吃什么（/restaurants）

页头“附近吃什么”带返回。

1. 后端说“应询问定位”时先只显示一次询问：“用一次你的位置？”，写明只用来查找附近的餐厅、精确位置不会保存、不允许也可以输入地名或地标且以后不再询问；“允许定位”与“输入地点”两个整宽按钮。
2. 已授权时进页面自动取一次定位检索，上方写“按你现在的位置查找附近的店”与“改为输入地点”；已拒绝或取不到定位时是地点表单（敏感区：地名或地标、城市可不填，有已保存的大致区域时多一个“用已保存的区域”），并写一句说明。
3. 需求胶囊（多选，最多 3 个，先显示前四个，“全部 N 项”展开其余）。
4. “记住大致区域，下次不用再输入。可在设置里清除。”勾选行（敏感区）。
5. “查找附近的店”。
6. 结果：提示原文加“仅供参考”；“附近的店”标题与“2 公里内 N 家，按适合程度与距离”；店铺面板（每家店名、结论、类型、距离、可点、适量、应避开，判断不出类型的只写提示原文；右侧导航瓷扣在新窗口打开后端给的高德导航链接）；“已避开的类型”（类型名、被避开的店名、每条原因写来源、代表菜与说明原文）；免责原文。

- 接口：GET /api/restaurants/settings、PUT /api/restaurants/settings/consent、GET /api/restaurants/needs、POST /api/restaurants/search。
- 坐标只用于这一次请求：不放进页面状态、浏览器存储、查询缓存或地址栏。

### 3.13 我的（/me）

大标题页头“我的”。用户名与注册日期；档案摘要（敏感区：出生年份、性别、活动水平、身高、体重、目标三列事实格，忌口与健康状况）；“修改档案”；两个开关（敏感区）：“打开应用时主动提问”（每天最多问一个问题）与“经期记录”（只给女性用户，关闭后隐藏经期入口、已有记录保留）；设置链接三行：模型服务（写“未设置”或“N 个，对话已设置”）、隐私与数据（含“减少透明”）、免责声明（写已确认的版本）；“退出登录”。

- 接口：GET /api/auth/me、GET /api/profile、PATCH /api/profile（经期记录开关）、GET /api/agent/settings、PUT /api/agent/settings（主动提问开关）、GET /api/llm/providers、GET /api/llm/assignments、GET /api/disclaimer/status、POST /api/auth/logout。
- 切换经期记录后由后端的能力清单决定导航与健康页的分段。

### 3.14 修改档案（/me/profile）

页头带返回，右上遮盖按钮，全部档案内容在敏感区里：身高、体重、活动水平、目标、饮食偏好与忌口、健康状况；操作坞“保存”，只提交改过的字段，成功回到“我的”并轻提示“已保存”。

- 接口：GET /api/profile、PATCH /api/profile。

### 3.15 模型服务（/settings/models）

页头“模型服务”带返回。服务列表（每个服务一块：名称、完整地址、后端给的密钥掩码、“测试连通”及结果“已连通”或“未连通”加后端说明）；没有服务时写“还没有模型服务。添加一个，填地址与密钥即可。”；“当前用途”（日常对话与看图识别各用哪个模型，未设置的写“未设置”）；“添加模型服务”；“其他设置”三行链接：隐私与数据、已保存的大致区域（区域名在敏感区里，或写“未保存”）、免责声明。

- 接口：GET /api/llm/providers、GET /api/llm/assignments、POST /api/llm/providers/{id}/test、GET /api/restaurants/settings（饮食开放时）。

### 3.16 添加模型服务（/settings/models/new）

页头“添加模型服务”带返回（回模型服务页）。四步写在一块面板里，每一步左侧是步骤号与状态标记（未开始、进行中、已完成、失败）：

1. 填写地址与密钥：类型（预设或自定义）、名称、服务地址、密钥（可显示）；“保存并获取模型”（出错后是“重新保存并获取模型”）；保存后只显示地址与后端给的密钥掩码，并写“保存后只显示掩码，原文无法再查看。”
2. 获取模型：写获取到几个、其中几个能看图、几个能调用工具；列不出模型或一个也没取到时可以手动添加模型编号。
3. 测试连通：选一个模型发一次最小对话，写后端的说明原文与用时。
4. 选择用途模型：日常对话与看图识别各选一个（或“暂不选择”），每个用途下只给它需要的那一项手动标注（对话要能调用工具，看图识别要能看图）；“保存用途”。保存后回到模型服务页并轻提示“已保存”。

- 接口：GET /api/llm/presets、POST /api/llm/providers、PATCH /api/llm/providers/{id}、POST /api/llm/providers/{id}/fetch-models、GET /api/llm/providers/{id}/models、POST /api/llm/providers/{id}/models、POST /api/llm/providers/{id}/test、PATCH /api/llm/models/{id}、PUT /api/llm/assignments/{purpose}。
- 密钥只在这一页的输入框里：不进地址栏、浏览器存储、查询缓存与日志；保存（无论成败）后立即从请求缓存里清掉，保存成功时清空输入框。

### 3.17 隐私与数据（/settings/privacy）

页头“隐私与数据”带返回，右上遮盖按钮。遮盖说明（打开后医嘱、经期、档案等内容用斜纹盖住；应用切到后台再回来时自动遮盖）；“减少透明”（跟随系统、开、关，存在本机）；已保存的大致区域（敏感区，区域名与保存日期，“清除”经确认面板后删除；饮食不开放时整段不显示）；外部授权（敏感区，每个授权的名称、权限、状态、到期与最近使用，有效的可以吊销）；调用记录（敏感区，按客户端名筛选，每行时间、客户端、能力名、结果、错误码与耗时）。

- 接口：GET /api/restaurants/settings、DELETE /api/restaurants/settings/area、GET /api/agent-grants、DELETE /api/agent-grants/{id}、GET /api/agent-grants/audit。
- 数据导出与删除入口本步骤没有做，归步骤 12 的合规处理（见《验收记录》的已知限制）。

### 3.18 免责声明（/settings/disclaimer，只读）

页头“免责声明”带返回，右侧写版本号；正文按行显示；下面写这个版本的确认时间。

- 接口：GET /api/disclaimer、GET /api/disclaimer/status。
