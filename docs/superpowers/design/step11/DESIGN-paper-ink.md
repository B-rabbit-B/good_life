对应步骤文档：docs/11-前端H5.md；页面与流程沿用 docs/superpowers/specs/2026-10-12-step11-frontend-design.md，只重开其中“组件库与视觉”两项。可视稿见同目录 index.html（浏览器直接打开，除网络字体外无外部依赖），截图在 shots/（文件名前缀 390 与 360 表示视口宽度，带 full 的是展开全长，带 covered 的是遮盖状态）。评审截图在 review-shots/，未改动。

## 一、设计想法

这款应用每天替用户做的事是“量”：今天吃了多少、还差多少，钠离医嘱上限还有多远，周期走到第几天，医嘱管到哪一天。所以界面是一把安静的尺。刻度只出现在真正度量的地方：能量账本、身高体重刻度尺、周期刻度，以及底部导航上标出“当前位置”的那一根靛色刻度；登录页、导航底纹、空状态和骨架里的装饰刻度都已去掉。其余部分保持克制：纸白底、墨色字、细线分隔、左对齐的账目行，宋体只做固定的页题与小节题，只留一种靛蓝作强调。结论与风险用松、赭、朱三种语义色，每种结论配不同形状。程序附上的医嘱提醒是带齿边的“附页”，与模型的话在形式上分开；就医提示是全站唯一的整块朱色。

### 原则

| 原则 | 落到界面上 |
|---|---|
| 数字是主角 | 16 号以上的展示数字用 Source Serif 4 表格数字，16 号以下用系统黑体表格数字；数字列右对齐 |
| 刻度只用于度量 | 能量账本、身高体重尺、周期刻度、导航当前位置；其他地方不画刻度 |
| 数字永不被截断 | 任何含数值的文字不得用省略号截断；放不下时换行，或改为只显示类别与状态 |
| 一种强调色 | 靛蓝只用于主按钮、当前位置（导航、今天、需要线）、流式光标和链接 |
| 风险靠形状与位置 | 适合实心方块，注意半填方块，不建议叉形方块，未核对虚线方块；就医提示永远在回答最上方 |
| 系统写的与模型写的分开 | 医嘱提醒是白底齿边附页并标“系统附注”；固定安全回复注明“不是模型生成的” |
| 关键动作写明后果 | 医嘱确认生效、继续遵守、确认解除都在底部面板里列出“确认后会发生”；不可撤销的解除另需勾选 |
| 一次只占一个开场位置 | 有医嘱到期时，开场问题就是复核本身；其他开场等它处理后再出现 |
| 状态即指引 | 每种异常写清发生了什么、下一步做什么；说明原文与错误码来自后端 |

### 刻意避开的

渐变、毛玻璃、发光、大圆角卡片堆叠、圆底图标宫格、表情符号、居中大标题、全大写小标签、渐变文字、默认 Inter 观感、鼠尾草绿配奶油色、第一稿的青绿主色加胶囊标签与标准图标底栏，以及第二稿里不度量任何东西的装饰刻度。

## 四、关键行为规则

### 一次只有一个开场

1. 打开应用时取开场问题。今天有医嘱到期，后端的优先级规则让开场问题就是复核本身（“你有一条医嘱（……）到了复查日，要不要现在看看？”），对话页只显示这一张开场卡片，不再另挂提醒条。
2. 卡片动作：继续遵守（打开继续遵守面板）、去医嘱页处理（跳转）、稍后（开场标为已拒绝，卡片收成顶部一行待复核条）。
3. 前端另外独立查询待复核项。主动开场被关闭、或今天已问过这一类时，仍显示收起的待复核条，直到条目被处理。
4. 复核处理完，下一次取开场才可能出现“今天还没有记录饮食”等其他问题。

### 待处理条（数据来自待复核列表）

后端的待复核列表同时返回两类条目：已到期的“待复核”条目，和仍在生效、但带着解除建议的条目。两类分开表述：

| 条目 | 标签 | 状态措辞 | 动作 |
|---|---|---|---|
| 待复核 | 赭色 | “待复核”，展开后写后端给的到期原因（已到复查日期 / 即将到预计结束日期 / 今天是预计结束日期 / 已过预计结束日期） | 继续遵守（打开继续遵守面板）、去医嘱页处理 |
| 生效中且有解除建议 | 靛色 | “有解除建议”，不写“待复核”；注明由谁提出、仍在生效，并标“仅供参考” | 不解除（撤销建议）、去医嘱页处理；不出现“继续遵守” |

收起态：只有一条时写它的类别与状态（“饮食要求　待复核”或“运动限制　有解除建议”）；多条时写“医嘱待处理 N 条”。不放医嘱原文。规则：含数值的文字永不使用省略号截断。

开场卡片只会因“到期”触发（主动开场规则表第 1 类），所以带解除建议的条目不会成为开场卡片，只出现在待处理条里。正在作为开场卡片显示的那一条，不再在待处理条里重复。

### 医嘱各动作到底改了什么

| 动作 | 在哪里 | 后端动作 | 状态变化 | 审计 |
|---|---|---|---|---|
| 确认生效 | 医嘱页“待核对”，底部面板二次确认 | confirm（可带修改） | 待核对 到 生效中；没有结束日期视为长期有效 | 记录“确认生效”，来源你本人，含修改过的字段 |
| 修改 | 医嘱页 | 修改条目 | 不变 | 记录“修改”与字段名 |
| 作废 | 医嘱页 | void | 到 已作废，进入历史 | 记录“作废”，可带原因 |
| 继续遵守 | 只对待复核条目：开场卡片、待处理条或医嘱页，底部面板 | continue，同时提交复查日期与预计结束两个字段 | 待复核 到 生效中 | 记录“继续执行”，含两个新日期 |
| 不解除 | 只对带解除建议的生效条目：待处理条、医嘱页或解除面板 | cancel-proposal | 不变 | 记录“撤销解除建议” |
| 确认解除 | 只在医嘱页，底部面板二次确认，并勾选“不能撤销” | resolve | 到 已解除 | 记录“确认解除”，含依据 |

继续遵守与不解除只会让约束延续，不属于“确认或解除”，因此允许在对话里完成；确认生效与确认解除只在医嘱页。

### 解除面板的次按钮按条目状态切换

| 条目状态 | 次按钮 | 点了之后 |
|---|---|---|
| 待复核 | 继续遵守 | 关闭解除面板，打开继续遵守面板 |
| 生效中，带解除建议 | 不解除，撤销这条建议 | 调用 cancel-proposal，关闭面板 |
| 生效中，没有建议 | 取消 | 只关闭面板 |

确认解除成功后，正式版关闭面板，列表里该条移到“历史与审计”并显示“已解除”；可视稿里按钮 2.2 秒后复原只是为了能反复演示。

### 继续遵守面板：两个日期一起提交

后端的继续执行会同时覆盖复查日期与预计结束两个字段，没提交的那个会被清空。所以面板：

1. 两个字段都显示，预填当前值，并在旁边写“原 某日”或“原 未设”。
2. 触发这次复核的那一项用赭色左线标出，原因措辞取自后端的到期原因（复查日期一类，或预计结束一类）。
3. 复查日期给快捷项：1 个月后、3 个月后、不再设；也可选任意日期。预计结束默认保持原值。
4. 提交时总是两个一起发。后果清单逐项写清：“复查日期改为某日”或“不再设复查日期”；“预计结束保持不设，继续长期有效”或“预计结束改为某日，结束前一天进入待复核”。
5. 后端要求新日期不能再次立即到期：复查日期必须晚于今天，预计结束至少在今天之后两天；不满足时在对应字段下显示后端的说明（still_due）。

### 日期措辞（按后端规则）

- 预计结束前一天（REVIEW_LEAD_DAYS 为 1）条目进入待复核，所以写“结束前一天起进入待复核”，不写“到期后”。
- 待核对条目如果有预计结束日期，过了那天仍未确认会被自动作废；条目标题下用赭色写“某日之后仍未确认，会自动作废”。
- 后端没有定时任务，状态在有人查询时才刷新。系统事件的来源写“系统（打开应用时检查）”，时间用实际检查的时间，不写零点。

### 隐私遮盖：Sensitive 组件

实现为一个 Sensitive 包裹组件。每个页面把下表中的内容包进去，并在页面注册时登记“本页有敏感区”。遮盖开关是全局状态：打开时所有 Sensitive 盖上斜纹并设 aria-hidden，同时播报“已遮盖”；应用切到后台再回来时默认打开。

| 页面 | 敏感区 |
|---|---|
| 对话 | 全部消息、附页、开场卡片、待复核条 |
| 饮食记录 | 能量账本、营养表、三餐 |
| 拍照识别结果 | 菜名、份量、数字、整餐评价 |
| 附近餐厅 | 地点输入、“记住大致区域”一行 |
| 医嘱（三个标签与录入页） | 全部内容 |
| 经期 | 全部内容（两个记录按钮除外） |
| 我的、修改档案 | 全部档案内容 |
| 训练 | 顶部的运动限制（它是医嘱内容） |

遮盖入口：有底部导航的页面在导航最右（拇指区），没有导航的二级页在右上角。打开遮盖后，导航里这一格的文字改为“已遮盖”，读屏名称改为“已遮盖，点按恢复显示”，不会被当成第五个标签。

遮盖时每个敏感区同时：盖上斜纹；设 aria-hidden；设 inert，键盘无法进入其中的按钮与输入框（inert 需 Chromium 102、Safari 15.5，在最低支持范围内）。不支持 inert 时的回退：把子树内可聚焦元素临时设为 tabindex=-1，取消遮盖时恢复原值。可视稿已按此实现。

## 五、动效规范

只给用户动作和数字变化做动效；没有进场动画、滚动触发或常驻循环（流式光标、识别转圈与骨架扫光除外，它们都表示“正在进行”）。只动 transform 与 opacity。按住确认已取消，因此不再有按住进度动画。

| 对象 | 做什么 | 时长 | 曲线 | 减弱动效时 |
|---|---|---|---|---|
| 回答流入 | 按服务端分段追加文字，末尾靛色光标闪烁 | 跟随数据 | — | 整段到达后一次显示，光标不闪 |
| 依据与附页出现 | 淡入并上移 4 像素 | 320 ms | (.2,.7,.2,1) | 直接出现 |
| 数字变化 | 从旧值数到新值 | 600 ms | 缓出（三次方） | 直接显示终值 |
| 能量刻度 | 每格从底部长出，从左到右错开 | 480 ms，每格错开 6 ms | (.2,.7,.2,1) | 直接显示 |
| 底部面板 | 自下滑入，遮罩淡入 | 320 ms | (.32,.72,0,1) | 只淡入，不位移 |
| 依据折叠 | 高度展开，箭头翻转 | 200 ms | (.4,0,.2,1) | 直接展开 |
| 遮盖 | 斜纹淡入 | 200 ms | (.4,0,.2,1) | 直接出现 |
| 识别进度圈 | 转动 | 1000 ms 循环 | 线性 | 静止，只靠文字 |
| 骨架扫光 | 亮带扫过骨架块 | 1400 ms 循环 | (.4,0,.2,1) | 不扫光 |
| 按钮按下 | 缩到 0.985 | 120 ms | (.4,0,.2,1) | 无 |

实现：CSS 用 prefers-reduced-motion 把时长压到 1 毫秒；脚本驱动的计数与流式在开始前读 matchMedia 并监听变化。流式文本只追加文本节点、按动画帧合批；消息容器 aria-live=polite，流式过程中 aria-busy=true，结束后读一次。不引入动画库。

## 六、刻度尺选择器的计算

| 参数 | 身高 | 体重 |
|---|---|---|
| 每单位像素 | 每厘米 8 像素 | 每千克 16 像素 |
| 小刻度 | 每 1 厘米 | 每 0.5 千克 |
| 大刻度与标签 | 每 10 厘米 | 每 5 千克 |

计算：容器宽 w，中线 c = w / 2，当前值 v。可见范围是 v ± c / 每单位像素。值为 k 的刻度画在 x = c + (k − v) × 每单位像素。指针固定在中线。标签只画完整落在容器内的那几个（x − 14 不小于 0 且 x + 14 不大于 w）。容器尺寸变化时用 ResizeObserver 重算。拖动时 v 随位移变化并吸附到小刻度；点数字弹出数字键盘直接输入。在 360 与 390 宽度下已核对：165 厘米时 160 的标签在指针左边 40 像素，56.5 千克时 55 的标签在指针左边 24 像素。

## 七、字体与加载

### 搭配

| 角色 | 字体 | 字重 |
|---|---|---|
| 固定页题与小节题 | 思源宋体（Noto Serif SC，OFL 1.1） | 只用 700 一个字重 |
| 16 号以上的展示数字 | Source Serif 4（OFL 1.1），表格数字与等高数字 | 只用 500 一个字重 |
| 正文、动态文字、16 号以下的数字 | 系统黑体：苹方、鸿蒙黑体、MiSans、Noto Sans CJK、微软雅黑 | 400、500、600 |

### 实测字体体积

测量方法：从可视稿的全部手机画面中取出所有用宋体显示的文字，加上画面里没出现但会用到的固定标题，共 150 个不重复的字；交给 Google Fonts 的 text= 子集服务生成 woff2，记录字节数。数字子集是 0 到 9、逗号、小数点、冒号、斜杠、减号、乘号、百分号。测量在浏览器里直接请求，没有把字体源文件下载到本地，所以没有用 pyftsubset；构建时会改用 pyftsubset 生成并复测，预计差异在一两成以内。

| 子集 | 字数 | 实测 woff2 体积 |
|---|---|---|
| 思源宋体 700，固定标题 | 150 | 29.6 KB |
| 思源宋体 500，同一组字（对照） | 150 | 29.1 KB |
| Source Serif 4 500，数字与符号 | 17 | 3.8 KB |
| 对照：本展示页按 Google 切片自动加载的宋体 | 17 个切片 | 614 KB |

结论：第二稿“两个字重约 40 KB”的估计偏乐观，实际两个字重约 59 KB。现在只留 700 一个字重，约 30 KB；固定标题再增加时按每 100 字约 15 到 20 KB 估算，上限定为 40 KB。最后一行说明了为什么动态文字不能用宋体：只要宋体去显示任意文字，就得靠切片按需加载，一页就可能拉下几百 KB。

### 加载策略

1. 字体随前端打包、同源提供，不用 Google 字体服务（中国大陆访问不稳定，且会向第三方暴露访问记录）。可视稿为方便离线查看仍用 Google Fonts。
2. 构建时扫描源码里的固定标题，生成宋体 700 子集；生成 Source Serif 4 500 数字子集。两者都 preload，font-display: swap。
3. 回退字体用 size-adjust、ascent-override 对齐度量，避免换字体时跳动。
4. 安卓没有可靠的系统宋体，所以不存在“退回系统宋体”这回事：字体没到时，标题直接用系统黑体 700，数字用系统黑体表格数字。index.html 的“系统字体回退”开关可直接看效果（shots/360-05-diary-system-font.png、360-07a-medical-system-font.png）。

### 首屏预算（中端安卓机、对话页）

| 项目 | 上限 | 说明 |
|---|---|---|
| 对话路由首屏脚本（压缩后） | 150 KB | React 与路由、数据请求库、对话页用到的少量 React Aria 组件与业务代码；日历等重组件不在这个路由里 |
| 样式（压缩后） | 20 KB | |
| 预加载字体 | 35 KB | 实测宋体 700 子集 29.6 KB + 数字 3.8 KB |
| 最大内容绘制 | 实地 4G 网络第 75 百分位 2.5 秒；Lighthouse 移动端模拟 3.0 秒 | 这是没有服务端渲染的单页应用，模拟慢速 4G 下 2.5 秒偏紧；对策是在 index.html 里内联静态外壳（页头、导航、输入框）。外壳必须与脚本接管后的首帧逐像素一致，否则接管时会产生布局偏移。最大内容绘制要在对话内容（开场卡片或最近一条回答）上量，不能拿外壳里的页题充数 |
| 累计布局偏移 | 0.05 | 回退字体度量对齐；流式消息只在列表末尾追加，开场卡片与待复核条预留高度 |

以上数字在实现时用打包分析与 Lighthouse 移动端模式核对，超出时先拆路由、再砍字体。

## 八、组件库决定

### 三个选项

| 选项 | 优点 | 缺点 | 许可 |
|---|---|---|---|
| (a) 保留 Ant Design Mobile，深度定制主题 | 中文生态好，组件全（下拉刷新、图片上传、选择器、轻提示、安全区），最快达到验收 | 视觉基因强，主题变量只能改颜色、圆角、字号，结构改不了；要做成本稿得大量覆盖内部 adm- 类名，升级时容易坏 | MIT |
| (b) react-aria-components + 自绘样式 | 触控按压、焦点锁定、读屏语义、本地化日历与数字输入都很扎实；样式完全自由 | 工作量大，见下面的“真实成本” | Apache-2.0 |
| (c) 混合，从 React Bits 借动效 | 有几个微交互思路可借 | 许可证带 Commons Clause 销售限制；目录大多依赖悬停或 WebGL | MIT + Commons Clause |

### 推荐 (b)，以及它的真实成本

用 react-aria-components 提供行为与语义，样式全部按本稿自绘；动效不引入库；React Bits 只借鉴思路并按下面的“净室”要求自写。理由：这套设计的辨识度全在自绘部分（账本、刻度尺、附页、结论形状、遮盖），(a) 的结构会一路和它对抗；而手机上最难做对的触控与读屏，React Aria 比我们从零写可靠。Radix（MIT）排第二：它没有日历与数字输入，触控处理也不如 React Aria 细。

成本如实写下：

- 约 25 个组件要手写样式，工作量约为“定制 antd-mobile 主题”的 1.5 到 2 倍。
- 没有现成的轻提示、下拉刷新、图片上传，需要自己做（轻提示用 aria-live 区域；下拉刷新不做；图片上传用原生选择加画布压缩）。
- 日历显式设置 firstDayOfWeek 为 mon。我在 Chromium 里查过 Intl 的 zh-CN 周信息，首日是周一；但 React Aria 用的是 @internationalized/date 自带的周数据，没核对过，所以无论默认值是什么都显式设置。
- react-aria-components 加 @internationalized/date 压缩后约 60 到 90 KB，必须按路由拆包：日历只进经期路由，对话路由只带按钮、文本框、折叠与对话框。

需要更新的地方：设计文档里“组件库用 Ant Design Mobile”改为“react-aria-components（Apache-2.0）”；依赖许可证清单追加 react-aria-components、@internationalized/date、Noto Serif SC 与 Source Serif 4（OFL 1.1）。

### React Bits 许可证核查

核查了 GitHub 仓库 DavidHDev/react-bits 主分支的 LICENSE.md（2026 年 10 月 12 日）。标题是“MIT + Commons Clause License Condition v1.0”：只允许“作为应用、网站或产品的一部分”使用与分发；Commons Clause 一节写明可以商用，但不得出售、再许可或再分发这些组件本身，无论单独、打包还是移植版本。

结论：它不是开源许可，属于项目规定里“带销售限制条款”的一类，不复制任何代码。步骤 12 要把项目整理成作品集，仓库若公开，复制来的组件可能被视为“再分发组件本身”。其依赖 gsap 用的是 Webflow 的免费使用条款，不是开源许可，本项目不用。

净室要求：规格只写行为描述（本文件第五节与组件清单就是全部输入）；实现 CountUp、StatusMark、ThoughtLine 一类组件时，实现者不得打开 React Bits 的源码；变量名、状态机与结构由实现者自己设计。

## 九、关于“按住一秒确认”的决定

取消。确认解除改为：面板写明四条后果，最后一条“不能撤销”用朱色；下面一个必勾的勾选框“我知道解除后不能撤销，需要重新录入才能恢复这条约束”；勾选后“确认解除”变成可点的朱色实心按钮；结果用 aria-live=assertive 播报。不加 300 毫秒延迟：勾选本身已是有意的第二个动作，再加延迟只会让人以为没点上。

理由：按住手势不可发现（短按没有反馈时，用户以为坏了）；在读屏下需要“双击并按住”，在 iOS 上还会和长按菜单冲突；对手部不便的用户是障碍。而验收要求的是“明确点击、二次确认、写清将发生什么”，勾选加按钮把后果写成一句用户必须读过才能勾的话，比按住更直接地满足要求。不做成设置项。

## 十、无障碍

- 对比度：见颜色表。--ink-4 只画刻度；上月日期与禁用按钮文字都用 --ink-3。禁用按钮保持 4:1 左右，让人读得出按钮上的字。
- 不只靠颜色：结论有四种形状；把握程度有文字；需要核对的项有文字原因。
- 字号：全站最小 12；实现时用 rem，跟随浏览器字号设置；允许缩放。
- 触控目标：见令牌表。
- 安全区：页头上沿加 env(safe-area-inset-top)，底部导航、固定操作区与面板下沿加 max(env(safe-area-inset-bottom), 8px)；viewport 设 viewport-fit=cover；安卓用 interactive-widget=resizes-content，iOS 用 visualViewport 处理软键盘。
- 读屏：刻度类图形都有完整 aria-label；刻度尺是滑块语义；面板打开时焦点进入标题，关闭后回到触发按钮；就医提示 role=alert；遮盖时敏感区 aria-hidden 并播报。
