# 步骤 11 前端 H5：设计

对应步骤文档：docs/11-前端H5.md。依赖步骤 08、09、10。总览已定：手机浏览器 H5，React 前端，Python 后端。

## 已定的选择

1. 视觉与组件以设计稿为准：docs/superpowers/design/step11/index.html 与 DESIGN.md（蓝白“影青”主题：白瓷面板承载数据，磨砂玻璃只用于固定外壳，统一圆角体系，含降级与性能预算）。组件库用 React Aria Components（Apache-2.0）提供行为与无障碍，样式全部自写，不用 Ant Design Mobile；不用任何动画库，动效用 CSS 与 Web Animations API；React Bits 许可为 MIT 加 Commons Clause，不拷贝其代码，只按行为描述自行重写（洁净室做法，见 DESIGN.md 第八节）。设计稿与本文冲突时，视觉、令牌、组件与动效以设计稿为准，业务规则以后端为准。
2. 技术方案：Vite + React + TypeScript 单页应用；路由 React Router（按路由拆包）；接口数据用 TanStack Query；接口类型由 openapi-typescript 从后端的接口描述生成，并有测试保证生成结果是最新的。除 React Aria Components 外其余都是 MIT 许可。字体按设计稿的方案自托管子集，不在运行时访问外部字体服务。
3. 开发时 Vite 把 /api 转发给本机后端；上线时前端打包成静态文件，由后端在根路径一并提供（同源，不开跨域）。另提供一个带自签证书的 HTTPS 局域网模式，供真机测定位。
4. 第 6 条（两种手机与浏览器）：Claude 用 Playwright 模拟 iPhone（WebKit 内核）与安卓手机（Chromium 内核）自动跑关键流程并截图；真机上的拍照、相册与定位由用户补测，按惯例本步骤有条件通过。
5. 以上由用户在对话中确认；第三部分（测试、验收、交付物）按本文默认执行，用户已授权。

## 一、整体结构

仓库根目录新建 frontend/，按功能模块组织：

- src/api：接口客户端（统一带令牌、统一解析 {"error": {"code", "message"}}、401 清令牌回登录页）、生成的接口类型、按模块的查询与修改钩子。
- src/features：auth、onboarding（免责与建档）、chat、photos、meals、cycle、medical、fitness、restaurants、settings、me。
- src/components：状态组件（加载中、失败带重试、无数据、数据不足、需要授权）、“仅供参考”标签、就医提示条、二次确认弹窗、遮盖层、跳转卡片。
- src/app：路由、底部标签栏、路由守卫、全局遮盖开关、主题。

导航：以聊天为中心，底部四个标签：对话、记录（饮食与训练）、健康（经期与医嘱）、我的（档案、设置、隐私），右端是一格一键遮盖。两个模块都不开放时“健康”入口隐藏、导航变三项；只有医嘱时直接显示医嘱列表，不显示标签页。拍照入口在聊天输入框旁；附近餐厅入口在聊天快捷按钮与记录页。

守卫顺序：未登录 → 登录页；未确认免责 → 免责页；档案未填完 → 建档页。显示哪些模块只看后端的能力清单（经期入口仅对开放经期模块的用户显示）。

令牌存浏览器本地存储，每次请求带上；401 清掉并回登录页。

界面不做业务规则判断：结论、依据、提示文案、错误说明一律展示后端给的内容。

隐私：右上角一键遮盖，打开后医嘱、经期、档案等敏感页面内容模糊显示，应用切到后台再回来时默认遮盖；密钥只显示后端给的掩码，前端从不保存密钥原文。

“仅供参考”：所有预测、建议、评价旁统一显示；就医类回复与高风险内容用醒目的红色提示条。

视觉：见设计稿。蓝白配色，玻璃只在固定外壳（底部导航与输入底座、吸顶页头、底部面板）使用并遵守设计稿的模糊预算；数据密集区用不透明白瓷面板；降低透明、不支持 backdrop-filter、强制颜色与低端机时降级为实色；经期页不用粉色刻板配色与俗称，文案中性；一键遮盖用不透明斜线纹，不用模糊。中文界面。

## 二、页面与关键流程

页面：登录与注册；免责声明；建档（三步：基本信息、活动与目标、饮食偏好与忌口，可跳过第三步）；聊天主页；拍照识别；饮食记录；经期；医嘱（待核对、生效中、历史三个标签，含录入与证据上传）；健身（记训练、列表、周汇总与动作趋势折线）；附近餐厅；设置（模型服务、隐私与数据、免责声明）；我的。

聊天：顶部为打开应用时的主动开场卡片（回答或“不用了”）；对话中助手的依据折叠显示；输出检查附加的医嘱提醒用醒目样式；就医类回复红色提示条；回答以基于请求的流式读取逐段显示（不用 EventSource，错误响应也要能读出说明）；失败可重试；快捷按钮：附近吃什么、记一餐、看医嘱；后端标出医嘱线索时只显示“去医嘱页处理”的按钮。没配模型时提示去设置。

拍照：选图或拍照（输入框接受图片并允许调用相机）→ 识别中 → 菜品卡片列表（菜名、份量、克数、热量、把握程度，需提醒修正的带标记，待确认的必须先选候选、改名或删除）→ 整餐评价与“仅供参考” → 选日期与餐次 → 确认入库 → 跳到当天饮食记录。失败时显示后端的说明与下一步（重拍、去设置）。

医嘱：确认生效与确认解除都在医嘱页的底部面板里完成：面板写明将发生什么，必须勾选“我知道……”后确认按钮才可用（取代按住确认）；聊天里不能直接确认或解除。每次打开应用查询待复核项，同一时间只显示一张开场卡片，待复核优先。动作按状态区分：待复核条目是“继续遵守”（打开面板，同时显示并预填复查日期与预计结束两项日期，提交永远带两项，对应后端 continue）或“去确认解除”；生效中且带解除建议的条目是“不解除”（对应 cancel-proposal）或“去医嘱页处理”，文案不叫待复核；生效中无建议的条目只有“取消”。“删除”一律写作“作废”。详见设计稿 DESIGN.md 第四节动作表。

经期：月历标出经期与预测区间（虚线浅色并写明置信范围）、当前阶段与提示、记录经期与记录今天；数据不足时如实提示。

附近餐厅：只在后端“应询问定位”为真时弹出定位说明；拒绝后不再弹，改为地点输入；结果卡片（名称、类型、距离、结论、可点、导航按钮）、已避开类型及原因（标明出自哪道菜）、固定声明；可选“记住大致区域”，设置里可清除。

模型配置：添加服务（类型、地址、密钥）→ 获取模型 → 测试连通 → 为日常对话与看图识别选模型，可手动标注能力；每步显示成功或失败；密钥只显示掩码。

后端小改动（随本步骤完成）：聊天消息输出带编号；审计列表支持按客户端名筛选；新增按用户的医嘱事件列表（GET /api/medical/events，带 limit），供医嘱历史与审计页使用；打包后的前端目录存在时，后端在根路径提供静态文件并对前端路由回退到首页（/api 开头的路径不受影响）。

## 三、测试、验收与交付物

自动化测试：

- 单元与组件测试：Vitest + React Testing Library，接口用 MSW 模拟（均为 MIT）。覆盖：接口客户端（令牌、错误解析、401）、守卫顺序、能力清单决定入口、二次确认弹窗、流式读取（含错误响应）、拍照修正流程、遮盖开关、掩码显示、各状态组件、“仅供参考”。
- 类型检查（TypeScript 严格模式）与 ESLint 必须零错误。
- 接口类型生成结果与后端接口描述一致的检查测试。
- 端到端：Playwright（Apache-2.0）对真实后端（测试库，模型、看图模型、高德用本机模拟服务）跑关键流程，两种设备：iPhone 13 模拟（WebKit）与 Pixel 7 模拟（Chromium）。流程：新用户注册到拍照入库（验收第 1 条）；男女用户的经期入口（第 2 条）；医嘱确认与解除的二次确认、聊天无法直接完成（第 3 条）；待复核提醒（第 4 条）；模型配置全流程（第 5 条）；状态提示（第 7 条）；“仅供参考”（第 8 条）；掩码（第 9 条）。截图保存到不进仓库的结果目录。
- 后端改动的 pytest 测试；后端全量测试保持零失败零警告。

包管理用 pnpm，锁定文件进仓库。前端依赖与许可证追加到 docs/01-交付物/依赖许可证.md 的新一节。

代验：Claude 按 9 条验收标准，用 Playwright 两种设备模拟与内置浏览器逐条核对，记入验收记录的“代为验收记录”；第 6 条真机部分由用户补测（提供核对清单），本步骤预计有条件通过。

交付物（docs/11-交付物/，不含代码、命令与反引号）：页面清单与信息结构说明；关键流程交互说明（建档、拍照识别、医嘱核对与解除、经期记录、模型配置）；状态与异常界面清单；手机端适配说明与测试设备清单（含真机核对清单）；验收记录（9 行，用户验收列先空，由文档测试守护）。README 新增“前端 H5”一节（安装、开发、打包、局域网 HTTPS 真机测试），总览中步骤 11 状态随验收更新。
