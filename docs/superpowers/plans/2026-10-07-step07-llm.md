# 步骤 07 多模型接入 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用户添加多个模型服务（名称、类型、地址、密钥），后端统一拉取模型列表、标注看图与工具调用能力（可手动修正）、做连通性测试并区分失败原因、为“对话”与“看图识别”分别选模型；后端对内只暴露一个统一调用入口。满足 `docs/07-多模型接入.md` 的 7 条验收标准（第 2 条的真实服务实测由用户运行实测脚本完成）。

**Architecture:** 新增 `app/llm` 包。三个自写的轻量适配器（OpenAI 兼容格式、Claude、Gemini）基于项目已有的 httpx2，负责拉取模型、对话（文字、图片、工具）与错误归类；能力对照表是只读数据文件，按模型名规则匹配，用户覆盖优先；服务配置、模型与用途分配入库，密钥加密且延迟加载，只在调用时解密；用户填写的地址经过协议与内网地址检查。统一调用入口 `complete` 按用途找到模型并在调用前做能力检查。真实服务实测由用户用实测脚本在本机运行。

**Tech Stack:** Python 3.12、FastAPI、SQLAlchemy 2、PostgreSQL 16、Alembic、pydantic v2、httpx2（导入名 httpx2，接口与 httpx 相同，测试用 httpx2.MockTransport）、pytest。不新增依赖。

**Spec:** `docs/07-多模型接入.md`。设计已在对话中由用户确认：自写轻量适配而不用 LiteLLM（LiteLLM 在 2026 年 3 月发生过 PyPI 供应链投毒，恶意版本窃取环境中的密钥）；真实服务实测由用户运行脚本，覆盖通义千问、DeepSeek、豆包、智谱四家；Claude 与 Gemini 只做模拟测试并在记录中写明未实测。

## 关键决策

| 决策 | 内容 | 理由 |
|---|---|---|
| 适配层 | 自写三个适配器：openai_compatible、anthropic、gemini | 用户选定；LiteLLM 有供应链投毒前科且依赖很重；本项目只需拉取模型、对话、错误归类 |
| 服务类型 | kind 取 openai_compatible、anthropic、gemini；另提供预设（通义千问、DeepSeek、豆包、智谱、OpenAI、Claude、Gemini）只用于填默认地址 | 国内主流服务都提供兼容格式 |
| 能力来源 | 有效能力 = 用户覆盖（真、假）> 对照表规则 > 未知；对照表按模型名正则匹配，先匹配先用 | 拉取到的列表通常不含能力信息 |
| 用途 | chat（日常对话）与 vision（看图识别）；看图用途只接受有效看图能力为“是”的模型，“否”和“未知”都拒绝并提示手动标注；对话用途拒绝对话能力为“否”的模型 | 验收第 7 条：明确提示而不是静默失败 |
| 运行时检查 | 统一调用前再次检查：用途模型被删或能力被改成否时给明确错误；带图片而模型看图能力不是“是”时拒绝；带工具而工具能力为“否”时拒绝 | 分配之后能力可能被改 |
| 连通性测试的判定 | 先拉取模型列表，再用指定模型发一次最小对话；列表 404 而对话成功 → 通过但提示“该服务不支持拉取模型列表，请手动添加模型编号”；两者都 404 → 地址错误；列表成功而对话说模型不存在或 404 → 模型不可用 | 部分服务未必提供模型列表接口，要在实测中核实 |
| 密钥解密时机 | 密钥列延迟加载；只有调用服务的代码路径访问它 | 规格要求调用时才解密 |
| 测试注入 | 服务层函数接收 `adapter_factory`，接口通过依赖 `get_adapter_factory` 取得，测试覆盖它以注入 MockTransport | 测试不碰网络 |
