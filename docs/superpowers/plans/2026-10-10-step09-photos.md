# 步骤 09 拍照识别 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用户上传一张饭菜照片，后端用“看图识别”用途的模型识别菜品与份量，匹配步骤 04 的营养库计算热量与营养（模型不给热量），匹配不上的标为待确认，用户可修正，只有确认后才写入饮食记录；用步骤 04 的引擎按个人约束评价这一餐。满足 `docs/09-拍照识别.md` 的 9 条验收标准（第 8 条照片评测由用户运行评测脚本完成）。

**Architecture:** 新增 `app/photos` 包：`images.py`（Pillow 校验、转正、去 EXIF、缩放、重新编码）、`recognition.py`（提示词与模型输出解析）、`portions.py` 与 `data/portion_units.json`（份量换算）、`matching.py`（匹配营养库、计算营养、提醒修正规则）、`models.py`、`service.py`、`schemas.py`、`router.py`、`eval_check.py`（评测脚本）。模型调用走步骤 07 的 `resolve_target(user, "vision")` 与 `complete(..., target=...)`；评价走步骤 04 的 `build_context` 与 `evaluate_meal`；写入饮食记录走 `meals.log_meal`。

**Tech Stack:** Python 3.12、FastAPI（UploadFile）、SQLAlchemy 2、PostgreSQL 16、Alembic、httpx2、pytest；新增依赖 Pillow（12.x，MIT-CMU 许可，用户已确认）。

**Spec:** `docs/09-拍照识别.md`。设计已在对话中由用户确认：后端用 Pillow 压缩与去除隐私信息；照片评测由用户运行脚本；只做应用接口（不进智能体聊天、不进 SDK 与 MCP）。另需满足步骤 08 评审带入的要求：看图调用用 `resolve_target(user, "vision")`；服务端自己校验图片（大小、类型、内容），不只靠接口模式；新的上传接口纳入请求体大小中间件；结构化识别用“正文里的 JSON”而不是工具调用。

## 关键决策

| 决策 | 内容 | 理由 |
|---|---|---|
| 图片格式与大小 | 只收 JPEG、PNG、WebP，按文件头判断；原始文件不超过 8 MB；像素总数不超过 4000 万；HEIC 给出“请改成 JPEG 再上传”的提示 | 浏览器拍照通常给 JPEG；Pillow 默认不支持 HEIC |
| 图片处理 | 先按 EXIF 方向转正，再去掉全部元数据，带透明通道的贴到白底，长边缩到 1280 像素，以质量 85 重新编码为 JPEG | 去隐私、省模型费用、统一格式 |
| 识别输出 | 模型只输出一段 JSON：状态（ok、not_food、unclear）与菜品列表（菜名、份量说法、估计克数、把握程度 0 到 1），最多 12 个；格式不对重试一次 | 多数看图模型工具能力未知，用正文 JSON |
| 不是食物、看不清 | 不保存记录，返回 422 并给出重拍建议 | 验收第 9 条 |
| 匹配 | 用营养库检索，第一个结果是精确、常用名或别名命中才算“已匹配”；否则“待确认”，附最多 5 个候选 | 不擅自编造数据 |
| 份量换算 | 依次用：该食物自带份量 → 通用换算表（按类别的碗、份、盘、个、块、片、勺、杯、根、半个手掌、一拳头等）→ 模型估计克数（标为估算）→ 都没有时用类别默认份量（标为估算） | 规格：常见说法统一换算到克，换算表可维护 |
| 提醒修正 | 把握程度低于 0.6、待确认、克数小于 10 或大于 1500、克数只来自估算，各给一条原因；有任一原因即“建议修正” | 规则默认值，评测后再调 |
| 确认入库 | 只有草稿可确认；还有待确认菜品时拒绝；每个已匹配菜品写一条饮食记录（备注“拍照识别”）；只能确认一次 | 验收第 5 条 |
| 评价 | 每次返回识别记录时，用引擎对已匹配菜品做一餐评价（只针对今天的约束），结论与依据全部来自引擎 | 验收第 6 条 |

**Interfaces:**

    - `get_recognition(db, user_id, rec_id)`、`list_recognitions(db, user_id, limit=50)`（新的在前，不加载图片）
    - `update_items(db, user_id, rec_id, items: list[dict]) -> PhotoRecognition`：只有草稿可改（否则 `photo_not_editable` 409）；整组替换；每项可带 id（保留）、name、portion_text、grams（用户给的，source user）、food_id；重新 `build_item`；最多 12 项；空列表允许（但确认时会拒绝）
    - `confirm(db, user_id, rec_id, eaten_on, meal_type, today) -> PhotoRecognition`：只有草稿可确认（否则 `photo_not_editable`）；没有菜品 → `photo_empty_meal`(422)；有待确认菜品 → `photo_items_need_confirmation`(422，说明先选候选、改名或删除)；在一个事务里对每个已匹配菜品调用 `meals.log_meal(..., grams=克数, portion=None, note="拍照识别")`，记录 meal_entry_ids、eaten_on、meal_type、confirmed_at，状态改为 confirmed
