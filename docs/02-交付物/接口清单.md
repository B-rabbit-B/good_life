# 步骤 02 接口清单

本文列出步骤 02 提供的全部经期接口，共 12 个。所有接口路径都以 /api/cycle 开头，请求与响应的正文都是 JSON 格式（删除成功时无正文）。日期一律写成“年-月-日”的格式，例如 2026-09-01。

在线的交互式接口文档由服务自动生成，服务启动后在浏览器打开 8000 端口下的 docs 页面即可查看并直接试用，操作顺序见仓库根目录 README 的“经期模块演示”一节。

## 一、访问条件

所有经期接口都要同时满足三个条件，由统一的入口检查，缺一不可：

1. 已登录：请求头带有效的访问令牌，否则返回 401（未登录 not_authenticated，或令牌失效 invalid_token）。
2. 已确认当前版本的免责声明：否则返回 403，错误码 disclaimer_not_accepted。
3. 经期模块对该用户开放：档案性别为女性，并且没有主动关闭经期功能。否则返回 403，错误码 cycle_not_available。判断规则只有一处（步骤 01 的能力清单），本模块不重复实现。

有一项自动化检查负责把关：它会逐个检查所有 /api/cycle 开头的接口，只要有一个没有挂上上述统一入口，测试就会失败。

其他约定：

- 任何接口都不接受客户端传入用户编号，请求里带了多余字段会被 422 拒绝。
- “今天”由服务统一提供，服务层不自行取系统日期，因此测试中可以固定为某一天。
- 所有预测和阶段提示的返回内容都带有“仅供参考，不能用于避孕或诊断”一类的说明。

## 二、接口一览

所有接口都需登录、需已确认免责声明、需经期模块开放，下表不再重复；这三项对应的错误码（not_authenticated、invalid_token、disclaimer_not_accepted、cycle_not_available）在“主要错误码”列中不再逐个列出。

### 月经记录

| 方法 | 路径 | 请求字段或查询参数 | 用途 | 主要错误码 |
|---|---|---|---|---|
| GET | /api/cycle/periods | 无 | 读取自己的全部月经记录，按开始日从新到旧排列。每条含编号、开始日、结束日（可为空）、创建时间 | 无 |
| POST | /api/cycle/periods | start_date（开始日，必填）；end_date（结束日，可不填，不填表示还没有结束） | 新增一次月经，成功返回 201 和这条记录。补录过去的月经也用它 | period_in_future、invalid_period_range、period_too_long、period_overlap、validation_error |
| PATCH | /api/cycle/periods/{编号} | start_date、end_date，均可选，只提交要改的；start_date 不能提交为空，end_date 提交为空表示重新标记为未结束 | 修改一次月经，比如补填结束日。修改后重新做全部日期检查，重叠检查会排除这条记录自己 | not_found、period_in_future、invalid_period_range、period_too_long、period_overlap、validation_error |
| DELETE | /api/cycle/periods/{编号} | 无 | 删除一次月经，成功返回 204，无正文 | not_found |

### 每日记录

| 方法 | 路径 | 请求字段或查询参数 | 用途 | 主要错误码 |
|---|---|---|---|---|
| GET | /api/cycle/day-logs | 查询参数 start（起始日）、end（截止日），均可不填；不填截止日按今天算，不填起始日按截止日往前 90 天（含截止日当天）算 | 读取某个日期范围内的每日记录，按日期从早到晚排列。每条含日期、流量、疼痛、情绪、症状、备注、最近修改时间 | validation_error（日期格式不对） |
| PUT | /api/cycle/day-logs/{日期} | flow（流量）、pain（疼痛，0 到 3）、mood（情绪）、symptoms（症状列表，最多 20 个）、note（备注，最长 500 字），全部可选，取值见《经期数据表说明》 | 保存某一天的记录。这一天已有记录则整条替换，没提交的项变为空，不是合并；没有则新建 | log_in_future、validation_error |
| DELETE | /api/cycle/day-logs/{日期} | 无 | 删除某一天的记录，成功返回 204，无正文 | not_found |

### 经期设置

| 方法 | 路径 | 请求字段或查询参数 | 用途 | 主要错误码 |
|---|---|---|---|---|
| GET | /api/cycle/settings | 无 | 读取当前状态与最近修改时间；第一次读取时自动创建，默认是正常记录 | 无 |
| PUT | /api/cycle/settings | status（必填）：tracking（正常记录）、pregnant（孕期）、paused（暂停预测）三选一 | 切换状态。孕期或暂停状态下不再输出经期预测，切回正常记录后立即恢复 | validation_error |

### 统计、预测、阶段与提示

| 方法 | 路径 | 请求字段或查询参数 | 用途 | 主要错误码 |
|---|---|---|---|---|
| GET | /api/cycle/stats | 无 | 查询周期统计：完整周期数、月经次数、平均周期长度、周期波动程度、最短与最长周期、平均经期长度、最近周期长度列表，以及最近 365 天的已记录天数、常见症状、出血日平均疼痛。算法见《预测与阶段规则说明》。暂停状态下仍可查询 | 无 |
| GET | /api/cycle/prediction | 无 | 查询预测：状态（正常 ok、数据不足 insufficient_data、已暂停 paused）、预计下次月经开始日与区间、预计排卵日与区间、易孕窗口、降级标记、提示文字、免责说明。数据不足或暂停时所有日期都为空 | 无 |
| GET | /api/cycle/phase | 查询参数 date（要查询的日期），可不填，不填按今天算 | 查询某一天的阶段：月经期、卵泡期、排卵期、黄体期或未知，以及周期第几天、距下次月经还有几天、是否按预测推算、未知时的原因（没有数据、早于最早记录、数据不足、孕期、暂停） | validation_error（日期格式不对） |
| GET | /api/cycle/tips | 查询参数 date，可不填，不填按今天算 | 查询某一天的阶段提示：包含该天的阶段信息、适用的提示规则列表（编号、阶段、类别、严重程度、标题、内容、依据）和固定的免责说明。阶段未知时只有通用提示 | validation_error |

## 三、统一错误格式

与步骤 01 完全相同：所有错误响应的正文都是一个 error 对象，含机器可读的错误码 code 和中文提示 message；参数校验类错误会额外带 details 列表。

## 四、本步骤新增的错误码

| 错误码 | HTTP 状态码 | 中文含义 | 出现场景 |
|---|---|---|---|
| not_found | 404 | 记录不存在 | 修改或删除一次月经时，编号不存在或属于别的用户（两种情况一样，不暴露该编号是否存在）；删除某一天的记录时，这一天没有记录 |
| cycle_not_available | 403 | 经期功能只对档案性别为女性、且没有关闭该功能的用户开放 | 性别不是女性、没有填写性别，或已主动关闭经期功能的用户访问任何经期接口 |
| period_in_future | 422 | 经期日期不能晚于今天 | 新增或修改月经时，开始日或结束日晚于今天 |
| invalid_period_range | 422 | 结束日期不能早于开始日期 | 新增或修改月经时，结束日早于开始日 |
| period_too_long | 422 | 单次经期不能超过 15 天，请检查日期；或者：这次经期已超过 15 天还没有填写结束日期，请补全结束日期 | 有结束日时，结束日比开始日晚 15 天或更多（一次经期最长 15 天）；没有结束日时，开始日距今天已超过 14 天，也就是超过 15 天还没结束 |
| period_overlap | 409 | 与已有的经期记录日期重叠；或者：与一次尚未结束的经期重叠，请先填写那次经期的结束日期 | 新增或修改的经期日期范围与自己已有的另一次经期重叠；没有结束日的经期按“持续到今天”计算 |
| log_in_future | 422 | 不能记录未来日期 | 保存每日记录时，日期晚于今天 |

说明：以上错误码都是业务错误，由服务统一转成标准的错误格式；步骤 01 已有的错误码（validation_error、not_authenticated、invalid_token、disclaimer_not_accepted 等）含义不变，本步骤继续沿用。
