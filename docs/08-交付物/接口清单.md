# 接口清单

步骤 08 新增 13 个接口，路径都以 /api/agent 开头，在接口文档页面（服务启动后打开 8000 端口下的 docs 页面）的 agent 分组里可以直接试用。另外，步骤 08 给 SDK 与 MCP 新增了一项只读能力：读取档案详情（SDK 版本升到 1.1，MCP 工具共 27 个），见步骤 06 的交付文档。

通用约定：

- 所有接口都要求已登录并已确认免责声明，只能操作自己的数据。没有登录返回 401（not_authenticated），没有确认免责声明返回 403（disclaimer_not_accepted）。
- 别人的记录与不存在的记录一样返回 404（not_found）。任何接口都不接受客户端传入用户编号。
- 请求正文里出现没有声明的字段，或字段格式不对，返回 422，错误码 validation_error，并带每个字段的明细。
- 错误格式统一为一个 error 对象，含 code 与 message，message 是中文说明。
- 对话内容、偏好、开场问题的文字都加密存储，日志与审计里没有对话正文。
- 智能体调用工具用的是服务端凭证，不是用户的登录令牌，也不接受任何客户端传入的凭证。

## 一、会话

### 1. 新建会话：POST /api/agent/conversations

请求：title（标题，可不填或填 null；填写时 1 至 50 字，两端空白会被去掉）。没有别的字段。

响应 201：会话对象，字段为 id、title、created_at、updated_at。

### 2. 列出会话：GET /api/agent/conversations

返回自己的全部会话，按更新时间从新到旧排列，字段同上。

### 3. 查看会话：GET /api/agent/conversations/{conversation_id}

返回会话对象，外加 messages（消息列表，按先后顺序）。每条消息有 id（消息编号，流式回答结束时的 message_id 就是这条助手消息的 id）、role（user 或 assistant）、text、evidence（依据段，没有时为空字符串）、flags（标记列表）、created_at。

给前端的消息只有用户与助手的可见内容：工具调用、工具结果、模型的内部状态都不会返回；只含工具调用的助手消息、没有文字的助手消息也不返回。别人的会话与不存在的会话返回 404。

### 4. 删除会话：DELETE /api/agent/conversations/{conversation_id}

响应 204，会话里的全部消息一并删除。别人的会话与不存在的会话返回 404。

### 5. 发消息：POST /api/agent/conversations/{conversation_id}/messages

请求：

- text：用户这句话，去掉两端空白后 1 至 2000 字。
- stream：是否流式，布尔值，不填时为真。

处理过程见《智能体行为设计》，检查规则见《输出检查规则说明》。这个接口先确认会话属于本人，再开始处理，处理期间不占用数据库事务。

非流式（stream 为假）的响应 200，是一个对象：

| 字段 | 含义 |
|---|---|
| message_id | 这条助手消息的编号 |
| text | 最终的回答文字：模型的回答（或固定的安全回答）加程序附上的医嘱提醒与健康提示 |
| evidence | 依据段，只来自引擎的依据条目；没有提到食物时为空字符串。依据不放在 text 里 |
| flags | 这一轮发生的标记，见下表 |
| tools_used | 这一轮调用过的工具名，按首次出现的顺序，不重复 |

流式（stream 为真）的响应是 text/event-stream，回答先检查完，再按段推送，事件依次是：

- delta：若干个，每个的 data 是一个对象，text 是约 20 个字的一段。
- done：最后一个，data 是对象，含 message_id、evidence、flags、tools_used（不含 text，因为文字已经通过 delta 发完）。
- error：出错时只有这一个事件，data 含 code 与 message；响应的状态码与对应的错误一致，因此流式出错时状态码也不是 200。

所有 delta 的文字拼起来，就是非流式返回的 text。

flags 的取值：

| 标记 | 含义 |
|---|---|
| guard_rewritten | 输出检查拦截了第一版回答，重写后通过 |
| guard_fallback | 重写后仍不通过（或重写失败），换成了固定的安全回答 |
| resolution_clue | 用户说了医生的新意见（例如“医生说我好了”），智能体只能提出解除建议 |
| tool_limit | 工具调用用满了 6 次模型调用的上限：回答是模型最后一次回复里附带的文字，没有文字时才是整理不全的固定说明 |
| risk_ 加类别名 | 命中风险话题，用了固定的安全回复，类别名为 medication、pregnancy、severe_symptom、extreme_diet、self_harm |

错误：

- 404 not_found：会话不存在或不是自己的。这种情况即使 stream 为真，也是普通的 404 响应。
- 409 agent_model_not_configured：还没有为“日常对话”选择模型，说明里指引到设置页。用户这一句已经保存。
- 422 或 409，错误码沿用步骤 07：所选模型的配置不适合对话，例如 llm_model_lacks_tools（模型被标明不支持工具调用）、llm_model_not_chat（模型被标明不是对话模型）。这类错误按原来的状态码与错误码返回，说明里写着该去设置页怎样改。用户这一句已经保存。
- 502 agent_model_error：调用模型服务失败（密钥错误、额度不足、模型不存在、超时、服务出错等），说明以“模型调用失败”开头，后面是步骤 07 给出的原因与建议。用户这一句已经保存。
- 422 validation_error：text 为空、超过 2000 字，或出现没有声明的字段。

## 二、偏好记忆

### 6. 列出偏好：GET /api/agent/preferences

返回自己的偏好，按添加先后排列。每项有 id、content、source（agent 表示智能体记下的，user 表示用户自己添加的）、created_at。

### 7. 添加偏好：POST /api/agent/preferences

请求：content（偏好，两端空白去掉后 1 至 100 字）。响应 201：偏好对象，source 为 user。内容与已有偏好相同（归一后）时，不新增，返回已有的那一条。

过滤规则：只记口味与习惯；医嘱、用药、过敏、病情、孕期这类健康信息一律拒绝，宁可误拒也不漏放，拒绝后用户可以改写成纯口味说法，例如“我不吃香菜”。规则详见《智能体行为设计》第六节。

错误：

- 422 agent_preference_rejected：内容是医嘱或健康状况信息，说明里引导到医嘱或档案里记录；或者内容里有指令式的说法（例如忽略、规则、指令、英文 ignore、system prompt、【】符号），说明里请用户只写口味或习惯。
- 偏好里连续的空白与换行会被压成一个空格再保存。
- 409 agent_too_many_preferences：已有 50 条，请先删除不再需要的。

### 8. 删除偏好：DELETE /api/agent/preferences/{preference_id}

响应 204。别人的偏好与不存在的偏好返回 404。

## 三、设置

### 9. 查看设置：GET /api/agent/settings

响应：openings_enabled（是否开启主动开场）。新用户默认为真。

### 10. 修改设置：PUT /api/agent/settings

请求：openings_enabled（必填的布尔值）。响应：同上。关闭后取开场一律返回空。

## 四、主动开场

规则与频率限制见《主动开场规则表》。

### 11. 取今天的开场问题：GET /api/agent/opening

响应：opening 是 null，或一个对象，含 id、kind（五类之一：review_due、period_soon、trained_no_meal_yesterday、no_meal_today、profile_stale）与 question（问题文字）。

返回 null 的情形：设置里关闭了主动开场；今天没有该问的；今天五类都问过了。

今天已经有一个还没被拒绝也没被回答的开场时，返回的就是它，不新建、不调用模型；它被拒绝或回答之后，再取才会轮到下一类。取到的开场问题不是一条对话消息，由前端决定怎样展示。

### 12. 拒绝开场：POST /api/agent/opening/{opening_id}/decline

响应 204。今天不再问这一类。别人的开场与不存在的开场返回 404；已经处理过的开场再次处理不改变它的状态，仍返回 204。

### 13. 回答开场：POST /api/agent/opening/{opening_id}/answer

响应 204。表示用户去处理了这个问题；同样算今天问过这一类。其余规则同上。

## 五、本步骤的错误码

| 错误码 | 状态码 | 含义 |
|---|---|---|
| agent_model_not_configured | 409 | 还没有为“日常对话”选择模型 |
| agent_model_error | 502 | 调用模型服务失败，说明里是具体原因；模型配置类的错误（如 llm_model_lacks_tools）不转成它，按步骤 07 原来的状态码与错误码返回 |
| agent_preference_rejected | 422 | 偏好是医嘱或健康状况信息，或含有指令式的说法，被拒绝 |
| agent_too_many_preferences | 409 | 偏好已达 50 条的上限 |

另外会遇到通用的 not_authenticated、disclaimer_not_accepted、not_found 与 validation_error，含义见上文通用约定。

## 六、智能体调用工具时的约定

这部分不是接口，但与接口行为有关：

- 智能体在对话中调用工具时，工具的失败结果（比如参数不合法、数据不足、记录不存在）都以结构化的形式交回模型，由模型向用户解释；不会让整轮对话失败。
- 一个工具结果超过 8 KB 时，交给模型并保存下来的是一个摘要：标明已截断，并附上前 2000 个字。
- 模型要求调用本轮没有提供的工具（例如需本人确认的医嘱动作、没有开放的经期工具）时，得到“没有这个工具”的失败结果，什么也不会执行。
- 智能体的每次读取与工具调用，审计里凭证类型是 agent、客户端名称是 agent；用户在自己的调用审计里能看到它们，见步骤 06 的《调用审计说明》。
