# 步骤 06 接入使用说明

本文让你不经过任何自家前端，只用一个通用的、支持 MCP 的客户端，就能连上 good-life 的 MCP 服务，并完成记录经期、查询预测、录入医嘱、记录一餐、评估食物、记录训练这六件事。文中以官方的 MCP Inspector 和 Claude Desktop 为例；客户端的界面会随版本变化，具体的菜单位置以它们各自的最新官方说明为准，本文只写需要填写的内容。

MCP 服务是后端项目里的一个本地程序，由客户端按你的配置在本机启动，通过标准输入输出与客户端通信，不监听任何网络端口。它读取你的授权令牌，代表签发这个令牌的用户操作你本机上的数据库。工具有哪些、各自怎么用，见《MCP工具清单》；授权与安全的设计，见《权限与授权设计说明》。

## 一、准备工作

1. 数据库已启动，并且已经建到最新版本，后端依赖已经安装，后端目录里已经有配置好的环境配置文件。这些步骤与前几个步骤一样，具体操作见仓库根目录 README 的第 1 至 5 节。
2. 后端服务已启动，能在浏览器里打开 8000 端口下的 docs 页面（接口文档页面）。创建授权要用到它，MCP 服务本身运行时并不需要后端服务在运行，但需要数据库在运行。
3. 一个已注册、已登录、已确认免责声明的账号，操作见 README 第 8 节。要演示经期，档案里的性别要设成女性；要看到饮食需求的估算，档案里要填好出生年份、身高、体重、活动水平；档案没填全时，相关结果会附“数据不足”的提示，这是正常的。
4. 本机装有 uv。用 MCP Inspector 还需要装有 Node.js，因为它用 Node 自带的 npx 运行；只用 Claude Desktop 则不需要。

## 二、在接口文档页面创建授权

1. 在接口文档页面（http://localhost:8000/docs）用登录接口登录，点页面右上角的 Authorize，把登录令牌填进去，操作同 README 第 8 节。
2. 找到“agent-grants”分组里的创建授权接口（路径是 /api/agent-grants，方法 POST），点 Try it out。
3. 填三项：name 写一个能认出客户端的名字，例如 MCP Inspector；access 选 read（只读）或 read_write（读写）；expires_in_days 填有效天数（1 到 365，不填默认 90）。要走完本文的六个场景，需要选读写；只想看数据，选只读。
4. 点 Execute。响应里有一个以 gl_ 开头的 token 字段，这就是授权令牌。它只在这一次响应里显示，请立即复制保存；遗失了只能吊销后重新创建。
5. 同一个分组里还有：列出授权（看状态与最近使用时间）、吊销授权、查看调用审计（见《调用审计说明》）。授权令牌不能用来调用这些接口，它们只认你的登录令牌。

不要把令牌贴到聊天里或提交进仓库；令牌等同于你交给这个客户端的一把钥匙。

## 三、启动 MCP 服务需要什么

服务是一个 Python 模块，名字是 app.mcp_server。它必须在后端目录里，用 uv 来运行：让 uv 在后端项目的环境里运行 Python，并以模块方式启动 app.mcp_server。通常你不需要手工启动它，由客户端启动；手工启动时它会安静地等待客户端通过标准输入发来消息，看不到任何输出是正常的。

它读取的环境变量：

| 环境变量 | 是否必填 | 含义 |
|---|---|---|
| GOODLIFE_AGENT_TOKEN | 填了才能用 | 你在第二节得到的授权令牌 |
| GOODLIFE_CLIENT_NAME | 可不填 | 客户端的名字，会写进每一行审计，最多 64 个字符，不填则记为 mcp |

数据库地址与两个密钥（数据库地址、登录密钥、字段加密密钥）默认从后端目录里的环境配置文件读取，和后端服务用的是同一份，所以无需重复填写。如果客户端运行时找不到这份文件，也可以直接在客户端配置的环境变量里填同名的三项配置；字段加密密钥必须与后端服务用的相同，否则读取加密内容会失败。数据库必须在运行。

几个行为请心里有数：

- 令牌只在服务启动时读取一次，所以更换令牌要重启服务（在客户端里重新连接）。
- 但每一次工具调用都会重新核对令牌是否有效，所以你在接口文档页面吊销授权后，下一次调用马上被拒绝，不必重启。
- 没有设置令牌时服务照样启动，只是每一次调用都返回“未认证”类的错误，错误码为 missing_credential。

## 四、在 MCP Inspector 里接入

MCP Inspector 是 MCP 官方提供的调试工具，在浏览器里列出服务的工具并手动调用，最适合验收。

1. 用 Node 的 npx 运行官方的 MCP Inspector 包（包名在 modelcontextprotocol 名下，叫 inspector）。它会在本机启动一个页面并给出地址，在浏览器打开；如果页面要求填写代理会话令牌，按终端里的提示填写。
2. 在连接区域，传输方式（Transport Type）选 STDIO。
3. 命令（Command）填 uv 可执行文件的位置。填完整路径最稳妥；在 PowerShell 里查询 uv 命令的位置就能得到。
4. 参数（Arguments）填四项，按顺序：run、python、-m、app.mcp_server，以空格分隔。
5. 工作目录：填后端目录（仓库里的 backend 文件夹）的完整路径。如果你用的 Inspector 版本里没有工作目录一栏，就改在参数最前面再加两项：--directory，以及后端目录的完整路径，也就是整个参数变成：--directory、后端目录、run、python、-m、app.mcp_server。
6. 环境变量（Environment Variables）：添加 GOODLIFE_AGENT_TOKEN，值填令牌；可以再添加 GOODLIFE_CLIENT_NAME，值填 MCP Inspector。
7. 点 Connect。连接成功后进入 Tools 页签，点 List Tools，应当看到 26 个工具；逐个点开，能看到每个工具的说明（用途、授权级别、什么时候用、什么时候不要用）与输入字段。选中一个工具，填入字段，点 Run Tool，右侧会显示结果。结果同时有文字和结构化两种形式，内容相同。

## 五、在 Claude Desktop 里接入

1. 在 Claude Desktop 的设置里找到开发者（Developer）一栏，点编辑配置，会打开 Claude Desktop 的配置文件 claude_desktop_config.json。
2. 在配置文件的服务器列表（mcpServers）里添加一项，名字可以叫 good-life，需要填三样：命令、参数、环境变量。这个配置没有稳定的工作目录选项，所以统一用 uv 的目录选项来指定后端目录：
   - 命令：uv 可执行文件的完整路径。
   - 参数，按顺序：--directory、后端目录的完整路径、run、python、-m、app.mcp_server。
   - 环境变量：GOODLIFE_AGENT_TOKEN（令牌）与可选的 GOODLIFE_CLIENT_NAME（填 Claude Desktop）。
3. 配置文件是 JSON 格式，写路径时反斜杠要写成两个，或者直接用正斜杠，例如盘符后面用正斜杠。保存文件。
4. 完全退出 Claude Desktop 再重新打开（只关窗口不够，要退出托盘里的程序）。在对话输入框的工具列表里应当出现 good-life，里面有 26 个工具。
5. 之后直接用自然语言向 Claude 提要求，它会选择工具并向你请求使用工具的许可。写入类工具要读写授权。

其他支持 MCP 的客户端同理：只要它能以子进程方式启动一个标准输入输出的 MCP 服务，填上同样的命令、参数、工作目录（或目录选项）与环境变量即可。

## 六、六个场景走一遍

下面的做法用 Inspector 逐个调用工具，用 Claude Desktop 就把每一步换成自然语言。日期都写成“年-月-日”。示例里的数字只是示意。

### 1. 记录经期

用到的工具：cycle_list_periods、cycle_record_period。需要读写授权，账号档案性别为女性。

先调用 cycle_list_periods 看有没有记过。再调用 cycle_record_period，开始日期填例如 2026-09-10，结束日期填 2026-09-14（还没结束可以不填）。返回新记录，里面有编号。如果与已有的经期重叠，会返回“冲突”类错误，错误码 period_overlap。

### 2. 查询预测

用到的工具：cycle_get_prediction，也可以配合 cycle_get_stats、cycle_get_phase。只读授权就够。

调用 cycle_get_prediction，不需要输入。记录得越多越准；只有一两次记录时，会返回“数据不足”：结果照常返回，同时在提示里说明经期记录还不够，这是正常的，不是失败。预测仅供参考，不能用于避孕或诊断。

### 3. 录入医嘱，待用户确认

用到的工具：medical_submit_order、medical_get_constraints、medical_list_items、medical_propose_resolution。提交需要读写授权。

调用 medical_submit_order，原文填例如“一周内忌食辛辣，禁酒。”，开具日期可不填。返回的条目全部是“待确认”状态，返回里有条目编号。此时调用 medical_get_constraints，结果里没有这条：未确认的条目不是生效的约束。

接着回到接口文档页面，用登录令牌调用医嘱条目的确认接口（路径是 /api/medical/items/{条目编号}/confirm），状态变为生效中；再调用 medical_get_constraints，就能读到它。再调用 medical_propose_resolution，填条目编号和理由，例如“医生说可以恢复”，返回的条目带有解除建议，状态仍然是生效中，约束照常生效。在 Inspector 的工具列表里，你找不到任何确认、修改、解除、作废医嘱的工具，这是刻意的设计。

### 4. 记录一餐

用到的工具：nutrition_search_foods、nutrition_log_meal，之后可以用 nutrition_get_daily_summary 核对。记录需要读写授权。

先调用 nutrition_search_foods，搜索词填 米饭，从结果里记下食物编号。如果结果提示只有名称相近的候选，请确认是哪一种。再调用 nutrition_log_meal：日期填今天，餐次填 lunch（午餐；其他是 breakfast、dinner、snack），食物编号填刚才记下的，克数填 150；克数与份量只能填其中一项。最后调用 nutrition_get_daily_summary，应当能看到这一餐与全天的合计。档案没填全时，会提示数据不足，无法估算每日需求。

### 5. 评估食物

用到的工具：nutrition_search_foods、nutrition_evaluate_food；评估前模型应当先读 medical_get_constraints。只读授权就够。

拿到食物编号后，调用 nutrition_evaluate_food，填食物编号，克数可不填（按默认份量）。返回结论（适合、谨慎、不建议三种之一）和逐条依据，依据会标明来源：医嘱、经期、目标、训练、摄入。例如先按场景 3 确认一条“忌辛辣”的医嘱，再评估麻婆豆腐，应当得到“不建议”，并指出是哪条医嘱。

### 6. 记录训练

用到的工具：fitness_search_exercises、fitness_log_workout，之后可以用 fitness_get_week_summary 核对。记录需要读写授权。

先调用 fitness_search_exercises，搜索词填 卧推，记下动作编号。再调用 fitness_log_workout：日期填今天，主观强度填 7，力量动作里放一个动作，填刚才的动作编号，组里依次填三组：60 千克 10 次、60 千克 8 次、65 千克 6 次。返回新记录，里面有与运动限制医嘱的冲突提示（没有相关医嘱时为空）。然后调用 fitness_get_week_summary，开始日期不填，总训练量应当是 600 加 480 加 390 等于 1470。

## 七、验收时顺手核对的三件事

1. 没有确认或解除医嘱的工具：Inspector 的工具列表里只有 26 个工具，没有任何确认、修改、解除、作废医嘱的工具，医嘱方面只能提交、读取和提出解除建议。
2. 只读授权不能写：再创建一个只读授权，用它连接，调用 cycle_record_period 或 nutrition_log_meal，应当得到“禁止”类的错误，错误码 write_not_granted。
3. 看审计：回到接口文档页面，调用查看调用审计的接口，每一次调用，包括刚才被拒绝的，都有一行，其中没有医嘱原文、备注或令牌，详见《调用审计说明》。

## 八、常见错误与处理

| 现象或错误码 | 类别 | 原因 | 处理 |
|---|---|---|---|
| 客户端提示服务启动失败或连接断开 | 无 | 命令路径不对、后端目录不对、没装依赖、数据库没启动、环境配置文件缺失或不合法 | 先在后端目录手工运行服务看终端的报错；确认 uv 路径、目录、数据库、环境配置文件；服务的日志写在标准错误里，客户端的日志里能看到 |
| missing_credential | 未认证 | 没有设置 GOODLIFE_AGENT_TOKEN，或为空 | 在客户端配置里填入令牌，重新连接 |
| invalid_grant | 未认证 | 令牌写错、授权已过期或已吊销 | 在接口文档页面查看授权状态，必要时重新创建，并更新客户端配置 |
| write_not_granted | 禁止 | 用只读授权调用了写入类工具 | 另建读写授权 |
| unknown_capability | 参数不合法 | 工具名不存在（工具名里是下划线，不是点；也没有确认或解除医嘱的工具） | 只用工具列表里的工具 |
| validation_error | 参数不合法 | 字段缺失、类型不对，或多填了字段（包括任何用户编号） | 看返回里的明细，按字段说明修正 |
| disclaimer_not_accepted | 需要用户本人确认 | 账号还没有确认当前版本的免责声明（免责声明升级后也需要重新确认） | 在接口文档页面登录后确认免责声明 |
| cycle_not_available | 模块未开放 | 账号档案的性别不是女性，或经期功能被关闭 | 先调用 profile_get_capabilities 看哪些模块开放，必要时修改档案 |
| not_found | 未找到 | 编号写错，或那条记录不是这个用户的 | 先用列表或搜索类工具确认编号 |
| 修改过令牌却仍然用旧令牌 | 无 | 令牌只在服务启动时读取 | 在客户端里重新连接，让服务重启 |

每个错误结果里都有一条给智能体的建议，智能体应当据此如实告诉用户，而不是编造结果。
