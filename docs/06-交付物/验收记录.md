## 需要你确认的设计决定

下面这些规则是实现时定下的，步骤文档没有写死具体做法，或实际行为与实施计划有出入。你若不认同任何一项，告诉我改成什么即可。

1. 授权令牌的形式与有效期：以 gl_ 开头加随机串，数据库只存 SHA-256 哈希，明文只在创建时返回一次；权限只有只读与读写两种；有效期 1 至 365 天，默认 90 天；同时有效的授权最多 20 个；吊销是软删除，立即生效。
2. 进程内 SDK、本地 stdio 的 MCP：SDK 直接连数据库，步骤 08 的智能体在后端内部使用；MCP 只做本地标准输入输出，不做远程访问。令牌由环境变量提供，服务启动时读取一次，但每次工具调用都重新认证，所以吊销立即生效，更换令牌则需要重启服务。
3. 医嘱确认与解除不暴露给模型：SDK 里有六项“需用户本人确认”的能力（确认、修改、解除、作废、继续生效、撤回解除建议），只认用户登录令牌；MCP 不注册；模型只能提出解除建议。
4. 提出解除建议时事件来源按凭证记录（本任务的行为，实施计划里没有）：用授权令牌记为“智能体”，用用户登录令牌记为“用户”。为此该能力没有走医嘱接口函数（接口把来源固定为用户），而是直接调用医嘱模块的同一个业务函数。
5. 名字对不上的工具一律是能力不存在（本任务的行为）：MCP 收到不在工具列表里的名字（包括需本人确认的 6 个动作的下划线写法与带点写法）时，把名字里的点换成下划线再交给 SDK，一定得到 unknown_capability，并记入审计，所以任何名字都到不了需本人确认的能力。
6. 输出不符合声明的类型算内部出错：SDK 把能力的输出按声明的类型校验，不符合时返回 internal_error，而不是参数错误；错误信息不带输出内容。同样，只有输入参数的校验失败才算参数不合法，处理过程中出现的校验错误算内部出错。
7. 经期阶段在一条经期记录都没有时也附数据不足提示（本任务的行为）：与预测不足时不同的是，提示明确写“还没有经期记录”。
8. 读取类能力保留与对应 REST 接口相同的副作用：医嘱模块的准入检查与读取医嘱约束的能力会先刷新医嘱条目状态（到期转待复核、过期作废）；查看模块开放情况在没有档案时会创建一份空档案。SDK 没有额外屏蔽。
9. 数据不足不算错误：成功结果附 insufficient_data 类的提示，包括经期预测与阶段、饮食汇总档案不全、训练消耗缺体重。
10. 审计只记概况：记能力名、结果、错误码、客户端名称、凭证类型、授权编号、耗时与时间；不记参数、返回内容、令牌与错误文字；审计表没有存放这些内容的字段；被拒绝的调用也记；用独立会话写入；凭证认证失败的调用没有用户归属，用户在审计接口里看不到。
11. 向后兼容的规则是人工遵守的约定：新增能力、可选输入、输出字段为兼容变更，提高小版本号；删除或改名能力、改变含义、新增必填输入、调整授权级别为不兼容变更，提高大版本号。自动化测试只对比快照、发现变化，不判断变化是否兼容。当前版本号是 1.0。
12. MCP 工具的使用说明由自己撰写：每个工具有“什么时候用、什么时候不要用”，为降低模型误用；写入类工具说明里要求先搜索取得编号、分量含糊时先问清楚。

## 已知问题与后续

- 同时有效的授权最多 20 个的限制没有做串行化处理，并发创建时可能略微超出，不影响安全。
- 审计里，通过 MCP 调用时对不上任何工具的名字，记录的是把点换成下划线之后的名字，不是调用方原样给出的名字。
- 凭证认证失败的调用在审计表里有记录，但没有用户归属，用户自己查不到。
- 审计没有自动清理与保留期限设置。
- 授权不会因为用户登出而被吊销：登出只让登录令牌失效，不用的授权需要用户自己吊销。
- 写入类能力返回 internal_error 时数据可能已经保存（写入成功后输出序列化出错），所以写入出错后不要盲目重试，先用对应的列表类能力核对。
- 令牌保存在客户端的配置里，谁能读取这份配置，谁就能使用授权；建议每个客户端单独创建授权、优先只读、设置较短有效期、不用时吊销。
- 步骤 08 的智能体必须使用授权令牌而不是用户登录令牌，这是设计约定，SDK 本身不阻止传入登录令牌，需要在步骤 08 守住。
- 面向外部开发者的开放平台、远程访问方式、更多客户端接入方式，按步骤文档的约定不在本步骤做。
- 本步骤文档里的 MCP Inspector 与 Claude Desktop 的界面操作按公开文档的通用写法描述，客户端更新后菜单位置可能不同，以各自的官方说明为准。
