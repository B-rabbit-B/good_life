# 评测记录

对应验收第 8 条：用至少二十张自选照片做评测，记录识别正确率与常见错误类型，并据此确定“哪些情况需要提醒用户修正”。

评测要用真实的看图模型与你自己拍的真实照片，自动化测试做不了，所以由你本人在本机运行照片评测脚本。脚本已经用模拟模型与程序生成的图片验证过统计逻辑，但还没有用真实模型与真实照片运行过；在你运行之前，本条不能视为通过，下面的“评测结果”一节也是空的。

## 一、评测方法

准备：

1. 密钥：与步骤 07 的实测脚本用同一份本机密钥文件（backend 目录下的 llm_keys.local.env，做法见 README 的“多模型接入”一节）。至少要有一家服务同时填了密钥与看图模型名（形如 QWEN_VISION_MODEL）；脚本按服务的顺序用第一家填了看图模型名的服务。
2. 照片：在 backend 目录下新建 photo_eval 目录，放入至少二十张自选的照片（JPEG、PNG 或 WebP；HEIC 请先转成 JPEG）。建议覆盖：单个菜与多个菜、米饭面条等主食、汤、水果、外卖盒、光线较暗的、拍得较远的，再加几张不是食物的照片（例如桌面、书本）用来检验“不是食物”的提示。
3. 标注：把 backend 目录下的标注模板 photo_eval.labels.example.csv 复制到 photo_eval 目录，改名为 labels.csv，每张照片写一行：文件名、真实菜品（多个用顿号分隔）、真实克数（可不填；填写时与菜品一一对应，用顿号分隔，有厨房秤时最好称一下）、是否食物（是或否）。用表格软件编辑时请另存为“CSV UTF-8”格式。

运行：在 backend 目录运行照片评测脚本（具体运行方式见仓库根目录 README 的“拍照识别”一节）。每张照片走与正式流程相同的步骤：同样的图片处理、同样的提示词与格式重试、同样的解析、同样的营养库匹配与份量换算；不连数据库，不保存任何识别记录，不写饮食记录。每次调用最多等 60 秒。结果写入 backend 目录下的 photo_eval_result.md，并打印在屏幕上；中途按 Ctrl+C 中断时，已完成的照片也会写进去。

隐私：photo_eval 目录与 photo_eval_result.md 都已在 backend/.gitignore 中忽略，不会提交。结果文件里只有菜名与克数，没有图片内容，输出前去掉了全部密钥；照片本身只发给你选的看图模型服务。

## 二、指标定义

每张照片的识别状态是下列之一：识别出菜品、判为不是食物、判为看不清、两次格式都不对、未评测（找不到图片文件，或图片本身格式不对、太大、损坏）、调用出错（模型服务报错）。未评测与调用出错的照片不计入统计，在逐张结果里写明原因。标注有误的行（例如是否食物写了别的字、克数个数与菜品对不上）不评测，单独列出。

命中：识别项与某道真实菜品是营养库里的同一个食物，或者识别出的菜名（或匹配到的营养库食物名）与真实菜品同名。例如真实菜品写“西红柿炒鸡蛋”、识别为“番茄炒蛋”，两者在营养库里是同一个食物，算命中。按真实菜品的顺序，为每道菜找第一个还没配上的识别项。

下面的指标只算食物照片（非食物照片单独统计）：

| 指标 | 定义 |
|---|---|
| 菜品级召回率 | 命中的数量除以真实菜品的总数 |
| 菜品级精确率 | 命中的数量除以识别出的菜品总数 |
| 漏识 | 真实有、没有识别出来的菜品；整张被判为不是食物、看不清或两次格式都不对时，这张的真实菜品全部算漏识 |
| 多识 | 识别出来、但图里没有的菜品 |
| 认错 | 识别出了一道菜、但认成了别的菜：同一张照片里没命中的真实菜品与没命中的识别项两两相抵的数量（相抵后剩下的分别算漏识与多识） |
| 匹配不上 | 识别出的菜名在营养库里找不到对应的食物，被标为待确认 |
| 克数偏差超过 50% | 命中、且标注里填了真实克数的菜品中，换算出的克数与真实克数之差超过真实克数一半的数量 |
| 把握程度低但其实正确 | 把握程度低于当前提醒阈值 0.6、但命中了 |
| 把握程度高但其实错误 | 把握程度不低于 0.6、但没有命中 |

非食物照片：统计判为不是食物（正确）、判为看不清（同样会拒绝并提示重拍）、误判为食物的张数。另统计用了格式重试的张数与两次格式都不对的张数。

按把握程度分段的正确率：把食物照片里识别出的菜品按把握程度分成 0.0 至 0.4、0.4 至 0.6、0.6 至 0.8、0.8 至 1.0 四段（含下限、不含上限，最高一段包含 1.0），每段统计菜品数、命中数与正确率。

提醒阈值的建议：从把握程度最高的一段往下看（没有样本的段跳过），只要这一段的正确率不低于 80% 就继续往下，建议阈值取最后一个达标段的下限，低于它的菜品提醒修正。最高一段都不达标时，建议对所有菜品都提醒，或换一个看图模型再评；每一段都达标时，可以保留当前阈值或适当调低。结果里还会给出：识别错的菜品里有多少会被现有的四条提醒规则（把握程度低、待确认、克数超出范围、克数只来自估算）提醒到，识别对的菜品里有多少也被提醒了。分段样本很少时（例如一段不到 5 个）结论仅供参考。

## 四、提醒修正的规则

当前规则（默认值，见《识别结果数据结构说明》第五节）：把握程度低于 0.6、待确认、克数小于 10 克或大于 1500 克、克数只来自估算，任一条成立即提醒修正。
