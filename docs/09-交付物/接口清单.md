# 接口清单

步骤 09 新增 8 个接口，路径都以 /api/photos 开头，在接口文档页面（服务启动后打开 8000 端口下的 docs 页面）的 photos 分组里可以直接试用。拍照识别只做应用接口，不进智能体聊天，也不进 SDK 与 MCP。

通用约定：

- 所有接口都要求已登录、已确认免责声明，并且饮食模块对这个用户开放（与步骤 04 的饮食接口相同）。没有登录返回 401（not_authenticated，令牌失效时为 invalid_token），没有确认免责声明返回 403（disclaimer_not_accepted），饮食模块不可用返回 403（nutrition_not_available）。
- 只能操作自己的识别记录：别人的记录与不存在的记录一样返回 404（not_found）。任何接口都不接受客户端传入用户编号。
- 请求正文里出现没有声明的字段，或字段格式不对，返回 422，错误码 validation_error，并带每个字段的明细。
- 错误格式统一为一个 error 对象，含 code 与 message；message 是中文说明，并给出下一步建议（例如重拍、改格式、去修正）。
- 识别记录的字段见《识别结果数据结构说明》，处理过程见《识别流程说明》。
- 日志与审计里不出现图片内容、菜品文字或密钥。

## 1. 上传识别：POST /api/photos/recognitions

请求格式是 multipart/form-data：

- file：图片文件，必填。只收 JPEG、PNG、WebP（按文件头判断），不超过 8 MB，像素总数不超过 4000 万。
- keep_image：是否保留图片，布尔值，可不填，默认不保留。填了不是布尔值的内容返回 422（validation_error）。

处理过程：校验并处理图片（转正、去掉全部元数据、长边缩到 1280 像素、重新编码为 JPEG）→ 检查看图模型 → 调用模型识别（格式不对重试一次）→ 匹配营养库、换算克数、计算营养 → 保存为草稿。接口先结束自己的读事务再识别，调用模型期间不占用数据库事务。

响应 201：识别记录（草稿），带识别项、合计、是否建议修正、说明，以及引擎的评价。

错误：

| 状态码 | 错误码 | 何时出现 |
|---|---|---|
| 413 | photo_too_large | 图片超过 8 MB（请求体过大时在进入接口之前就返回） |
| 415 | photo_type_not_allowed | HEIC（提示改成 JPEG 再上传）或 GIF |
| 422 | photo_empty | 没有收到图片内容 |
| 422 | photo_unreadable | 认不出格式、文件损坏或打不开 |
| 422 | photo_too_many_pixels | 像素总数超过 4000 万 |
| 409 | llm_not_configured | 还没有为“看图识别”选择模型；不发起调用 |
| 422 | llm_model_lacks_vision | 选定的模型不能看图（或无法确认）；不发起调用 |
| 422 | llm_model_not_chat | 选定的模型被标明不是对话模型；不发起调用 |
| 502 | photo_recognition_failed | 模型两次都没有按要求给出识别结果；不保存记录 |
| 422 | photo_not_food | 模型判断不是食物；提示对准饭菜重拍，不保存记录 |
| 422 | photo_unclear | 模型判断看不清，或一个菜品也没有；提示在光线充足处重拍，不保存记录 |
| 按步骤 07 | llm_ 开头的调用错误 | 模型服务本身出错，例如 llm_invalid_key、llm_quota_exceeded、llm_rate_limited、llm_timeout、llm_model_unavailable、llm_bad_url、llm_provider_error，状态码与说明同步骤 07 的统一调用 |

## 2. 识别历史：GET /api/photos/recognitions

返回自己的识别记录，新的在前，最多 50 条。每条的字段与识别记录相同，但没有 evaluation 字段（不评价）；图片不会读出。

## 3. 查看一条：GET /api/photos/recognitions/{rec_id}

返回这条识别记录。识别项会按当前营养库核对一遍（食物已不在营养库里的改为待确认），合计重新计算；草稿带引擎的评价，已确认与已放弃的 evaluation 为空。

## 4. 修正：PUT /api/photos/recognitions/{rec_id}/items

请求：items，修正后的整组菜品，最多 12 个，可以是空列表。整组替换：带 id 的是修改原有的项，不带 id 的是新增，原有的项没有出现在列表里即删除。每一项：

- id：原有识别项的编号，1 至 64 个字符；新增的项不填。
- name：菜名，必填，去掉两端空白后 1 至 30 个字。
- portion_text：份量说法，可不填，最多 30 个字；修改原有的项时不填表示不变。
- grams：克数，可不填，填写时 1 至 3000（含两端）；不填时按《识别流程说明》第 13 节的规则沿用或重新换算。
- food_id：从候选里选的营养库食物编号，1 至 64 个字符，可不填；不填时按菜名检索。要保留之前选过的食物，需要再带上它。

响应 200：修正后的识别记录，营养、合计、提醒原因与评价全部重新计算。改过的项把握程度记为 1。

错误：

| 状态码 | 错误码 | 何时出现 |
|---|---|---|
| 409 | photo_not_editable | 记录已确认或已放弃 |
| 422 | photo_unknown_item | 有不存在或重复的识别项编号，请刷新后再改 |
| 422 | photo_unknown_food | 营养库里没有这个食物编号 |
| 422 | photo_too_many_items | 超过 12 个菜品（请求格式检查通常先以 validation_error 拒绝，这是服务里的第二道检查） |
| 422 | validation_error | 菜名为空或过长、克数超出 1 至 3000、带了没有声明的字段等 |

## 5. 确认入库：POST /api/photos/recognitions/{rec_id}/confirm

请求：

- eaten_on：吃的日期，不能晚于今天。
- meal_type：餐次，breakfast、lunch、dinner、snack 之一。

每个已匹配的菜品写一条饮食记录（备注“拍照识别”），与识别记录的状态变化在同一个事务里提交，任何一条失败都一条不写。只能确认一次。

响应 200：已确认的识别记录，带 eaten_on、meal_type、meal_entry_ids；evaluation 为空。

错误：

| 状态码 | 错误码 | 何时出现 |
|---|---|---|
| 409 | photo_not_editable | 记录已确认或已放弃 |
| 422 | photo_empty_meal | 一个菜品也没有 |
| 422 | photo_items_need_confirmation | 还有待确认的菜品 |
| 422 | photo_grams_out_of_range | 有菜品的克数超过饮食记录的上限 5000 克，请先修正这道菜 |
| 422 | meal_in_future | 吃的日期晚于今天（沿用步骤 04 饮食记录的错误码） |

## 6. 放弃：POST /api/photos/recognitions/{rec_id}/discard

没有请求正文。把草稿改为已放弃，不写饮食记录。响应 200：已放弃的识别记录。已确认或已放弃的返回 409（photo_not_editable）。

## 7. 删除：DELETE /api/photos/recognitions/{rec_id}

响应 204。连同保留的图片删除整条识别记录；已经写入的饮食记录不受影响。任何状态的记录都可以删除。

## 8. 取保留的图片：GET /api/photos/recognitions/{rec_id}/image

响应 200：图片本身，类型 image/jpeg，是处理后的 JPEG（不含任何元数据），带不缓存（Cache-Control 为 no-store）与禁止猜测类型（nosniff）的响应头。上传时没有选择保留图片的返回 404（photo_image_not_kept），提示需要保留时在上传时选择“保留图片”。

## 错误码汇总

本模块自己的错误码（都以 photo_ 开头）：photo_empty、photo_too_large、photo_type_not_allowed、photo_unreadable、photo_too_many_pixels、photo_recognition_failed、photo_not_food、photo_unclear、photo_unknown_food、photo_unknown_item、photo_too_many_items、photo_not_editable、photo_empty_meal、photo_items_need_confirmation、photo_grams_out_of_range、photo_image_not_kept。

沿用别的模块的错误码：not_authenticated、invalid_token、disclaimer_not_accepted、nutrition_not_available、not_found、validation_error、meal_in_future，以及步骤 07 的 llm_not_configured、llm_model_lacks_vision、llm_model_not_chat 与模型调用错误。
