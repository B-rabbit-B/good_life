# 识别结果数据结构说明

本文说明一次拍照识别返回给前端的数据（识别记录、识别项、合计、评价）与数据库里保存的识别记录表，重点是把握程度、待确认标记与“建议修正”的原因。字段名与接口里的完全一致。

## 一、识别记录

一次拍照识别就是一条识别记录。接口返回的识别记录字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| id | 编号 | 识别记录编号 |
| status | 文字 | 记录状态：draft（草稿，可以修正）、confirmed（已确认，已写入饮食记录）、discarded（已放弃） |
| items | 列表 | 识别项，见第二节 |
| totals | 对象 | 整餐合计，只算已匹配的识别项，见第三节 |
| needs_review | 布尔 | 是否建议修正：任何一个识别项有提醒原因即为真 |
| disclaimer | 文字 | 固定的说明：菜品与份量由模型估算，热量与营养由营养库按份量计算，仅供参考；请核对后再确认入库 |
| image_kept | 布尔 | 是否保留了图片（上传时选择，默认不保留） |
| model_id | 文字 | 这次识别所用的看图模型编号 |
| eaten_on | 日期或空 | 吃的日期，确认后才有 |
| meal_type | 文字或空 | 餐次（breakfast、lunch、dinner、snack），确认后才有 |
| meal_entry_ids | 列表或空 | 确认时写入的饮食记录编号，确认后才有 |
| created_at | 时间 | 创建时间 |
| updated_at | 时间 | 最后修改时间 |
| evaluation | 对象或空 | 引擎对这一餐的评价，见第四节；只有草稿才有，列出识别历史时没有这个字段 |

状态流转：上传识别成功后是草稿；草稿可以反复修正；草稿确认后变为已确认，放弃后变为已放弃；已确认与已放弃的记录不能再修正、确认或放弃（409，photo_not_editable），但可以查看与删除。不是食物、看不清、格式两次都不对的照片不会产生识别记录。

## 二、识别项

| 字段 | 类型 | 含义 |
|---|---|---|
| id | 文字 | 识别项编号，修正时用它指明修改哪一项 |
| name | 文字 | 菜名：模型识别的，或用户修正后的（最长 30 个字） |
| portion_text | 文字 | 份量说法，例如一碗、半盘（最长 30 个字，可以为空） |
| grams | 数字 | 克数（整克，用户填写的可以带小数） |
| grams_source | 文字 | 克数来源，见下表 |
| confidence | 数字 | 把握程度，0 到 1；模型没给时按 0.5；用户修正过的项记为 1 |
| status | 文字 | matched（已匹配营养库）或 needs_confirmation（待确认） |
| food_id | 文字或空 | 匹配到的营养库食物编号；待确认时为空 |
| food_name | 文字或空 | 匹配到的营养库食物名称；待确认时为空 |
| match_type | 文字或空 | 匹配方式：exact_name（名称相同）、common_name（常用名）、exact_alias（别名）、user_selected（用户从候选里选的）；待确认时为空 |
| candidates | 列表 | 按菜名检索营养库得到的前几个食物，最多 5 个，每个有 food_id 与 name：待确认时供用户挑选（可能为空列表），已匹配时第一个就是匹配到的食物；用户从候选里选过食物的项为空列表 |
| nutrients | 对象或空 | 营养：energy_kcal（千卡）、protein_g、fat_g、carbohydrate_g、fiber_g（克）、sodium_mg、iron_mg、calcium_mg（毫克），各保留一位小数，营养库里没有的项为空；待确认时整个为空 |
| source | 对象或空 | 数据出处：dataset（数据集名称）、license_status（许可状态）、note（说明）；待确认时为空 |
| review_reasons | 列表 | 建议修正的原因，见第五节；为空表示不需要提醒 |

克数来源 grams_source 的取值：

| 取值 | 含义 | 是否算估算 |
|---|---|---|
| food_portion | 按这个食物自带的份量换算 | 否 |
| unit_table | 按通用换算表换算 | 否 |
| model_estimate | 份量说法认不出，用模型估计的克数 | 是 |
| group_default | 什么都没有，用类别默认份量 | 是 |
| user | 用户修正时自己填的 | 否 |

换算规则见《份量换算表说明》。

## 三、待确认标记

匹配不上营养库的识别项 status 为 needs_confirmation，即“待确认”：

- 没有任何营养数字（nutrients 为空），也没有出处（source 为空），不计入合计，不参与评价；系统不会用相近的食物代替，也不会采用模型给的数字。
- candidates 里给出最多 5 个候选，用户可以从中选一个（修正时带上它的 food_id），也可以改成营养库里有的名称，或删除这一项。
- review_reasons 里一定有 needs_confirmation。
- 还有待确认的项时不能确认入库（422，photo_items_need_confirmation）。
- 已匹配的食物后来不在营养库里了（营养库更新过），返回时也会改成待确认，按菜名重新给候选。

## 四、合计与评价

totals 是整餐合计，字段与识别项的 nutrients 相同。只算已匹配的项：按每项的食物与克数重新计算、不取整地相加，最后只取整一次。全是待确认的项时各项为 0。

evaluation 只在草稿上出现，一个识别项都没有时为空；只有待确认的项时也会给出（结论为 caution，items 为空）：

| 字段 | 含义 |
|---|---|
| conclusion | 整餐结论：suitable（适合）、caution（注意）、not_recommended（不建议）；有待确认的项时至少是 caution |
| unchecked_items | 待确认（没有核对）的菜名列表，没有时为空列表 |
| unchecked_notice | 有待确认的项时是一句程序写好的固定提示：这些菜品没能匹配到营养库，暂时没有按医嘱和饮食约束核对，请先选择对应的食物或改名，核对之后再吃或再确认入库；没有时为空 |
| items | 每个已匹配的识别项一条：item_id（对应识别项编号）、food_name、conclusion、reasons（依据列表）、tradeoff（权衡说明） |
| disclaimer | 引擎的免责说明 |

每条依据 reasons 有 source（来源：medical 医嘱、cycle 经期、goal 目标、training 训练、intake 当日摄入、preference 偏好）、effect（作用：block 阻断、unverifiable 无法核实、caution 注意、prefer 推荐、info 提示）、code、message（中文说明）与 ref（对应的医嘱条目等编号）。这些全部原样来自步骤 04 的引擎，按今天的约束评价。

## 五、建议修正的原因

review_reasons 是一个列表，按下面的固定顺序列出成立的原因；任一原因成立，这一项就“建议修正”，整条记录的 needs_review 为真。前端应当突出显示这些项，鼓励用户修正。

| 原因 | 条件 | 默认值的含义 |
|---|---|---|
| low_confidence | 把握程度低于 0.6 | 模型自己也不太确定 |
| needs_confirmation | 待确认（没有匹配到营养库） | 没有营养数字，必须处理后才能确认入库 |
| grams_out_of_range | 克数小于 10 克或大于 1500 克 | 一道菜的克数不太可能这么少或这么多 |
| estimated_grams | 克数只来自估算（模型估计的克数或类别默认份量） | 份量说法没能换算，克数不可靠 |

这些阈值是规则的默认值，用户运行照片评测后再调整（见《评测记录》）。用户修正过的项把握程度记为 1，不会再有 low_confidence；自己填了克数的项来源是 user，不会再有 estimated_grams。

## 六、数据库里的识别记录表

表名 photo_recognitions，每条记录属于一个用户：

| 列 | 含义 | 存储方式 |
|---|---|---|
| id | 识别记录编号 | 明文 |
| user_id | 所属用户 | 明文，删除用户时一并删除 |
| status | 记录状态（draft、confirmed、discarded） | 明文 |
| items | 识别项列表（保存时的样子，返回前按当前营养库核对并重新算合计与评价） | EncryptedJSON 加密 |
| image | 保留的图片：处理后的 JPEG，不含任何元数据；不保留时为空 | EncryptedBytes 加密，延迟加载：列表与查看都不会读出来，只有取图片的接口才读 |
| image_kept | 是否保留了图片 | 明文 |
| model_id | 所用的看图模型编号 | 明文 |
| eaten_on | 吃的日期（确认后） | 明文 |
| meal_type | 餐次（确认后） | 明文 |
| meal_entry_ids | 写入的饮食记录编号（确认后） | 明文 |
| created_at | 创建时间 | 明文 |
| updated_at | 最后修改时间 | 明文 |
| confirmed_at | 确认时间 | 明文 |

按用户与创建时间建有索引，用于列出识别历史（新的在前，最多 50 条）。原始上传文件在任何情况下都不保存；删除识别记录会连同图片一起删除，已经写入的饮食记录不受影响。
