# 份量换算表说明

模型给出的份量是“一碗”“半盘”“两个”这样的说法，系统统一换算成克，再用营养库每 100 克的数值算营养。本文说明换算的优先顺序、能认出的说法、换算表里每个单位与每个类别组的克数，以及这些数字的来源与维护方式。代码在 backend/app/photos/portions.py，换算表是 backend/app/photos/data/portion_units.json。

## 一、优先顺序

每个识别项按下面的顺序取克数，取到为止，结果四舍五入到整克，并记下克数来源：

| 顺序 | 做法 | 克数来源 | 是否算估算 |
|---|---|---|---|
| 1 | 份量说法里的单位是这个食物自带的份量单位（营养库里食物的份量，例如米饭的“碗”是 150 克、番茄炒蛋的“份”是 265 克）：单位克数乘数量 | food_portion | 否 |
| 2 | 份量说法里的单位在通用换算表里：按食物所属的类别组取克数，表里没有这个组的数值、或没有匹配到食物（待确认）时取这个单位的默认克数，再乘数量 | unit_table | 否 |
| 3 | 份量说法认不出，但模型给了估计克数：直接用模型的估计 | model_estimate | 是 |
| 4 | 以上都没有：用食物所属类别组的默认份量；没有类别组（或没有匹配到食物）时一律按 150 克 | group_default | 是 |

用户修正时自己填的克数，来源记为 user，不再换算。来源是 model_estimate 或 group_default 的项会带上“克数只来自估算”（estimated_grams）的提醒，鼓励用户修正。

营养库里自带份量的食物目前有 91 个（步骤 10 新增烤羊肉串与生鱼片两道菜品，由 89 个变为 91 个），自带的单位有份、个、杯、勺、碗、根、罐、小勺、盒、盘、两、瓶、片、块。食物自带的单位即使不在通用换算表里（例如罐、瓶、盒、两、小勺）也能认出；连成的长单位优先，例如“一小勺”在食物自带“小勺”时按小勺算，而不是按“小”加“勺”。

## 二、能认出的说法

先去掉空白与“大约”“约”“左右”这些词，再按“数量、大小、单位”读：

- 数量：阿拉伯数字（可带小数，例如 1.5）、一到九、两、十、十几（例如十二）；“半”表示 0.5；没有数量时按 1。
- 一碗半这样结尾带“半”的，在数量上加 0.5。
- “大”“小”写在数量前面（例如大半碗）时作用在数量上：“大”按 1.4 倍，“小”按 0.7 倍，“半”按 0.5 倍。大半碗就是 0.5 乘 1.4，即 0.7 碗。
- “大”“小”紧贴在单位前面（例如一小碗、大碗）时，先看表里有没有连起来的单位（小碗、大碗），有就当作一个单位；没有（例如一小盘）就作用在数量上，即 0.7 盘。
- 数量后面多了一个“个”且去掉它之后是表里的单位时，去掉这个“个”，例如“一个手掌”按“手掌”算。
- 说法本身就是一个单位（例如“半个手掌”“碗”）时，数量按 1。
- 认不出时（例如“一些”，或者没有匹配到食物时的“三两”），这一步不给克数，按优先顺序往下走。

例子（米饭属于主食组，自带份量“碗”150 克）：一碗是 150 克；大半碗是 105 克；一小碗不是米饭自带的单位，按换算表主食组的小碗 100 克；番茄炒蛋（菜肴组）一盘按换算表 250 克，一份按它自带的份量 265 克。

## 四、类别组与默认份量

类别组按营养库里食物类别的前缀归类（类别以表中任一前缀开头就属于这个组）；默认份量用于优先顺序的第 4 步。

| 类别组 | 默认份量（克） | 营养库类别前缀 |
|---|---|---|
| 主食 | 200 | 谷类及其制品、薯类淀粉及其制品、菜品-主食、补充-主食 |
| 汤粥 | 300 | 菜品-汤羹、菜品-火锅与麻辣烫 |
| 菜肴 | 200 | 菜品-家常菜、菜品-凉菜、蔬菜类及其制品、菌藻类、干豆类及其制品 |
| 肉蛋 | 150 | 畜肉类及其制品、禽肉类及其制品、蛋类及其制品、鱼虾蟹贝类 |
| 水果 | 150 | 水果类及其制品 |
| 饮品 | 250 | 补充-饮料、补充-饮品、补充-酒类、乳类及其制品-液态乳、乳类及其制品-酸奶 |
| 零食 | 50 | 补充-糕点甜食、坚果种子类 |

不属于任何组的食物（例如调味品、油脂）和待确认的项，单位克数用默认值，类别默认份量一律按 150 克。

## 五、来源与维护方式

来源：通用换算表、大小系数与类别默认份量里的克数，都是实现时按家常餐具与常见份量拟定的默认值，没有外部出处，没有经过称量校准。食物自带的份量来自步骤 04 的营养库数据（见步骤 04 的交付文档）。

这些数字靠照片评测来调：用户用自选的真实餐食照片运行评测脚本，评测结果里有“克数偏差超过 50%”的数量（需要在标注里填真实克数），以及每张照片识别出的克数与真实克数的对照；按偏差集中的单位与类别组修改换算表（见《评测记录》）。

维护方式：直接编辑 portion_units.json，不需要改代码，重启服务后生效。

- 增加单位：在 units 里加一项，写默认克数，按需要写各组的克数；组名必须是 category_groups 里已有的组。
- 调整克数：改对应单位或组的数值；修改后已保存的草稿不会自动重算，用户修正或新识别时才按新表换算。
- 增加类别组：在 category_groups 里加组名与类别前缀（前缀要能在营养库里找到食物），同时在 group_defaults 里写它的默认份量。
- 修改后运行完整测试：自动化测试会检查每个单位都有默认克数、每个组都有默认份量、各组的前缀都能在营养库里找到食物、每个单位都能被认出。本文的表格也要同步更新，文档测试会逐行核对。
