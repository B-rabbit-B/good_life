# 步骤 01 接口清单

本文列出步骤 01 提供的全部接口。所有接口路径都以 /api 开头，请求与响应的正文都是 JSON 格式（退出登录成功时无正文）。

在线的交互式接口文档由服务自动生成，服务启动后在浏览器打开 8000 端口下的 docs 页面即可查看并直接试用，具体做法见仓库根目录的 README。

## 一、登录方式

- 登录成功后会得到一个访问令牌。之后每次请求都在请求头 Authorization 中带上“Bearer 空格 令牌”。
- 令牌默认有效 7 天，可通过配置调整。
- 退出登录后，该用户此前签发的全部令牌立即失效。
- 除注册、登录、免责声明正文和健康检查外，其余接口都需要登录。
- 档案相关接口和能力接口除了登录，还要求用户已确认当前版本的免责声明。后续所有业务接口都遵循同样的规则。

## 二、接口一览

“需登录”指必须带有效令牌；“需已确认免责声明”指用户必须已确认当前版本的免责声明。

### 单独同意与账号数据处置（步骤 12 新增）

经期与医嘱是敏感模块，免责声明之外还要各自单独同意才开放。下面的接口里，“单独同意”的两个要求登录并已确认免责声明；“账号”下的三个只要求登录，不要求确认最新版免责声明，免责声明升版后、重新确认之前，用户也必须能撤回同意、导出与删除自己的数据。导出与删除前要重新输入密码，密码错了是 403 password_incorrect（不是 401，401 会让前端清掉登录状态），与登录共用同一套限速，同一用户 15 分钟内输错 5 次后一律 429。

| 方法 | 路径 | 需登录 | 需已确认免责声明 | 请求字段 | 用途 | 主要错误码 |
|---|---|---|---|---|---|---|
| GET | /api/consents | 是 | 是 | 无 | 查看经期与医嘱两项单独同意的状态：kind（cycle 或 medical）、title、text（同意文案）、current_version、granted、granted_at、granted_version、withdrawn_at | disclaimer_not_accepted、not_authenticated、invalid_token |
| POST | /api/consents/{kind} | 是 | 是 | version（当前文案版本），必填；kind 是路径里的 cycle 或 medical | 给出单独同意，返回该项的同意状态 | consent_outdated（提交的不是当前版本，409）、validation_error、disclaimer_not_accepted |
| POST | /api/account/consents/{kind}/withdraw | 是 | 否 | 无 | 撤回单独同意：在同一个事务里清除该模块的全部数据并关闭模块，成功返回 204 | not_found（没有有效同意，404）、not_authenticated、invalid_token |
| POST | /api/account/export | 是 | 否 | password（登录密码），必填 | 导出本人全部数据：返回压缩包（每个模块一份 JSON、医嘱原件、保留的照片与一份中文说明），响应禁止缓存 | password_incorrect（403）、too_many_attempts（429）、export_too_large（413，医嘱原件与保留的照片合计超过 200 MiB）、validation_error |
| POST | /api/account/delete | 是 | 否 | password（登录密码）与 confirm（必须为真），均必填 | 立即彻底删除账号与全部数据，不可恢复，成功返回 204 | password_incorrect（403）、too_many_attempts（429）、validation_error（没有勾选确认） |

未同意就访问经期或医嘱的接口，返回 403，错误码 consent_required，提示“使用经期记录前，需要你单独同意处理经期信息”或“使用医嘱前，需要你单独同意处理医嘱与健康信息”。

## 三、统一错误格式

所有错误响应的正文都是同一种结构：最外层只有一个 error 对象，里面有两项固定内容：

- code：机器可读的错误码，前端和后续模块据此判断处理方式。
- message：中文提示，可以直接展示给用户。

参数校验类错误（validation_error）会额外多一项 details，是一个列表，每一项指出哪个字段（field）出了什么问题（message），方便前端把提示对应到具体输入框。其中 message 是按错误类型写成的中文说明（例如“至少 8 个字符，请补全”“不能大于 250”），不认识的类型写“输入内容不符合要求，请检查后重试”；每一项另带 type（错误类型）与 original（校验库给出的英文原文），只供排查，不用于显示。

HTTP 状态码与错误码配合使用，例如未登录是 401，未确认免责声明是 403，用户名重复是 409，参数不合法是 422，服务内部异常是 500。

## 四、错误码一览

| 错误码 | HTTP 状态码 | 中文含义 | 出现场景 |
|---|---|---|---|
| validation_error | 422 | 请求参数不合法，提示为“请求参数不合法”，并带 details 说明具体字段 | 用户名或密码不符合长度或字符要求；档案字段取值越界、枚举值不在允许范围、提交了档案之外的字段；请求缺少必填内容 |
| http_error | 视情况而定（常见 404、405） | 通用的 HTTP 错误，提示文字取自底层错误信息 | 访问不存在的路径，或用了该路径不支持的请求方法。它是兜底错误码，其他有专用错误码的情况不会落到这里 |
| username_taken | 409 | 该用户名已被注册，请换一个 | 注册时用户名已存在；比较时不区分大小写 |
| invalid_credentials | 401 | 用户名或密码错误 | 登录时用户名不存在或密码不对，两种情况给出同样的提示，避免被用来试探哪些用户名存在 |
| not_authenticated | 401 | 请先登录 | 需要登录的接口没有带令牌，或 Authorization 请求头不是“Bearer 空格 令牌”的格式 |
| invalid_token | 401 | 登录已失效，请重新登录 | 令牌格式错误、被篡改、已过期，或用户已退出登录、对应用户已不存在 |
| disclaimer_not_accepted | 403 | 请先阅读并确认免责声明 | 已登录但尚未确认当前版本免责声明，就访问了业务接口 |
| disclaimer_outdated | 409 | 免责声明已更新，请重新阅读最新版本后确认 | 确认免责声明时提交的版本号不是当前版本 |
| too_many_attempts | 429 | 尝试次数过多，请 15 分钟后再试 | 登录或导出、删除前的密码复核：同一键 15 分钟内失败 5 次后，再尝试（即使密码正确）一律返回；计数在进程内，重启后清零 |
| password_incorrect | 403 | 密码不正确，请重新输入 | 导出或删除账号前重新输入的密码不对；用 403 而不是 401，是为了不让前端清掉登录状态 |
| consent_required | 403 | 使用经期记录前或使用医嘱前，需要你单独同意 | 没有有效的单独同意就访问了经期或医嘱模块的接口 |
| consent_outdated | 409 | 单独同意的说明已更新，请重新阅读最新版本后同意 | 给出单独同意时提交的版本不是当前版本 |
| request_too_large | 413 | 提交的内容太大，请删减后再试 | 上传与对话之外的 POST、PUT、PATCH 请求，请求体超过 1 MiB；模型对话的请求体上限是 32 MiB，同样返回这个错误码 |
| export_too_large | 413 | 医嘱原件与保留的餐食照片合计超过 200 MB，无法一次导出 | 导出数据时原件与保留照片合计超过 200 MiB，在读任何文件之前就拒绝 |
| evidence_limit_reached | 409 | 每份医嘱最多上传 10 个文件 | 给一份医嘱上传原件时已满 10 个，详见《步骤 03 接口清单》 |
| internal_error | 500 | 服务器内部错误 | 服务出现未预料的异常。响应里不包含任何异常细节，具体原因只记录在服务日志中 |
