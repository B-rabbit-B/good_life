# 步骤 02：经期模块

## 目标

做出面向女性用户的经期记录与预测能力，并输出"当前所处阶段"和"该阶段的饮食与生活提示"，作为后续智能体和 SDK 的第一个完整领域模块。

## 范围

- 经期记录：每次月经的开始日、结束日，以及每天的流量、痛经程度、情绪、其他症状，均可补录和修改。
- 周期统计：平均周期长度、平均经期长度、周期波动程度、常见症状出现的规律。
- 预测：下次月经预计开始日、预计排卵日、易孕窗口，并给出前后浮动的置信区间。
- 阶段判断：给定任意一天，判断处于月经期、卵泡期、排卵期、黄体期中的哪一段，以及距离下次月经还有几天。
- 阶段饮食与生活提示：由一份可维护的规则表给出，比如经期偏好温热、少吃寒凉、注意补铁等，附上适用条件和免责说明。
- 特殊状态：用户可标记"孕期"或"暂停预测"，此时不再做经期预测。
- 对外提供的能力以"领域服务"的形式实现，此步骤先作为内部服务和接口，后续在步骤 06 统一封装。

## 明确不做

- 机器学习预测。
- 孕期的详细追踪与孕周内容。
- 智能体对话与主动提醒，这些放到步骤 08。
- 界面页面，放到步骤 11。

## 关键设计

- 预测方法：以最近若干次周期做加权平均，近期权重更高；周期波动大时，置信区间自动变宽；记录不足时，明确告知"数据不足，仅为参考"，不给假精确。
- 异常数据处理：周期过短、过长、长时间缺失记录时，预测结果打上"可能不准"的标记，并提示如有持续异常建议咨询医生，不做诊断。
- 规则表独立于代码：饮食与生活提示放在可维护的规则数据里，每条规则包含适用阶段、内容、依据说明、严重程度，方便你逐条审核。
- 女性专属开关：只有档案性别为女性且未选择关闭时，才向该用户开放此模块。
- 经期数据属于敏感数据，读写都要走步骤 01 定下的加密与隔离策略。

## 交付物

- 经期数据表说明。
- 预测与阶段判断的规则说明文档，写清楚每一步怎么算、什么情况下降级。
- 阶段提示规则表，含每条规则的依据说明，供你审核。
- 接口清单（记录、修改、查询统计、查询预测、查询某日阶段、查询阶段提示）。
- 一组用于演示的样例数据说明：规律型用户、波动型用户、数据不足型用户。

## 验收标准

1. 能录入至少三次完整周期，统计结果与手算一致。
2. 规律型样例的预测区间窄，波动型样例的预测区间明显更宽。
3. 数据不足的样例，预测结果带有"数据不足"标记，而不是给出确定日期。
4. 任意给定日期，阶段判断与手算一致，边界日（如月经第一天、预测排卵日）逐个核对。
5. 阶段提示规则表你已逐条审核，删除或修改了你不认同的条目。
6. 男性用户或关闭了该功能的用户，访问该模块会被拒绝。
7. 一个用户读不到另一个用户的经期数据。
8. 孕期或暂停状态下，不再输出经期预测。

## 风险与对策

- 风险：预测被当成医疗结论。对策：所有预测结果都附"仅供参考，不能用于避孕或诊断"的说明。
- 风险：用户数据量少导致预测不准。对策：降级策略与明确标记，见关键设计。
- 风险：饮食提示中医式说法缺乏统一依据。对策：每条规则写明来源与适用条件，标注为"传统经验，非医学结论"的单独归类，由你决定是否保留。
