## 二、验收方式

后端目录里有一个验收脚本，模块名是 app.phase2_acceptance，用 uv 以模块方式运行即可（数据库需在运行）。它会重建验收账号 demo_phase2_final（密码 demo-pass-123，女性，1996 年出生，身高 162 厘米，体重 54 千克，活动量轻，目标减脂），全程通过真实的接口（与前端将来调用的接口相同）完成，没有经过任何界面。

没有真实的模型密钥和高德密钥，所以脚本在本机启动两个模拟服务，结束时都会关闭：

- 模拟模型：按兼容格式应答，沿用中期检查按关键词给出固定回答或工具调用的做法；收到带图片的请求时按图片颜色给出固定的识别结果（饭菜颜色的图是一盘麻婆豆腐加一碗米饭，并故意多塞一个“热量 999”的字段；白图是“不是食物”）；用户说不想做饭时，先调用附近餐厅工具，再从工具结果里推荐粥铺。同一个模型服务下添加两个模型：mock-agent 用于日常对话，qwen-vl-max 用于看图识别。
- 模拟高德：提供周边搜索、地址解析与逆地理三项，固定返回七家店：川菜馆、麻辣烫、粥铺、轻食沙拉、火锅（高德类别编码 050117）、面馆，以及一家判断不出类别的“某某餐厅”。

模型与高德的调用都走真实的适配器与高德客户端，只是对面换成了本机的模拟服务；高德的地址与密钥只在脚本进程里临时改成模拟服务和演示用的假密钥，不读取、不修改后端的配置文件，结束时原样恢复。脚本不使用任何真实密钥，也不访问外网。

故事顺序与中期检查的不同之处：为了让忌辛辣的医嘱在拍照识别和餐厅推荐时仍然生效，中期检查的“医生说好了并解除”和“解除之后”两步移到最后。确认医嘱、确认解除医嘱、修正并确认拍照识别、定位授权这几步代表用户本人在应用里的操作。

这个脚本也加进了自动化测试，每次全量测试都会在测试库上完整跑一遍。
