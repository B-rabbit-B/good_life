# 需求到检索关键词的映射说明

本文说明用户的“想吃什么”如何变成发给高德的检索关键词，以及哪些部分由规则决定、哪些部分可以交给模型。内容按实际代码写成：需求词表在后端 app/restaurants/data/needs.json，匹配与解析在 app/restaurants/needs.py，检索流程在 app/restaurants/service.py。

## 1. 分工

- 需求词表是固定的，一共 12 个需求词。用户的说法只会被归到这 12 个词上，词表以外的说法一律不用于检索。
- 先用规则匹配；规则没有命中时，才可能请对话模型从词表里挑词，模型挑出词表以外的词一律丢弃。
- 检索关键词、餐厅类型、过滤与排序全部由规则决定，模型只负责“这句话属于词表里的哪几个词”。

## 3. 需求的来源与合并

检索请求里与需求有关的字段有两个：

- need：一句话需求，最长 100 字，可不填。
- needs：直接给出的需求词键，最多 3 个，可不填。

处理顺序：

1. 直接给出的键先校验：有词表里没有的键，返回 422，错误码 restaurant_unknown_need，说明里列出未知的键并建议从词表里选；此时不会发出任何网络请求。
2. 规则匹配一句话需求（见第 4 节），结果与直接给出的键合并：直接给出的在前，去重后最多 3 个。规则有命中时来源记为 rules，否则记为 none。
3. 规则没有命中、一句话需求不为空、并且是应用接口发起的检索时，请对话模型从词表里挑词（见第 5 节）。模型挑出了词时，与直接给出的键合并去重（最多 3 个），来源记为 model。
4. 仍然没有任何需求词时，不限需求。

检索结果的 needs 字段返回用到的键、名称与来源（rules、model、none）。直接给出键而一句话需求没有命中规则时，来源仍记为 none，键照常使用。

## 4. 规则匹配

- 需求词的名称或任一同义说法作为一段文字出现在一句话需求里，即算命中。
- 否定：说法出现的每一处，如果紧挨在它前面的是下列否定说法之一，这一处不算；只要有一处不是被否定的，就算命中。否定说法有“不”、“别”、“不想”、“不要”、“不吃”、“不喝”、“不想吃”、“不想喝”、“不要吃”、“不要喝”、“别吃”、“别喝”。例如“不想吃甜的”不会命中甜品。
- 本身以“不”开头的说法（例如不吃辣、不油腻、不吃肉、不吃猪肉）不做否定检查。
- 命中的词按词表的顺序排列，最多取 3 个。例如“胃不舒服想吃点软的”命中清淡与粥两个词。

## 5. 模型挑词（可选）

- 只有应用接口的检索会请模型挑词；SDK、MCP 与聊天智能体的“附近餐厅”工具没有一句话需求参数，需求词键只能从词表的枚举里选（智能体自己按对话填写），服务层不再调用模型。
- 使用用户在步骤 07 里为“日常对话”选定的模型。用户没有选对话模型，或者调用出错、超时，都静默按“没有需求”处理，不影响检索。
- 系统指令列出全部需求词的键、名称与说明，要求只从词表里挑、最多 3 个、没有合适的就返回空列表，不推荐餐厅、不解释，只输出一个形如 needs 列表的 JSON 对象。用户的一句话需求作为用户消息发送。回答最多 200 个 token。
- 解析：取回答里第一个 JSON 对象的 needs 列表，只保留词表里的键，去重后最多 3 个；格式不对或没有可用的键时按“没有需求”处理。
- 调用模型期间不占用数据库事务。

## 6. 从需求词到高德检索

1. 按需求词的顺序，依次取每个词的检索关键词，去掉重复的，最多保留 3 个。例如清淡加粥得到“粥、粤菜、家常菜”。
2. 有关键词时，每个关键词向高德发一次周边搜索，最多 3 次；没有任何需求时，不带关键词发一次。
3. 每次周边搜索都限定在高德的餐饮服务大类（类别编码 050000），按距离排序，取第一页 25 条，并请求营业信息以取得评分（高德有提供时）。半径来自请求，500 至 5000 米，默认 2000 米。
4. 几次检索的结果合并，按店铺编号去重，同一家店保留先出现的那一条。
5. 需求词的“偏向的类型”在排序时使用：结论相同的店里，属于偏向类型的排在前面（见《约束过滤与排序规则说明》）。需求词不会让任何一家店被过滤掉。

## 7. 已知局限

- 规则只认词表里写明的说法。例如“不想吃辣”“不要太辣”不在不辣的同义说法里，不会命中不辣；这时如果是应用接口发起的检索，并且用户选了对话模型，会交给模型挑词。
- 否定判断只看紧挨在前面的文字，“要不喝粥吧”“要不要吃面”里的“不”会被当作否定，不会命中粥或面食。
- 检索关键词是给高德的文字关键词，高德按自己的相关性返回结果，店名或类别里不一定有这个关键词；最终每家店属于哪个类型、是否适合，仍由《约束过滤与排序规则说明》里的规则判断。
