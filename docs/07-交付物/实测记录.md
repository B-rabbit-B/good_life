# 实测记录

本文是国内外主流服务的实测记录。步骤 07 的验收标准要求至少四家不同服务实测通过，并写明各家拉取与调用的实际表现，包括调研中未能核实的情况。

## 一、实测方式

- 实测由用户本人在本机运行实测脚本完成，Claude 没有任何服务的密钥，也不会替你实测。
- 密钥只写在本机的一个密钥文件里（backend 目录下的 llm_keys.local.env，由同目录的模板 llm_keys.local.env.example 复制而来）。这个文件和实测结果文件 llm_live_result.md 都已在 backend 目录的忽略清单里，不会被提交；请不要把密钥文件发给任何人，也不要提交。
- 脚本用的是系统里真实使用的适配器（与正式调用同一套代码），对每家服务依次检查七项，每项记录耗时。运行方法见仓库根目录 README 的“多模型接入”一节。
- 没有填密钥的服务会被跳过，结果里写“未提供密钥”。
- 没有填写模型名时，只跳过对话、工具调用、看图三项（工具调用没有单独填模型名时沿用对话模型名）；拉取模型和三项故意的错误仍会运行，其中没有对话模型名时，“密钥改错”改用拉取模型来检查。
- 每次调用的超时是 60 秒，比正式调用宽松；对话、工具调用、看图最多输出 512 个 token，给会先思考再回答的模型留出余量。
- 运行时每开始检查一家、每完成一项，都会在屏幕上打印一行进度（只有服务名、项目、结果、错误码与耗时，不含密钥）。中途按 Ctrl 加 C 中断时，中断之前已完成的检查仍会写进结果文件，文件开头注明本次运行被中断。
- 密钥文件要保存为 UTF-8 编码（记事本另存时选 UTF-8，带不带 BOM 都可以）；不是 UTF-8 时脚本会提示另存为 UTF-8，不会继续运行。
- 脚本把结果写入 llm_live_result.md 并打印在屏幕上。输出前会去掉全部密钥，文件开头写明运行日期与“本文件不含任何密钥”。你仍然应该先看一遍，再把结果摘抄到本文第四节。

## 二、每家要实测的项目

| 序号 | 项目 | 做法 | 通过的判断 |
|---|---|---|---|
| 1 | 拉取模型 | 向服务拉取模型列表 | 成功；记录模型数量、前 5 个名称，失败则记录错误码 |
| 2 | 对话 | 用对话模型发“请只回复：好” | 有回复 |
| 3 | 工具调用 | 提供一个 get_weather（参数 city）工具，问“北京今天天气怎么样？请调用工具查询” | 模型确实调用了 get_weather |
| 4 | 看图 | 发一张脚本内生成的 16 乘 16 纯红色图片，问“这张图片是什么颜色？只回答颜色” | 回答里含“红” |
| 5 | 密钥改错 | 把密钥换成一个明显错误的值再请求 | 归类为 invalid_key |
| 6 | 地址改错 | 在地址后面加上不存在的路径再拉取模型 | 归类为 not_found 或 unreachable |
| 7 | 模型名改错 | 用一个不存在的模型名发起对话 | 归类为 model_not_found |

第 5 至 7 项是故意制造的错误，“通过”的意思是系统把错误归到了预期的类别，从而在界面上能给出准确的提示。如果某家服务的实际表现与预期不一致，脚本会记录实际得到的错误码，那正是需要补适配的地方，请原样写进本文。
