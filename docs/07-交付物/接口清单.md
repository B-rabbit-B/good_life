# 接口清单

步骤 07 新增 17 个接口，路径都以 /api/llm 开头，在接口文档页面（服务启动后打开 8000 端口下的 docs 页面）的 llm 分组里可以直接试用。

通用约定：

- 所有接口都要求已登录并已确认免责声明，只能操作自己的数据。没有登录返回 401（not_authenticated），没有确认免责声明返回 403（disclaimer_not_accepted）。
- 别人的记录与不存在的记录一样返回 404（not_found）。任何接口都不接受客户端传入用户编号。
- 请求正文里出现没有声明的字段，或字段格式不对，返回 422，错误码 validation_error，并带每个字段的明细。
- 错误格式统一为一个 error 对象，含 code 与 message，message 是中文说明并给出下一步建议。
- 任何响应里都没有密钥，只有掩码 key_hint。

## 一、服务配置

### 1. 列出预设：GET /api/llm/presets

返回七个预设的列表，每项有 id、name、kind（服务类型）、base_url（预设地址）。预设只用来填默认地址，见《服务类型与调用方式》。

### 2. 添加服务：POST /api/llm/providers

请求：name（名称，1 至 50 字）、kind（openai_compatible、anthropic、gemini 之一）、base_url（地址，1 至 300 字）、api_key（密钥，1 至 500 字，两端空白会被去掉）。

响应 201：服务对象，字段为 id、name、kind、base_url（已去掉结尾斜杠）、key_hint、created_at、updated_at。

错误：

- 422 llm_invalid_url：地址不合格（协议不对、非本机地址不是 https、带用户名密码或查询参数或 # 片段、指向内网或本机、无法解析），说明里写明原因。
- 409 llm_provider_exists：同一用户下已有同名服务。
- 409 llm_too_many_providers：已有 20 个服务。

### 3. 列出服务：GET /api/llm/providers

返回自己的全部服务，按名称排序，字段同上。

### 4. 查看服务：GET /api/llm/providers/{provider_id}

返回一个服务，字段同上。不存在或不是自己的返回 404。

### 5. 修改服务：PATCH /api/llm/providers/{provider_id}

请求：name、base_url、api_key，都可以不填或填 null，表示保持原值；只修改填了的字段。服务类型不可改，请求里出现 kind 会被拒绝（validation_error）。改密钥后 key_hint 随之更新。

改地址的规则：新地址的协议、主机或端口与原来不同时，必须在同一个请求里填写 api_key（新的密钥），否则返回 422 llm_key_required_for_new_url，整次修改都不生效（名称也不改）。只改路径时可以不填密钥，原密钥保留。这样已保存的密钥不会被发到一个新的主机上。

错误：

- 同添加服务的 llm_invalid_url 与 llm_provider_exists。
- 422 llm_key_required_for_new_url：改了地址的协议、主机或端口，却没有同时填写密钥。

### 6. 删除服务：DELETE /api/llm/providers/{provider_id}

响应 204。服务下的模型与指向这些模型的用途分配一并删除。

## 二、模型与能力标注

### 7. 拉取模型：POST /api/llm/providers/{provider_id}/fetch-models

由后端向该服务拉取模型列表，新增来源为 fetched 的模型。没有请求正文。

响应：added（本次新增的数量）、total（服务这次返回的数量）、skipped（因超过 500 个上限或编号为空、过长而没有收录的数量）、models（该服务下现有的全部模型，含手动添加的，按模型编号排序）。已有模型与它们的能力标注不改动，列表里消失的模型也不删除。

错误：服务返回的错误按《服务类型与调用方式》的归类转成下文第五节的错误码，例如 llm_invalid_key、llm_listing_unsupported_or_bad_url、llm_quota_exceeded。拉取失败时不会改动已有模型。

### 8. 列出模型：GET /api/llm/providers/{provider_id}/models

返回该服务下的全部模型，按模型编号排序。每个模型的字段：

| 字段 | 含义 |
|---|---|
| id | 模型记录编号，分配用途、修改标注、删除时用它 |
| provider_id | 所属服务 |
| model_id | 模型编号（调用服务时填的名字） |
| display_name | 显示名称，可为空 |
| source | fetched（拉取）或 manual（手动添加） |
| capabilities | 有效能力：vision（看图）、tools（工具调用）、chat（对话），各为真、假或空（空表示未知） |
| table_capabilities | 对照表给出的能力，格式同上 |
| overrides | 用户手动标注，格式同上，空表示没有标注 |
| capability_note | 命中对照表规则的说明，没有命中为空 |

### 9. 手动添加模型：POST /api/llm/providers/{provider_id}/models

请求：model_id（1 至 200 字）、display_name（可不填）。响应 201：模型对象。用于不提供模型列表的服务，或列表里没有的模型。

错误：409 llm_model_exists，该服务下已有同编号的模型。

### 10. 修改能力标注：PATCH /api/llm/models/{model_pk}

请求：vision、tools、chat 三项，出现的项才会修改；值为真、假或空（空表示回到对照表）。

响应：模型对象，外加 assignment_warnings（文字列表）：如果这个模型已被分配到某个用途，而修改后不再满足该用途的要求，修改仍然保存，列表里会有一条提醒，说明使用时会报错；没有问题时为空列表。

### 11. 删除模型：DELETE /api/llm/models/{model_pk}

响应 204。指向它的用途分配一并删除。

## 三、连通性测试

测试不会保存任何东西。两个接口的响应格式相同。

### 12. 测试还没保存的服务：POST /api/llm/providers/test

请求：kind、base_url、api_key，以及可选的 model_id（模型编号字符串，给了才做对话测试）。地址不合格时直接返回 422 llm_invalid_url，不发出任何请求。

### 13. 测试已保存的服务：POST /api/llm/providers/{provider_id}/test

请求：可选的 model_id。使用已保存的地址与密钥（读取时才解密）。

### 测试的响应

| 字段 | 含义 |
|---|---|
| conclusion | 结论，取值见下表 |
| ok | 结论为 ok 或 ok_listing_unsupported 时为真 |
| message | 中文说明与下一步建议 |
| listing | 拉取模型这一步：ok、code（失败时的接口错误码）、message |
| chat | 对话这一步，格式同上；没有给模型编号，或拉取失败的原因不需要再试对话时为空 |
| models_found | 拉取到的模型数，拉取失败时为空 |
| sample_models | 前 10 个模型编号 |

结论取值：

| 结论 | 含义 |
|---|---|
| ok | 连接正常（拉取成功；给了模型编号时对话也成功） |
| ok_listing_unsupported | 对话成功，但该服务不支持拉取模型列表（或当前密钥无权拉取），请手动添加模型编号 |
| invalid_key | 密钥不正确或没有权限 |
| bad_url | 地址错误或无法连接：拉取与对话都返回 404，或无法连接、地址格式不对；只有拉取返回 404 而没有给模型编号时，也归为地址问题，并提示可能是服务不支持列表，请填一个模型编号再测一次 |
| model_unavailable | 对话说模型不存在或没有权限 |
| quota_exceeded | 余额或额度不足 |
| rate_limited | 被限流 |
| timeout | 超时 |
| bad_request | 服务拒绝了请求 |
| provider_error | 服务出错或返回内容无法识别 |

判定规则的要点：先拉取列表，再用指定模型发一次最小对话（提示词“请只回复：好”）。列表 404 而对话成功，通过但提示不支持拉取；两者都 404 是地址错误；列表成功而对话说模型不存在或 404，是模型不可用；列表报密钥不正确时也会再试对话，对话成功说明密钥只是无权拉取列表；其他拉取错误直接以拉取的错误为结论。验收中的“密钥错误、地址错误、模型不可用”三种原因，就是靠这套规则区分的。

## 四、用途分配与统一调用

### 14. 查看用途分配：GET /api/llm/assignments

返回已分配的用途列表，按用途排序，每项有 purpose（chat 或 vision）、model（模型对象）、provider_name（所属服务名称）。

### 15. 选择用途的模型：PUT /api/llm/assignments/{purpose}

用途只能是 chat（日常对话）或 vision（看图识别）。请求：model_id，注意这里填的是模型对象里的 id（模型记录编号），不是模型编号字符串。每个用途至多一条，重复分配是替换。响应：分配对象，格式同上。

检查规则：

- 看图识别只接受有效看图能力为“支持”的模型，“不支持”和“未知”都拒绝，返回 422 llm_model_lacks_vision，提示先在模型上手动标注“支持看图”。
- 日常对话拒绝有效对话能力为“不支持”的模型，返回 422 llm_model_not_chat。
- 用途不认识返回 422 llm_unknown_purpose；模型不存在或不是自己的返回 404。

### 16. 清除用途的分配：DELETE /api/llm/assignments/{purpose}

响应 204。这个用途没有分配时返回 404；用途不认识返回 422 llm_unknown_purpose。

### 17. 统一调用：POST /api/llm/chat

后端对外唯一的模型调用方式：按用途找到用户分配的模型，调用前再检查一遍能力，才读取密钥并调用服务。

请求：

- purpose：chat 或 vision。
- messages：消息列表，1 至 50 条。每条有 role（system、user、assistant）、text（最多 20000 字，可为空）、images（图片列表，可不填，最多 4 张；每张有 mime_type，取值 image/png、image/jpeg、image/webp、image/gif，以及 data_base64，即 base64 编码内容，解码后不超过 5 MB）。
- max_tokens：最大输出长度，1 至 4096，默认 1024。

响应：text（回复文字）、tool_calls（模型要求的工具调用，每项有 name、arguments、call_id；本接口不开放传入工具，所以通常为空）、model_id（实际使用的模型编号）、provider_name（服务名称）、usage（input_tokens 与 output_tokens，服务没有给时为空）。

调用前的检查与错误：

- 409 llm_not_configured：这个用途还没有分配模型，说明里指引到设置页选择。
- 422 llm_model_lacks_vision：用途是看图识别，或消息里带了图片，而当前模型的看图能力不是“支持”。这就是验收第 7 条要求的明确提示，说明里写明原因，并给出三条出路：换一个支持看图的模型、手动标注、改为手动填写。
- 422 llm_model_not_chat：当前模型被标明不是对话模型。
- 422 llm_invalid_images：图片放在了系统或助手消息里，或一次超过 8 张，或合计超过 20 MB。
- 单条消息超过 4 张、单张超过 5 MB、base64 编码不合法、图片类型不支持：422 validation_error。
- 服务返回的错误见下文第五节。

## 五、调用服务时的错误码

拉取模型、测试、统一调用在服务返回错误时，都按下表转成接口错误；说明里是中文的原因与下一步建议，末尾附服务返回的原始信息（已去掉密钥，最多 300 字）。

| 错误码 | 状态码 | 含义与建议 |
|---|---|---|
| llm_invalid_key | 400 | 密钥不正确或没有权限：检查密钥是否复制完整、是否属于这个服务、账户是否开通了权限 |
| llm_bad_url | 400 | 无法连接，或地址格式不对；对话时遇到与模型无关的 404 也是这个码：检查地址（例如少了或多了 /v1）与网络 |
| llm_listing_unsupported_or_bad_url | 400 | 拉取模型时返回 404：服务可能不提供模型列表，也可能地址写错，请核对地址或手动添加模型 |
| llm_model_unavailable | 400 | 模型不存在或没有使用权限：确认拼写，先点获取模型看看可用的模型 |
| llm_bad_request | 400 | 服务拒绝了这次请求：检查模型编号与提问内容，或换一个模型 |
| llm_quota_exceeded | 402 | 余额或额度不足：到服务商控制台充值或提升额度 |
| llm_rate_limited | 429 | 被限流：稍后再试 |
| llm_timeout | 504 | 连接超时：检查网络后重试 |
| llm_provider_error | 502 | 服务出错或返回的内容无法识别（包括返回的内容超过 10 MB）：稍后再试，或换一个模型 |

另有本模块自己的校验错误：llm_invalid_url（422）、llm_key_required_for_new_url（422）、llm_provider_exists（409）、llm_too_many_providers（409）、llm_model_exists（409）、llm_unknown_purpose（422）、llm_not_configured（409）、llm_model_lacks_vision（422）、llm_model_lacks_tools（422，只在后端内部带工具调用时出现）、llm_model_not_chat（422）、llm_invalid_images（422），含义见上文各接口。
