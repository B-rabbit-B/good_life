# 服务类型与调用方式

本文列出系统支持的三种服务类型、七个预设，以及每种类型拉取模型与调用模型的请求方式、鉴权方式、图片与工具的表示、错误如何归类。内容以代码为准：适配器在 backend/app/llm/adapters，预设在 backend/app/llm/kinds.py。

后端对外只有一种调用方式（统一调用入口，见《接口清单》），内部由适配器把统一的消息、图片、工具转换成各家的格式，再把各家的返回转换回统一的结果。浏览器从不直接带着密钥请求第三方。

## 一、三种服务类型

| 服务类型 | 适用的服务 | 说明 |
|---|---|---|
| openai_compatible | 通义千问、DeepSeek、豆包、智谱、OpenAI，以及其他兼容 OpenAI 格式的服务 | 国内外大多数服务都提供这种格式，是最常用的类型 |
| anthropic | Claude | 使用 Anthropic 自己的消息接口，格式与兼容格式不同 |
| gemini | Gemini | 使用 Google 的生成内容接口，格式与兼容格式不同 |

服务类型由用户在添加服务时选定，之后不能修改（想换类型请新建一个服务）。

## 二、七个预设

预设只用来在界面上帮用户填入默认地址，服务类型与地址之后都可以由用户改。接口 GET /api/llm/presets 返回下面七项。

| 预设 | 服务类型 | 预设地址 |
|---|---|---|
| 通义千问 | openai_compatible | https://dashscope.aliyuncs.com/compatible-mode/v1 |
| DeepSeek | openai_compatible | https://api.deepseek.com/v1 |
| 豆包 | openai_compatible | https://ark.cn-beijing.volces.com/api/v3 |
| 智谱 | openai_compatible | https://open.bigmodel.cn/api/paas/v4 |
| OpenAI | openai_compatible | https://api.openai.com/v1 |
| Claude | anthropic | https://api.anthropic.com |
| Gemini | gemini | https://generativelanguage.googleapis.com/v1beta |

这些地址是调研得到的公开地址，其中哪些服务确实提供模型列表接口、对话是否可用，要以《实测记录》为准。

## 三、共同的请求行为

- 所有请求由后端发出，超时时间默认 20 秒，可用配置项 LLM_TIMEOUT_SECONDS 调整。
- 不跟随重定向：服务返回重定向时不会去访问新地址（避免把密钥带到别处），按服务出错处理。
- 请求地址由用户填写的服务地址加上固定的路径拼成；服务地址保存时已去掉结尾斜杠。
- 请求正文与响应都是 JSON；成功响应不是合法 JSON，或缺少必要字段、类型不对，归为服务出错（provider_error）。
- 响应正文边读边计数，最多读 10 MB（按解压后的大小算）；超过就停止读取，归为服务出错，说明是“服务返回的内容过大”。超时按每一步网络操作计算（连接、每次读取），目前没有整次请求的总时限。
- 密钥只放在请求头里，不放进地址。发请求之前先检查密钥：为空、带首尾空格、控制字符或全角字符都直接判为密钥不正确，不发请求。
- 拉取到的模型列表一律按模型编号去重并排序，结果顺序固定。

## 四、openai_compatible

- 鉴权：请求头 Authorization，值为 Bearer 加空格加密钥。
- 拉取模型：向服务地址加 /models 发 GET 请求，从响应的 data 列表里取每一项的 id。这种格式的列表不翻页，也不带显示名称。
- 对话：向服务地址加 /chat/completions 发 POST 请求，正文含模型、最大输出长度、消息列表（角色为 system、user、assistant）。最大输出长度的字段名一般是 max_tokens；只有服务地址的主机是 api.openai.com 时用 max_completion_tokens（OpenAI 的新模型只认这个名字）。
- 图片：用户消息的内容改为分块列表，文字一块，每张图一块，图用“数据地址”形式（data 冒号、图片类型、base64、编码内容）内嵌。
- 工具：每个工具表示为类型 function 的一项，带名称、说明与参数结构。模型要调用工具时，响应里每个调用有名称与参数，参数是一段 JSON 文字，后端解析成对象；空文字或 null 视为没有参数，个别兼容服务直接给对象时原样使用；参数解析不出对象，归为服务出错。
- 结果：回复文字取第一个候选的消息内容（内容为空视为空文字），实际使用的模型名与用量（输入与输出的 token 数）取自响应，缺失时用请求的模型名、用量记为空。

## 五、anthropic（Claude）

- 鉴权：请求头 x-api-key 放密钥，另带请求头 anthropic-version，固定为 2023-06-01。
- 默认地址：服务地址不填时用 https://api.anthropic.com。
- 拉取模型：向服务地址加 /v1/models 发 GET 请求，取每项的 id 与 display_name。列表分页：响应说还有更多页时，用最后一项的编号作为 after_id 继续取，最多取 10 页。
- 对话：向服务地址加 /v1/messages 发 POST 请求。与兼容格式的差别：系统消息不放进消息列表，而是合并成单独的 system 字段（多条用空行连接）；最大输出长度（max_tokens）是必填项；消息里不接受空内容，至少要有一条非系统消息，否则在发请求之前就以“请求被拒绝”报错。
- 图片：用户消息的内容是块列表，每张图一块（类型 image，来源为 base64，带图片类型与编码内容），文字另成一块；没有文字时不放空文字块。
- 工具：每个工具有名称、说明与 input_schema（参数结构）。模型要调用工具时，响应的内容块里有类型 tool_use 的块，带名称、参数对象与调用编号。回复文字取所有 text 块拼接。
- 用量：输入与输出 token 数取自响应的 usage。

## 六、gemini

- 鉴权：请求头 x-goog-api-key 放密钥，不使用把密钥放在地址里的写法。
- 默认地址：服务地址不填时用 https://generativelanguage.googleapis.com/v1beta。
- 拉取模型：向服务地址加 /models 发 GET 请求，取每项的 name（去掉开头的 models/）与 displayName，只保留支持生成内容（generateContent）的模型。列表分页：响应带下一页标记时用 pageToken 继续取，最多 10 页。
- 对话：向服务地址加 /models/模型名:generateContent 发 POST 请求（模型名里开头的 models/ 会去掉，并做地址转义）。消息放在 contents 里，角色只有 user 与 model（助手消息转成 model）；系统消息合并成 systemInstruction；最大输出长度放在 generationConfig 的 maxOutputTokens。
- 图片：每张图是一个 inline_data 块，带图片类型与 base64 内容，文字是 text 块。
- 工具：所有工具放在一个 functionDeclarations 列表里，每项有名称、说明与参数结构。模型要调用工具时，响应的 parts 里有 functionCall，带名称与 args 对象。
- 被拦截：提示词被拦截（返回里没有候选、带 promptFeedback 的 blockReason），或候选没有内容且结束原因是 SAFETY、RECITATION、BLOCKLIST、PROHIBITED_CONTENT、SPII 之一时，后端归为“请求被拒绝”（bad_request），说明里写明原因，请用户修改提问内容。
- 没有内容但不是被拦截：候选没有内容而结束原因是其他值（例如 MAX_TOKENS，会思考的模型可能把输出长度全部用在思考上），按空回复处理：回复文字为空，模型名与用量照常给出。
- 用量：输入与输出 token 数取自 usageMetadata。

## 七、图片与工具的统一规则

统一调用入口对图片与工具有这些限制，在调用服务之前就检查：

- 图片只能放在用户消息里，系统消息与助手消息不能带图片，否则返回 llm_invalid_images，不会静默丢掉图片。
- 图片类型只接受 PNG、JPEG、WEBP、GIF 四种，内容是 base64 编码文字；单张解码后不超过 5 MB，一条消息最多 4 张，整个请求最多 8 张、合计不超过 20 MB。
- 带图片时，当前模型的看图能力必须是“支持”，否则返回 llm_model_lacks_vision；用途为“看图识别”时同样要求。
- 带工具时，当前模型的工具调用能力不能是“不支持”（未知允许尝试），否则返回 llm_model_lacks_tools。目前统一调用接口（POST /api/llm/chat）的请求里没有工具字段，工具由后端内部的调用方（步骤 08 的智能体）通过统一调用函数传入；接口层不开放，避免让前端随意定义工具。
- 统一调用函数只接收用户编号、用途、消息、工具与最大输出长度，不接收调用方的数据库会话：它自己开一个短会话读取分配、能力、地址与密钥，读完即关闭，调用服务期间不占数据库事务。调用方在调用它之前也应结束自己的事务。

## 八、错误如何归类

适配器把各家的错误统一归为九类，再由服务层转成接口错误码并附上中文说明与下一步建议。说明末尾会附上服务返回的原始信息（已去掉密钥并截断到 300 字）。

### 九类错误与接口错误码

| 适配器归类 | 含义 | 接口错误码 | 状态码 |
|---|---|---|---|
| invalid_key | 密钥不正确或没有权限 | llm_invalid_key | 400 |
| unreachable | 无法连接，或地址格式不对 | llm_bad_url | 400 |
| not_found | 地址不存在（404）；拉取时也可能是该服务没有模型列表接口 | llm_listing_unsupported_or_bad_url（拉取与测试），对话时为 llm_bad_url | 400 |
| model_not_found | 模型不存在或没有使用权限 | llm_model_unavailable | 400 |
| quota_exceeded | 余额或额度不足 | llm_quota_exceeded | 402 |
| rate_limited | 请求过于频繁被限流 | llm_rate_limited | 429 |
| timeout | 连接超时 | llm_timeout | 504 |
| bad_request | 服务拒绝了这次请求（参数不对、内容被拦截等） | llm_bad_request | 400 |
| provider_error | 服务出错，或返回的内容无法识别 | llm_provider_error | 502 |

### 通用的归类规则

先看正文，再看状态码：

1. 状态码是 400、402、403、429 之一，且正文里出现余额不足、欠费一类的措辞（例如 arrearage、credit balance is too low、insufficient balance、insufficient_quota、余额不足、欠费），不论状态码是什么，一律归为额度不足。各家表达余额不足用的状态码不一样，所以以措辞为准。
2. 401 与 403 归为密钥不正确。402 归为额度不足。
3. 429 默认是限流；正文里出现 quota、insufficient、balance、余额、额度、欠费等字样时归为额度不足。
4. 404：拉取列表时一律是地址不存在（避免“Cannot GET /v1/models”之类的正文被误判成模型不存在）；对话时正文提到模型（或“模型”）归为模型不存在，否则是地址不存在。
5. 400：正文里出现 model not found、does not exist、model not exist、模型不存在、InvalidEndpointOrModel、model_not_found 之一，或者出现更宽松的写法“model 之后不远处先有 not、再有 exist”（不区分大小写，例如 DeepSeek 的“Model Not Exist”），归为模型不存在，否则是请求被拒绝。
6. 其他 4xx 归为请求被拒绝；5xx 与重定向等归为服务出错。
7. 网络层：超时归为超时；连接失败、域名解析失败、地址格式不对归为无法连接。

### Claude 的补充规则

先看响应里错误的类型：authentication_error、permission_error 归为密钥不正确；not_found_error 在对话时归为模型不存在、拉取时归为地址不存在；rate_limit_error 归为限流；overloaded_error 归为服务出错并提示“服务繁忙，请稍后再试”。其余按通用规则（Claude 的余额不足是 400 加“credit balance is too low”的措辞，按通用规则归为额度不足）。

### Gemini 的补充规则

- 400 且信息里有“API key not valid”，或状态为 PERMISSION_DENIED、UNAUTHENTICATED：密钥不正确。
- 状态为 NOT_FOUND：对话时模型不存在，拉取时地址不存在。
- 状态为 RESOURCE_EXHAUSTED：要区分限流与额度用尽。带有 RetryInfo（建议稍后重试）的，或额度明细指向每分钟、每天的“请求次数”上限的，归为限流（过一会儿或次日恢复）；其余，包括每天的 token 用量上限，归为额度用尽。
- 其余按通用规则。

### 连通性测试的结论

测试先拉取模型列表，再（给了模型编号时）用该模型发一次最小对话（提示词“请只回复：好”，最多输出 16 个 token），按下面的规则给出结论，详见《接口清单》：

- 拉取成功、对话成功：连接正常（ok）。
- 拉取 404、对话成功：通过，但提示该服务不支持拉取模型列表，请手动添加模型编号（ok_listing_unsupported）。
- 拉取报密钥不正确、对话成功：同样给 ok_listing_unsupported，提示当前密钥没有拉取列表的权限；对话也失败，结论是密钥不正确。
- 拉取与对话都是 404：地址错误（bad_url）。
- 拉取成功（或列表只是不支持）而对话说模型不存在：模型不可用（model_unavailable）。
- 其他拉取错误（额度、限流、超时、无法连接、服务出错、请求被拒绝）：结论跟随拉取的错误，不再做对话。
