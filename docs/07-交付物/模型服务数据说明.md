# 模型服务数据说明

本文说明步骤 07 新增的三张表、密钥的保护方式，以及模型能力对照表的格式、来源与覆盖规则。内容以代码为准：表结构在 backend/app/llm/models.py，对照表在 backend/app/llm/data/capabilities.json。

## 一、三张表

三张表都带有用户编号（user_id）列，所有查询都从“当前用户”开始，别人的记录与不存在的记录一样返回未找到。任何接口都不接受客户端传入用户编号。

### 1. 模型服务（llm_providers）

用户配置的一个模型服务。

| 字段 | 含义 |
|---|---|
| id | 服务编号 |
| user_id | 所属用户，用户被删除时服务一并删除 |
| name | 服务名称，1 至 50 个字，同一用户下不能重名（重名返回 llm_provider_exists） |
| kind | 服务类型，只能是 openai_compatible、anthropic、gemini 三种之一，创建后不能修改 |
| base_url | 服务地址，最长 300 个字，保存时已去掉结尾的斜杠，并通过地址检查（见下文“地址检查”） |
| api_key | 密钥，加密保存，延迟加载，见“密钥的保护” |
| key_hint | 密钥掩码，形如 ****abcd，接口里只回传它 |
| created_at、updated_at | 创建与最近修改时间 |

每个用户最多配置 20 个服务，超过返回 llm_too_many_providers。

### 2. 模型（llm_models）

某个服务下的一个模型。

| 字段 | 含义 |
|---|---|
| id | 模型记录编号（接口里叫 id，分配用途时用的就是它） |
| user_id | 所属用户 |
| provider_id | 所属服务，服务被删除时其下模型一并删除 |
| model_id | 模型编号，即调用服务时填的名字（例如 deepseek-chat），1 至 200 个字，同一服务下不能重复 |
| display_name | 显示名称，可为空；Claude 与 Gemini 的列表会带显示名称 |
| source | 来源：fetched 表示由“获取模型”收录，manual 表示手动添加 |
| vision_override | 看图能力的手动标注：真、假或空 |
| tools_override | 工具调用能力的手动标注：真、假或空 |
| chat_override | 对话能力的手动标注：真、假或空 |
| created_at、updated_at | 创建与最近修改时间 |

三个标注列为空，表示没有手动标注，以对照表为准。

### 3. 用途分配（llm_assignments）

把一个“用途”指向一个模型。

| 字段 | 含义 |
|---|---|
| id | 分配编号 |
| user_id | 所属用户 |
| purpose | 用途，只有 chat（日常对话）与 vision（看图识别）两种 |
| llm_model_id | 分配到的模型记录编号，模型被删除时这条分配一并删除 |
| updated_at | 最近修改时间 |

每个用户每个用途至多一条，重复分配是替换。

## 二、密钥的保护

- 加密保存：密钥用与档案等敏感字段相同的字段加密密钥（FIELD_ENCRYPTION_KEY，Fernet 方案）加密后存入数据库，数据库里只有密文，直接查表看不到明文。
- 延迟加载：api_key 列在数据模型里声明为延迟加载，普通查询（列出服务、查看服务、列出模型、分配用途）都不会读取它，也就不会解密。只有真正要调用模型服务的两个入口会读取：拉取模型与连通性测试（读出后立即结束数据库事务），以及统一调用入口（用独立的短会话读取，读完即关闭）。调用服务期间不占用数据库事务。
- 掩码规则：对外只给 key_hint。密钥长度不少于 8 位时是四个星号加末 4 位，不足 8 位时只给四个星号，一位都不露。创建与修改服务时由后端计算，之后不再从明文推导。
- 不回传、不入日志：任何接口响应都没有密钥字段；修改服务时不填密钥表示保持原密钥。模型服务返回的错误文字在使用前会去掉密钥原文和形如 sk- 开头的长串，并截断到 300 字，再放进说明里。适配器对象的显示文字里也不含密钥。
- 密钥格式检查：带首尾空格、换行、制表符等控制字符或全角字符的密钥，在发出任何请求之前就会被判为密钥不正确，避免底层报错带出密钥原文。创建与修改时密钥会先去掉两端空白，长度 1 至 500 个字。
- 密钥不放进地址：保存地址时，带用户名密码（@ 之前的部分）、查询参数、# 片段的地址一律拒绝，Gemini 的密钥放在请求头里，不放进地址。

## 三、地址检查

保存、测试、拉取、调用前都会检查服务地址（出站前会再检查一次，防止域名解析结果后来变成内网）：

- 必须是 http 或 https 开头；非本机地址必须是 https。
- 不能带用户名密码、查询参数和 # 片段。
- 默认拒绝解析到本机回环、私有、链路本地、保留地址的主机，防止借服务地址探测内网。配置项 LLM_ALLOW_PRIVATE_HOSTS 为真时跳过这项检查，只用于测试与本地模拟服务，默认关闭。
- 不合格的地址返回 llm_invalid_url，说明里写明具体原因，且不回显地址里可能夹带的密钥。

## 四、模型能力对照表

拉取到的模型列表通常不含能力信息，所以随代码维护一份对照表，用来给每个模型标出三项能力：是否支持看图（vision）、是否支持调用工具（tools）、是否为对话类模型（chat）。每一项的取值是支持（真）、不支持（假）、未知（空）。

### 文件格式

对照表是一个 JSON 文件，位置在 backend/app/llm/data/capabilities.json，顶层有两项：

- source：来源说明。
- rules：规则列表，每条规则有五个字段：pattern（模型编号的正则表达式，不区分大小写，匹配模型编号中的任意位置）、vision、tools、chat（各为真、假或空）、note（给用户看的中文说明，说明为什么这样标）。

文件载入时有严格校验：不允许多余字段，正则必须能编译，否则第一次使用对照表时就会报错，而不是悄悄忽略，自动化测试也会检查它。

### 匹配规则与顺序

- 按文件里的顺序逐条匹配，先匹配到的先用，之后的规则不再看。没有任何一条匹配，三项都是未知。
- 当前共 22 条规则，顺序刻意安排：第一条是名称带有向量、重排、语音（含语音识别与合成、实时语音）、内容审核、图像生成、视频生成等字样的非对话模型（三项都标为假）；接着是各家的看图模型（通义千问的 QVQ、Omni、VL 系列，DeepSeek 的 VL 系列，智谱带 v 的 GLM 视觉模型，豆包的视觉模型与 Seed 1.6 系列，OpenAI 的 GPT-4o、GPT-4.1、GPT-5）；再往后是 OpenAI 的 GPT-3.5（纯文字，支持工具调用）、Claude 系列与 Gemini 系列（看图与工具调用都支持）；最后是各家的纯文字模型（DeepSeek 的对话与推理模型，通义千问的 max、plus、turbo、flash、long、3 与 2.5 系列、QwQ，智谱 GLM-Z1 与不带 v 的 GLM-4，豆包的 pro 与 lite 系列）。把更具体的规则放在前面，是为了让“GLM-4V”不被泛泛的“GLM-4”抢先匹配。
- 对没有把握的项，规则里写“未知”而不是猜测。例如多数视觉模型的工具调用情况标为未知。

### 来源与可信度

对照表的来源是各厂商公开文档，2026 年 10 月整理，没有逐个核实，文件里的来源说明也是这样写的。它只是默认值，不保证准确，所以每一项都可以被用户手动覆盖（见下一节）。厂商新增模型后，需要维护者在文件里补规则，并随代码一起发布；用户不必等待，可以随时在模型上手动标注。

## 五、能力的有效值与覆盖规则

一个模型的有效能力按下面的顺序取每一项：

1. 用户手动标注为真或假，就用手动标注。
2. 手动标注为空，就用对照表匹配到的值。
3. 对照表也没有（或没有匹配），就是未知。

接口里每个模型同时给出三组值：有效能力、对照表能力、手动标注，以及命中规则的说明，方便界面显示“为什么是这个结果”。手动标注可以改成真、假，也可以改回空（回到对照表）。

有效能力在两处起作用：

- 分配用途时：看图识别只接受看图能力为“支持”的模型，“不支持”和“未知”都拒绝，并提示先在模型上手动标注；日常对话拒绝对话能力为“不支持”的模型。
- 统一调用时（运行时检查）：分配之后能力可能被改，所以每次调用前都再检查一遍。用途所分配的模型被删除时，提示还没有选择模型；带图片而模型的看图能力不是“支持”时拒绝；带工具而模型的工具能力为“不支持”时拒绝；模型被标明不是对话模型时拒绝。
- 修改能力标注后，如果这个模型已被分配到某个用途而现在不满足要求，修改仍然保存，但响应里会附一条提醒，告诉你使用时会报错。

## 六、拉取模型时的数据规则

- 拉取只新增模型，来源记为 fetched；已有的模型（包括手动添加的）与它们的能力标注都不改动；列表里消失的模型也不删除。
- 每次最多收录排序后的前 500 个模型，编号为空或超过 200 个字的不收录，这些都计入“跳过数”，接口会告诉你。
- 同一次拉取按模型编号去重并排序，保证每次结果顺序一致；Claude 与 Gemini 的列表会翻页，最多翻 10 页，Gemini 只收录支持生成内容的模型。
- 手动添加的模型来源记为 manual，用于不提供模型列表的服务（例如豆包要填方舟控制台里的接入点编号）。

## 七、删除的连带关系

- 删除一个服务，其下的全部模型与指向这些模型的用途分配一并删除。
- 删除一个模型，指向它的用途分配一并删除，之后统一调用该用途会提示还没有选择模型。
- 删除用户，用户名下的三张表数据全部删除。
