# 新人复现记录

目的：验证一个没有任何本地状态的新人，只靠 README 就能把项目跑起来。本记录不含命令，命令都在 README 里，这里只写按哪一节做了什么、结果、卡点与对 README 的修正。

## 一、做法与限制

- 环境：在新的临时目录里，用本地仓库克隆出一份全新的工作副本（不联网，克隆来源是本机的仓库），里面没有依赖目录、没有构建产物、没有配置文件。
- 范围：只按 README 的第 1 至 7 节与第 22 节走一遍。
- 离线：依赖只从本机缓存安装。后端用离线方式同步依赖，前端用离线方式安装依赖；缓存缺包会停下报告，不联网。这次没有缺包。
- 数据库：本机的数据库容器已经在运行，且被其他任务使用，所以第 2 节只核对了命令与文件，没有再起第二个容器；第 5 节的建表改在这个容器里新建的一个一次性库上做（库名带 repro，用完即删），没有动开发库，也没有读本机真实的配置文件，第 4 节的两个密钥是现场新生成的临时值。
- 端口：第 7 节启动服务时 8000 端口当时是空的，但为了不与同时运行的其他任务冲突，改用 8011 端口，只影响命令里的一个数字。
- 仓库状态：克隆的是提交前的临时提交，内容与最终提交相同，只有本文的结果补记是之后加的。

## 三、导入路径大小写核对

Linux 区分文件名大小写，而本机是 Windows，不区分。写错大小写在本机一切正常，到持续集成的 Linux 环境里才会报“找不到模块”，这是持续集成第一次运行失败的常见原因。所以在推送前做了一次专门核对：

- 前端：把源码与端到端测试里全部相对导入（共 1878 处）逐一对照仓库里登记的真实文件名与目录名，要求大小写逐字一致。结果：全部一致；脚本报出的两处“找不到”是测试里作为字符串写的示例路径，不是真实导入。
- 后端：把全部以应用包名开头的导入（共 1214 处）逐一对照真实的目录与模块文件名，结果全部存在且大小写一致。
- 另查仓库里有没有只差大小写的同名文件：没有。

这个核对是一次性的人工脚本，没有进仓库；以后改文件名时再出现大小写问题，会在持续集成里暴露。
