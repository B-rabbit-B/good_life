# 项目介绍

好生活（good-life）是一个求职作品集项目。本文给两个版本：一段话版本用来开场自我介绍，一页纸版本用来回答“这个项目到底是什么”。其余材料依次是《架构说明》《创新点说明》《取舍记录》《演示脚本》《面试追问清单》《开源使用说明》。

## 一段话版本

好生活是一个由个人档案驱动的健康生活智能体，跑在手机浏览器里。它把经期、医嘱、饮食、健身沉淀成可复用的数据工具层（SDK 加 MCP），智能体在聊天里按档案调用，给出符合个人约束的饮食建议。核心做法是规则在前、模型在后：医嘱只能本人确认，回答发出前由输出检查拦截违反医嘱的食物，高风险话题只给固定回复，模型只负责理解与措辞。只提供生活方式建议，不做医疗诊断。

## 一页纸版本

### 定位

- 一句话：一个由个人档案驱动的健康生活智能体，把四类个人数据（经期、医嘱、饮食、健身）做成数据工具层，再让智能体在聊天里调用。
- 边界声明：只提供生活方式建议，不做医疗诊断，不替代医生。免责声明、高风险话题的固定回复、“仅供参考”标签在全站统一出现。
- 项目目的：求职作品集，重点是架构清晰、取舍可讲，而不是功能越多越好。所以每个功能都带着“放弃了什么”的记录。
- 不做：不接外卖平台，不用机器学习预测经期，不做医疗器械认证，不做正式合规认证（法条一律标注“参照，不做正式合规”）。

### 用户

- 终端用户：14 周岁及以上、在手机浏览器里管理自己饮食与健康习惯的个人。不分角色入口，由个人档案决定哪些模块开放：女性用户有经期模块，其余模块对所有人开放。14 至 17 岁的未成年用户不估算能量需求，也不提供减重类建议。
- 典型场景：有忌口医嘱的人问“晚饭吃什么”；经期用户想知道下次大约什么时候来、这个阶段怎么吃；增肌用户训练后问吃什么；不想做饭时找附近适合自己的餐厅；拍一张饭菜照片估算热量并入库。
- 作品集读者：面试官与技术评审。他们关心的是智能体工程：模型不可信时系统怎样仍然安全，以及这些承诺有没有测试证明。

### 主线

主线是“规则在前、模型在后”。凡是涉及安全与事实的判断都由确定性的规则与数据决定，大模型只负责把结果说得自然：

- 能不能吃由营养引擎按医嘱、经期、目标、训练与当日摄入给出结论，医嘱是硬约束，其余是软约束，软约束不能放宽硬约束。
- 回答发出前，输出检查逐个核对回答里提到的食物，违反医嘱的一律拦截，重写一次仍然违反就换成固定的安全回答。
- 用药、严重症状、孕期异常、极端节食、自伤（未成年用户再加减重）这几类话题用关键词规则直接给固定回复，不调用模型。
- 医嘱的确认、修改、解除、作废、继续生效只能由本人在界面里完成，智能体最多提出解除建议。
- 拍照识别里模型只负责认出菜名与份量说法，热量与营养全部来自营养库。
- 何时主动提问由规则决定，模型只负责措辞，措辞不合格就退回固定模板。

安全承诺的表述很克制：测试假设模型完全听从注入，只证明硬边界仍然成立，不声称真实模型能抵抗注入。智能体有 6 个写入工具，这一点在《取舍记录》里如实写明。

### 技术栈

- 后端：Python 3.12、FastAPI、SQLAlchemy 2、Alembic 手写迁移、PostgreSQL 16；密码用 argon2，登录令牌是 HS256 的 JWT，健康相关字段用 Fernet 加密列；图片处理用 Pillow；模型调用用自己写的三个适配器（OpenAI 兼容格式、Claude、Gemini），HTTP 客户端是 httpx2；MCP 服务用官方 Python 库的本地标准输入输出方式。
- 前端：React 19、TypeScript 严格模式、Vite、React Router、TanStack Query；组件的行为与无障碍语义用 React Aria Components，样式全部自写，不用动画库；接口类型由后端接口描述生成。
- 测试：后端 pytest（真实数据库，模型与高德一律是模拟服务）；前端 Vitest 加 MSW；端到端 Playwright（iPhone 13 与 Pixel 7 两种模拟设备）。
- 数据：营养库 1744 个食物（中国食物成分表整理数据、自建菜品、手动补充，授权状态逐项标注），内置动作库 56 个动作，都随程序加载、不入数据库。

### 关键数字

以下数字是撰写时从代码与测试里数出来的，换了版本以后以代码为准：

- 数据库：29 张表（含用户表），迁移 17 个；除用户表外，其余 28 张业务表都带用户编号并级联指向用户表，删除用户行即可删光该用户的全部数据。
- 接口：121 个接口（95 条路径），全部登记在接口快照里，前端类型由它生成。
- SDK 与 MCP：SDK 版本 1.2，共 34 项能力，其中暴露给智能体与 MCP 的是 28 项能力（只读 23、写入 5），另有 6 项需本人确认的医嘱能力不对外暴露；MCP 共 28 个 MCP 工具，与暴露的能力一一对应。
- 智能体：28 项能力加偏好记忆，一共有 6 个写入工具（记经期、记训练、提交医嘱、提出解除建议、记一餐、记偏好）；每轮对话最多 6 次模型调用；风险话题 5 类，未成年用户再加 1 类。
- 测试：后端自动化测试 2900 个以上（撰写时 pytest 收集到 2919 个，全量以警告当错误运行）；前端 Vitest 在步骤 11 验收时 584 个测试，之后随单独同意、导出与删除等界面继续增加；端到端有 9 条验收标准的流程，在两种模拟设备上各跑一遍。
- 营养库：1744 个食物，其中仅供个人学习的成分表整理数据与自建菜品共 1723 个，手动估算未核对的 21 个；因此仓库保持私有，商用前必须替换数据。
