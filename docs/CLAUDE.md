# docs 目录说明书

## 职责
- 项目文档。顶层是总览（00-总览与串联.md）、每个步骤的步骤文档（NN-名称.md，写目标与验收标准）、阶段性的整体验收与检查记录；NN-交付物/ 是每个步骤交给你本人阅读的交付文档；superpowers/ 是开发过程用的设计、规格与计划。
- 交付物目录统一由本说明书约定，不为每个 NN-交付物 目录各写一份说明书。

## 边界
- NN-交付物 下的全部 Markdown 是交付文档：不含代码、命令、反引号与代码块（命令只写在 README）；各步骤的后端文档测试（backend/tests/test_*_docs.py）核对这些文档与代码一致、并查禁用写法。
- 验收记录（NN-交付物/验收记录.md）的表头固定为：序号、验收项、自动化测试、手动核对方法、结果、用户验收。
  - 自动化测试列：后端写“文件名 加两个冒号 加测试名”（文件都在 backend/tests 下）；前端写“从 frontend 起的相对路径 加两个冒号 加测试标题”，标题与测试文件逐字一致；多个之间用分号，可在括号里简述它证明了什么。
  - 结果列由执行者在自动化验证后填写；用户验收列原本由用户本人填写。
- 代验：用户授权 Claude 代为验收时，用户验收列写“通过（代验，见“代为验收记录”）”，文末加“代为验收记录”一节（验收日期、验收人、验收方式，再加“序号、实际核对过程与观察到的结果、结论”三列的表）；需要真实密钥、真实服务或真机的部分标为待用户实测或待用户补测，不能写成通过。
- superpowers/specs 放设计规格（每个步骤的设计取舍），superpowers/plans 放实现计划（任务拆分、文件清单、精确值），superpowers/design 放界面设计稿与 DESIGN.md（前端的组件、无障碍与视觉规则）及评审截图。

## 入口
- 读一个步骤：先读 NN-名称.md 的验收标准，再读 NN-交付物/验收记录.md；改代码前读对应的规格与计划。
- 步骤 12 的交付文档放在 12-交付物/（共 17 份文档加一张架构图，目录内容由 backend/tests/test_step12_docs.py 守护，它还核对安全审查记录、已知问题与限制清单与验收记录；备份与恢复预案、依赖故障预案、新人复现记录由 test_step12_ops_docs.py 检查，项目介绍、架构说明与架构图、创新点说明、取舍记录、演示脚本、面试追问清单、开源使用说明由 test_step12_portfolio_docs.py 检查，持续集成工作流 .github/workflows/ci.yml 由 test_ci_workflow.py 检查）。
- 前端设计依据：superpowers/design/step11/DESIGN.md 与 index.html（端到端可视比对直接打开它）。

## 禁区
- 交付文档里不写代码、命令、反引号；计划与步骤文档不写时间估计。
- 改动或改名测试时，同步改所有验收记录与交付文档里对它的引用（文档测试会检查引用存在）。
- 不擅自改已验收步骤的结论与代验记录；只有用户要求或补测完成时才改，并写明依据。
- 不在文档里写真实密钥、真实用户数据或实测结果文件的内容；实测结果文件不提交。
